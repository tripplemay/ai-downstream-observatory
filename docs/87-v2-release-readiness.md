## 判定方式

- 有代码、有离线测试、有真实来源证据、有普通用户验收、已部署，是五种不同状态。
- 明确阻断是必要保护，不等同于正常研究/监测功能已经完成。
- 本轮纯测试优化不能把旧构建、局部浏览器收据或父提交 CI 提升为完整产品验收。
- 不新增策略默认值、个人资金、来源许可或交易权限；不以持续盈利为保证。

## 推进顺序与退出条件

1. **CI**：保留取消日志和原始 TAP，解决超时而非增加预算/分片、减少用例或
   重跑掩盖结果；准确候选的完整 push/PR 结果独立记录。
2. **产品纵切**：用上表补齐正常、变化、陈旧三路径与 P2/AI 独立证据，列出
   缺陷，不继续用外围恢复功能的局部成功代表完整 v2。
3. **真实研究**：沿用已批准来源/用途/请求边界；不自动重跑失败试验、重选
   参数或把已曝光保留期改称独立验证。策略资格与软件验收分开。
4. **发布前只读盘点**：准确 main SHA、环境保护、固定 SSH 信任、服务/模式、
   容量、迁移/真实副本恢复和回滚边界按当前证据复核。不沿用九月配置清单
   推断现在缺配置，也不沿用旧健康 200 推断当前可发布。
5. **受保护发布及外网验收**：遵循发布 runbook 和已批准的单份常驻备份政策，
   不捎带删除资源、购买存储或改交易授权。核对版本/schema、未登录拒绝、
   登录后真实业务、后台任务与数据质量；外网 200 仅是连通检查。

完整 v2 目标仍开放；本页没有触发生产、提供方、AI、金融事实、备份或删除操作。
