# 研究验证状态与下一版执行规则

## 本轮实现边界

- 将“后台作业完成”和“候选通过研究规则”分开显示。验证期或保留期失败时，
  参考组合卡直接说明尚未生成组合，不让使用者从训练期收益猜测是否可采用。
- 阶段执行缺口只投影已核验、与原始试验登记及冻结候选绑定的持久化汇总。
  不重新运行试验，不填造缺失阶段，不把未启动的保留期显示为通过。
- 汇总包含跳过、到期或策略部署失败；不能凭汇总断言某个证券的具体失败原因，
  也不是实盘交易或亏损金额。没有执行缺口仍不代表风险检查通过。
- 当前端已知来源期限到期，隐藏候选与阶段检查，保留服务端历史记录。
- 正式部署显式保留 core 的任务租约；不改变研究内核、已有结果 hash、
  数据库 schema、个人资料、真实资金、模型采纳或交易权限。

## 下一版执行规则：设计草案，尚未实现或准入

目标是让固定数量的研究订单在决策时有明确的价格波动余量，而不是看到未来
成交价之后重新缩小数量。该设计不是盈利保证或券商订单指令。

1. 在新研究版本中登记现金预算、价格边界、数量步长、费用、外汇边界、
   执行时点与到期规则；数值范围必须在读取新研究结果之前冻结。
2. 决策只使用当时可知的价格与外汇。按预先价格边界和全额费用计算固定数量，
   并锁定预算；不得借用其他挂单的预算、未交收卖出款或预计投入。
3. 下一合格时点只检验已冻结的数量和预算。超出边界必须保留未执行记录；
   不用日内最低价推定成交，不事后缩量，不补造资金，不重复下单掩盖失败。
4. 新版参数、执行引擎、结果契约及 Python/Web 独立复算必须一起版本化。
   原有执行缺口和零缺口准入标准不在本轮偷偷改成“可忽略”。
5. 如另行定义“预期未成交”与“计算错误”，需独立预登记成交覆盖、闲置现金、
   换手和对照策略的验收标准，不能依据旧验证失败临时放宽。

## 研究与发布门禁

- 先以明确标注的合成数据覆盖价格跳升、手续费最低额、数量步长、现金舍入、
  多挂单预算、交收、跨币种、分红、拆分和到期；不访问真实保留窗口。
- 保留首次研究的候选冻结、失败结果与曝光记录。旧验证窗口已被检查，
  不能在新规则下把同一窗口称为独立未见样本。
- 新规则的开发期诊断应与将来独立评价窗口区分；若尚无可证明独立的数据，
  保持探索性标签，不强行发布最终组合。
- 通过契约、不可变记录、跨运行时复算、实际 HTTP/界面及受保护发布验证，
  再分别验收真实行情接入、模型观察和持续监测。
- 港股、美股、外汇与账户可交易性仍需各自的证据；三只 A 股 ETF 的研究结果
  不代表已经覆盖所有市场。

个人预算、实际证券诊断、原始行情、供应商密钥和备份证据只保存在本地私有
工件中。本文件仅为可公开的通用工程设计。
