# 下一版执行规则：限额买入离线原语

## 当前状态

这是 `docs/36-research-validation-status-and-execution-policy.md` 的第一步工程实现，
不是已完成的新策略、投资组合、真实回测或生产功能。

- 独立契约：`contracts/v1/bounded-cash-buy.schema.json`。
- Python：`worker/execution_sandbox/bounded_cash.py`。
- Web 独立复算：`web/src/server/execution-sandbox/bounded-cash.ts`。
- 只允许显式标注的合成数据；只实现 CN/CNY 的现金买入批次。
- 未注册 worker 命令，未接入研究选择、API、页面或券商，不写任何数据库。
- 原研究内核、执行引擎、策略结果契约、schema migrations 和准入门槛不修改。
  旧候选、失败结果和曝光登记继续有效地保留为历史证据。

## 冻结与执行

1. 调用者显式提供每笔预算、价格余量、数量步长、手续费、滑点、来源可知时点、
   下一个执行时点与到期时点。没有默认的推荐价格余量，也不搜索收益最好的数值。
2. 可分配预算只来自已交收人民币现金，扣除其他订单已锁定预算。
   未交收应收款、预计投入和未来卖出款都不能提供购买力。
3. 使用决策时已经可知且未失效的报价。价格上界为：
   `决策价格 * (1 + price_buffer_bps / 10000)`。
   该上界约束的是包含滑点后的研究执行价格，因此滑点不能高于价格余量。
4. 按价格上界、完整最低/比例手续费和向上取整到分的现金扣款，求出最大整步数量。
   数量在此时冻结，预算锁定为该订单完整分配额度，不与其他订单互借。
5. 到期后的终态复算，只检查冻结数量和指定下一时点的报价。超界、不合时点、
   来源缺失或晚到均保留未执行记录。不事后缩量，不用释放的余额扩大其他订单，
   不换用另一天或日内最低价。
6. 冻结后出现分红、拆分等公司行动时，本阶段只标记待复核并不执行。
   尚未实现公司行动现金/数量状态机，不以改价、加钱或调整数量掩盖其缺失。
7. 低于一数量步长的预算单独记录为 `below_minimum`，不产生订单、费用或扣款。
   已计划却未执行的订单全部计入 `execution_failure_count`，包括超界和缺失来源；
   本阶段没有把“预期未成交”改为忽略，也不修改旧的零缺口规则。

`fee_cny` 保留未取整的手续费计算值，`rounding_cny` 单独记录向上取整差额；
两者与数量乘执行价格合计为实际模拟扣款，避免把现金舍入藏入收益或余额。

## 证据绑定与独立复算

- 冻结计划绑定输入、政策和独立源代码清单 hash；计划中没有未来成交报价。
- Python 与 TypeScript 各自实现数量搜索、时点校验、费用、舍入、预算和结果计算。
  Web 不直接相信 Python 给出的经济结果。
- 执行入口先重新核验整个冻结计划；结果校验还会完整复算。仅重新计算 hash，
  无法让篡改的数量、价格上界、手续费或余额通过。
- 金额和数量使用有界十进制文本，大数量步数使用整数而非浮点 `Number`。
  两端使用隔离的 160 位计算上下文，不修改现有金融计算的全局精度。
- 独立源清单与旧内核清单分开；旧内核文件图以公开基线校验，避免本原语的添加
  使旧研究身份漂移。依赖/旧内核确需升级时，应先明确旧研究兼容和重放方案，
  不能仅删除这个保护测试。

测试包含手算案例、64 组合成语料、最高/最低金额和数量步长边界、微秒、早于
Unix epoch 的时间、最低手续费、多个挂单、未交收款、源缺失/到期、公司行动
失效、重新封印后的篡改、跨币种拒绝及旧调度/契约的隔离。
这些只是软件证据，不构成策略独立性、行情来源或历史盈利的认证。

## 限制与后续工作

- 指定下一收盘价仅是合成研究价格代理。满足价格边界不能证明限价单、盘中价格、
  收盘竞价、数量和流动性在真实市场可成交；没有实际成交模型的认证。
- 这是无状态纯函数。同一输入重放得到同一结果，但不提供跨批次资金锁定、
  全局订单幂等、撤单、部分成交或交收持久化；不能用于真实下单。
- HK、US、FX、实际数量步长/交易权限、应收分红的交收和拆分后的订单处理，
  尚未实现或验收；目前都拒绝或阻断，不能默认为已支持。
- 测试中的价格余量和费率全部是虚构测试向量，不是策略参数选择或投资建议。
- 下一步应在独立研究引擎中加入连续现金/持仓状态与不可变事件，再同时版本化
  策略参数、计划、结果、试验登记和 Python/Web 复算。仍不能替换旧结果。
- 真实开发诊断与未来独立评价窗口必须分开登记。已看过的历史验证期不能再次
  宣称为未见样本；未经登记和独立评价，不生成最终参考组合或启用持续监测。
- 本阶段不发布生产；后续完整集成通过后，另走受保护发布及生产验收。
- 新增契约及原研究入口的严格编译/兼容测试，不等于全库契约的严格 lint。
  额外全库检查在未修改基线上也发现 `ai-monitor-context.schema.json` 的既有
  `pattern` 缺少本地 `type` 标注问题；本阶段不修改旧契约或将此检查记为通过。

## 本地验证入口

在仓库根目录使用已安装工程依赖的 Python：

```sh
python -m unittest tests.execution_sandbox.test_bounded_cash
node --test tests/execution_sandbox/contracts.test.mjs
```

在 `web/` 目录运行独立复算测试。需要指定 Python 时，通过
`WORKBENCH_TEST_PYTHON` 传入解释器路径，不传密钥或供应商行情。

```sh
npx tsx --test tests/bounded-cash-sandbox.test.ts
npm run typecheck
```
