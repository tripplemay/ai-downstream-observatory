# ETF 投资工作台：产品需求与使用流程

版本：v1.1 | 日期：2026-09-12 | 状态：公开产品规格，不包含个人配置

上位约束：[投资目标与约束](01-investment-mandate.md)。决策权限及状态流转：[投资决策与策略治理规则](03-decision-policy.md)。

本文的产品范围、使用流程和目标需求作为通用设计与验收依据，不是已完成功能或个人批准记录。具体组合的资金、日期、券商及待决策事项仅在本地填写并审批；采用公开规格不等于投资政策或交易获批。

## 1. 产品定位

支持长期投资者跨多个券商账户管理以 ETF 为核心的组合。初始与追加资金的金额、原币种和日期按上位模板 C-02 至 C-04 在本地填写，不预置个人资金计划，不在界面把计划金额伪装为已到账资产。

核心工作流：

```text
投资约束与账户资料
  -> 真实账本与可靠估值
  -> 资金计划和策略目标
  -> AI 复核及确定性风控
  -> 分账户建议与人工确认
  -> 用户在券商执行
  -> 实际成交回录与对账
  -> 收益归因、风险监测和策略复审
```

产品每天应回答：资产怎样、风险怎样、需要做什么、为什么，以及尚缺哪些证据。正常情况下，“不操作”可以是完整且有理由的决策结果。

## 2. 用户、模式与首版边界

### 2.1 用户与权限

- 一个投资者兼批准人；自动任务和 AI 是辅助执行主体，不是投资授权主体。
- 单用户不等于免登录；真实持仓、资金、建议、导入文件和配置必须限制访问。
- 跨账户统一分析，但确认交易以具体账户和币种为单位。

### 2.2 产品模式

| 模式 | 可做事项 | 不可做事项 |
|---|---|---|
| 只读管理 | 导入、对账、估值、展示已有风险和历史 | 不将不完整资料转为可执行建议 |
| 研究与模拟 | 比较配置、回测策略、生成模拟决策 | 不把模拟结果混入实际资产和收益 |
| 实盘建议 | 在已批准政策和有效输入下产生待确认清单 | 不自动向券商下单，不把确认当作成交 |

实盘建议模式启用条件见 03 文档；政策、账户或数据不足时，保留只读/研究能力，不用红绿灯掩盖未就绪状态。

### 2.3 首版包含与不包含

包含：手工及文件导入、真实组合账本、跨币种评价、资金计划、ETF 研究库、可复现策略、AI 复核、风险检查、人工执行清单、成交对账、基本报告及告警。

不包含：券商自动下单、无人审批的 AI 改仓、融资卖空及复杂衍生品执行、多用户资管、客户资金管理、收益保证、全市场逐笔高频交易、自动税务申报。

具体券商导入格式待 D-07 验证；先提供标准导入模板和人工录入，不假设不同券商格式相同，也不假设任何券商 API 已可用。首版不收集券商登录密码或交易授权密钥。

## 3. 核心概念

| 概念 | 定义及边界 |
|---|---|
| 总组合 | 用户纳入管理的全部账户、持仓、现金与待结算项目 |
| 账户 | 具体券商账户，具备实际币种余额及市场权限 |
| ETF/证券 | 唯一标识绑定市场与上市份额，另记底层资产、指数、注册地和币种等属性 |
| 配置部分 | 核心、策略、防御等资金责任划分，不是额外资产，不重复计算总资产 |
| 策略 | 版本化规则和风险预算，其输出是目标而非成交 |
| 资金计划 | 未来追加及投入安排；计划不是现金流水 |
| 投资建议 | 某个数据和政策版本下的动作或不操作结论 |
| 执行清单 | 建议经风控后，按账户拆分的待人工执行项目 |
| 实际成交 | 券商事实记录或经确认的人工事实录入，驱动真实持仓变化 |
| 研究专题 | 支持决策的研究材料；AI 下游研究归入此类，不再作为全站主结构 |

同一 ETF 可被多个策略持有；账户成交应净额化，内部策略归属仍可追踪。目标仓位、模拟持仓、实际持仓必须清楚区分。

## 4. 信息架构与主要页面

| 页面 | 首要信息 | 主要操作 |
|---|---|---|
| 我的组合 | 总资产、累计净投入、损益、TWR/XIRR、回撤、币种、估值截止时间 | 查看账户、归因和待办 |
| 资金计划 | 年度预算、实际到账、可用与受限现金、待投资金额、最晚处理日期 | 登记资金事实、审阅投入方案 |
| 投资决策 | 当前目标与实际差额、交易理由、风险结果、依赖、有效期 | 确认/拒绝/暂缓建议、登记执行 |
| ETF 标的库 | 底层资产、指数、成本、流动性、价格、折溢价、持仓重叠、账户可买性 | 比较候选、申请纳入或移出 |
| 策略实验室 | 规则版本、研究证据、回测/样本外/模拟表现、基准和资金预算 | 提交策略或参数变更审阅 |
| AI 投资研究 | 来源、数据日期、支持和反对证据、解释、待核实事项 | 追问、关联决策、提交验证假设 |
| 账户与账本 | 原币现金、持仓、流水、导入批次、对账差异 | 预览导入、确认、更正与对账 |
| 风控与运行 | 风险暴露、数据完整性、任务结果、阻断及告警状态 | 查看原因、处理异常、批准恢复 |

首页优先级：阻断与待办 > 资产和风险 > 目标偏离 > 收益归因 > 研究摘要。不得把 AI 报告长度、信号数量或候选 ETF 数量作为产品效果指标。

## 5. 首版功能需求

以下编号为已确认的产品需求基线，供第二轮设计与验收引用；实现尚未验收。

### P-01 账户建档与初始对账

- 录入脱敏账户别名、券商、市场权限、币种、账本起点和初始持仓。
- 初始历史不足时，记录期初市值和可确认成本；不得伪造历史买价或全历史收益。
- 资金预算不自动生成现金；实际资产以确认的期初记录或流水为准。
- 保留尚未确认项目；确认关键现金及持仓一致前，阻止依赖该账户的实盘建议。

### P-02 导入、事实账本与更正

- 导入流程：上传/选文件 -> 格式识别 -> 字段与证券映射 -> 预览/校验 -> 用户确认 -> 入账 -> 对账。
- 支持资金、买卖、费用、分红、换汇和转账记录；不能把全部现金变动当作入金。
- 同一文件或成交重复导入必须识别；无法可靠判重时要求人工确认，不能静默重复入账。
- 分批成交和多个费用项目可关联同一执行事项；撤单不删除已成交部分。
- 错误通过更正记录处理，保留来源、批次、操作者及前后状态。
- 原始文件和真实交易资料存于受控存储，不进入代码仓库或 AI 提示词。

### P-03 估值、收益与风险展示

- 原币与人民币结果可追溯到价格、汇率、日期和数据源。
- 交易日不同或行情滞后时明确展示，不伪装成同一时刻的全球实时估值。
- 缺价格的持仓不按零处理；保留最近可信估值并显示未完成估值范围，或将指标标为不可计算。
- 现金和待投资资金计入总组合表现；分红、费用和汇率按统一核算规则处理。
- 回测、前向模拟与真实账户分别展示，名称不得混用“实盘”。
- 若部分税费仅估算，标明覆盖范围；若数据不足，显示原因而非零收益或零风险。

### P-04 资金计划与年度追加

- 新组合不预置金额、追加次数、年初到账或券商。用户在本地填写日期化资金来源，确认后保存；允许更改将来预算并保留历史版本。
- 登记实际到账日期、金额、账户和币种；计划/已到账/可投资/已安排/已成交的金额分别可查。
- 比较一次投入、分批投入和受约束择时方案；未批准前不自动选定。
- 计划包含每批预算、最晚处理日、延期理由、未成交资金去向及到期处理动作。
- 新资金可用于修复目标偏离；不能以“定投”名义绕过目标权重和风控。

### P-05 ETF 标的库与暴露识别

- 区分上市地、交易币种、底层地区、资产类别和主要风险暴露。
- 同一指数不同上市产品可以比较，但不可仅凭名称自动认定完全等价。
- 保存持仓覆盖比例与披露日期；只有前十大持仓时，不宣称已完整穿透。
- 可买性、停牌、退市或其他状态必须有依据；接口失效不得等同于全部标的退市。
- 纳入和移出候选库可自动提出；纳入生效投资范围需按治理流程批准。

### P-06 投资决策与执行清单

- 每次评估产生交易建议、不操作结论或阻断说明；月度评估即使组合不变也留痕。
- 交易项目必须包含账户、证券、方向、数量/金额、币种、价格条件、费用估计、资金依赖和有效期。
- 可查看执行前后配置与风险、建议依据、替代方案及未执行影响。
- 批准前及用户准备执行时重新检查关键输入；输入改变则失效并重算，不沿用旧批准。
- “已批准”“用户报告已下单”“已导入成交”“已核对完成”是不同状态。
- 未执行或部分执行时，以实际持仓重算剩余需求，不能直接重复完整原清单。

### P-07 策略实验室与 AI 研究

- 策略版本绑定参数、配置预算、执行假设、基准、数据版本和验证报告。
- 实验结果可重放，历史比较不能选择性隐藏失败版本。
- AI 输出需含证据来源与日期、事实/推断/建议区分、反证和待核实项。
- AI 只能提出研究意见和待审变更，不能写入真实账本、批准交易、扩大预算或覆盖生效规则。
- AI 无法获得可靠证据时应明确缺失；不得用语言模型记忆冒充最新行情或基金公告。
- AI 不可用时记录降级状态；能否继续确定性评估取决于策略预先批准的 AI 依赖规则。

### P-08 风控、运行和审计

- 数据抓取、估值、信号计算、风控、AI、通知分别记录状态，不以最后一条日志代表整轮成功。
- 区分成功、部分成功、失败和跳过；通知失败不反向改变事实账本或投资结论。
- 数据缺失、重复流水、账户差异、资金不足和策略停用必须形成显式阻断。
- 重要动作记录操作者、时点、原因及关联版本；单用户系统同样保留审计。
- 可暂停建议生成并继续查看账本、监测已有风险；恢复须通过验证，不因定时器重启自动解除。

## 6. 典型使用流程

### 6.1 首次使用

1. 审阅投资约束和未决项，建立只读/研究工作区。
2. 在本地填写账户与日期化资金计划，导入期初持仓及现金并核对实际情况，不从计划自动创建余额。
3. 配置数据源、证券映射和币种，显示缺口清单。
4. 研究配置结构、资金投入节奏和候选策略，批准相应政策。
5. 通过数据、核算、风控及验证门槛后，启用实盘建议。
6. 生成首期建仓清单，用户确认并在券商执行，回录实际成交。

### 6.2 计划日期新增资金

提醒计划 -> 核实到账 -> 更新原币现金及总组合 -> 对比目标偏离 -> 提出投入安排 -> 审核交易和资金依赖 -> 用户执行 -> 对账。到账日期可按本地计划设定；到账不足或延期时重排计划，不把未来承诺用于提前下单。

### 6.3 日常无动作

更新有效市场数据 -> 估值与风险检查 -> 按生效策略判断 -> 记录“不操作”及下次复查条件。数据缺失导致无法判断时，应显示“阻断/未完成”，不能显示“不操作，组合正常”。

### 6.4 调仓、部分成交与偏离执行

生成新目标 -> 风控 -> 用户批准 -> 券商执行 -> 回录实际成交。实际价格或数量不同、只完成卖出或漏做一腿时，先核算事实及剩余现金，再决定剩余动作；每次重算形成新的建议版本。

## 7. 建议运行节奏

具体时间和通知渠道待 D-08；不复用一个中国收盘时间代表全部市场。

| 节奏 | 工作 |
|---|---|
| 各市场有效数据更新后 | 数据校验、估值、风险监测和到期事项检查 |
| 每个策略获批评估时点 | 产生评估记录、目标或不操作结论；不等于每次交易 |
| 每周 | 数据质量巡检、研究摘要、待核实事项 |
| 每月 | 组合表现、费用、现金拖累、执行偏差和策略复审 |
| 本地配置的追加日期及年度复审日 | 到账核实、投入安排、投资约束与基准复审 |
| 事件触发 | 账户权限、基金重大变化、策略停用、数据异常和资金计划变更 |

休市不等于任务失败，抓取成功也不等于数据新鲜；按市场日历和数据类型判断。

## 8. 异常与恢复要求

| 异常 | 用户看到什么 | 必须采取的系统行为 |
|---|---|---|
| 行情/汇率过期 | 截止时间、缺失范围、受影响指标 | 阻止依赖无效数据的新建议，保留最近可信记录 |
| 券商文件无法解析 | 具体行、字段、未知证券及错误原因 | 不部分静默入账；允许修正映射后重新预览 |
| 现金或持仓对不上 | 账本与券商差异 | 锁定受影响的执行清单，允许人工核实事实 |
| 同一资金被多条建议使用 | 冲突金额与建议列表 | 预留或冲突检测，避免重复占用 |
| 建议过期/政策变化 | 原因、失效时间、关联版本 | 不自动延长批准，重新检查并生成新版本 |
| 采集只返回部分市场 | 覆盖率及缺失市场 | 不把未返回证券停用，不把部分数据判为全局正常 |
| AI 超时/输出不合法 | AI 复核未完成 | 按已批准降级规则处理，不制造结论 |
| 通知发送失败 | 决策结果与通知失败分别显示 | 可重试通知，不重复生成交易或记账 |

受影响范围无法可靠确定时，暂停全组合的新实盘建议，而不是冒险判定只影响单个标的。

| `worker/paper_trade.py` | 可借鉴交易流水结构，但不能替代真实跨账户账本 |
| `worker/analyze.py` | 从直接回写投资状态，迁移到有证据和权限边界的研究建议 |
| 共享 SQLite、调度与部署 | 第二轮评估隔离、并发、认证、备份和故障恢复，不先指定重写技术栈 |

本轮不迁移数据库、不删旧数据、不重算历史收益、不部署。现有代码审查风险与生产事故必须区分，第二轮按明确预期补充复现和修复验收。
