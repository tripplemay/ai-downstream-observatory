# 人工成交回录：事实与交收分别核对

状态：本地研发功能，未发布。它是已发生事实的转录入口，不是账户级买卖建议、券商订单接口、成交认证或策略执行报告。

## 用户路径

1. 在“账户资料”显式关联自己的私有账本并选择账户。缺失证券需先在高级账本登记明确身份；不按简称、代码后缀或挂牌市场猜测。
2. 自行在券商执行交易后，点“录入已发生成交”。系统只读取当前账户、版本、证券身份和未完成交收记录；没有行情查询，不预填数量、金额、费用、方向、日期或来源。
3. 按成交资料选择买入/卖出和证券，填写实际数量、不含费用的成交本金、已核对的费用总额、实际日期与资料时区，以及来源标识、唯一编号和独立资料说明。费用未知不能用零代替，不用行情价格倒算成交。
4. 逐项复核页面摘要并确认。改动任一内容会取消确认；提交前都是本地草稿，不生成委托。保存事实后，旧对账和旧估值不再是当前版本证明，先重新核对。
5. 现金确已交收且有独立资料时，另点“录入实际交收”，明确选择相关未完成交收成交，填写本次实际现金金额、日期、时区及交收来源。支持分次交收，但不得超过该笔剩余应收/应付。不会按成交日期自动补造交收，也不从账本预填现金金额。
6. 随后重新独立对账，并在高级账本生成和核对完整估值，再读取组合对照。入账、对账匹配、估值与交易批准是不同步骤。

若顶部显示“提交仍待核对”，只读取最新记录不能证明原请求失败。使用既有“核对并重试原请求”，恢复相同请求与幂等收据；不要改内容、编号或新建另一条请求。旧收据是历史受理证明，不证明原事实至今未被修正。

## 金融边界

- 买入新增证券数量和本金成本，费用独立计入费用，应付为本金加费用；不改变已结算现金。
- 卖出复用既有持仓与成本释放规则，应收为本金减费用；不改变已结算现金，不补造缺失持仓。历史成本未知仍由既有账本记录为未分类结果，不能据此宣称实现盈利。
- 独立交收只变动现金与应收/应付，不再次改变证券数量。复杂带符号交收、费用超过本金、旧事实插入或修正，使用高级账本；简化入口不会调整输入以使其通过。
- 日期只保留原资料的日精度和显式时区，不转换成虚假的盘中时刻。未来事实拒绝入账；早于已记录事实的输入转入受控时间顺序复核。
- 不写策略批准、激活、预占、执行报告或 AI 任务，不触发券商下单。此入口也不替代 P2 的账户级待审清单或执行报告绑定。

## 范围、重复与隐私

- 只允许当前登录用户经审计拥有并明确关联的账本与账户。工作区、关联、账本、账户行版本和范围摘要逐项核对；停用账户与恢复只读状态拒绝新写入。
- 来源标识及唯一编号以字母或数字开头，仅允许字母、数字、`.`、`_`、`:`、`-`，各最多 120 字符；中文说明填写在独立资料说明中。不得填写密钥或 Token。
- 复用既有账本去重：同一账户、来源标识、原始编号和事实类型的相同事实可复用原记录，不重复金融写入；不同事实冲突则拒绝。更换编号、事实类型、时间精度或时区不能视为可靠的重复识别。后续 CSV 必须保持真实来源和语义一致，再做独立对账。
- 已被修正的旧来源不能通过新请求复活。原请求幂等恢复不重复入账；命令受理审计与金融事实去重是不同层级。
- 草稿与范围读取期间暂停账户切换、CSV、新对账和组合数字读取。离开提醒；取消清除草稿，失去会话验证或注销清除私人表单，旧请求响应不能污染新登录范围。
- 人工转录输入和审计只在私有账本中保存，不发送 AI 网关。用户对三类脱敏研究证据的许可不包含真实成交、持仓、现金、账户或来源原文。

## 工程与验收

新增只读 `GET /api/workbench/investor/trade-recording?account=...`，必须绑定当前会话。写入复用 `POST /api/workbench/investor` 的严格 JSON、32 KiB UTF-8 上限、同源检查、二次会话核对、CAS、不可变收据与事务。没有新的金融迁移或订单接口。

只读范围最多读取该账本 10,000 条历史事件，最多 200 个明确证券、50 个正向未完成交收记录；超限拒绝，不截断为完整范围。金额与数量仅支持最多 12 位整数和 8 位小数的精确字符串，不接受指数、千分位或隐式舍入。原事实摘要、父成交的应收/应付以及交收的现金/对冲分录会核验，损坏证据不变成可选择的交收记录。

上述 harness 属于早期证据。本轮另外在隔离临时库、真实 Next 生产构建、认证 HTTP 和 headless Chromium 中，完成有资金账户的完整事实转录纵切；供应商、券商原件及生产验收仍不由它替代。

- 从空库保存未知风险偏好、建空账户、独立零余额对账，明确录入三币种外部资金。资金丢失响应恢复仍使用相同字节与幂等键，不重复入账。
- 在高级账本通过实际表单登记虚构证券；账户页明确回录买入和卖出，本金、费用及数量均独立填写。成交不改现金，买卖各两次实际交收只改变现金与应收/应付，不重复改变证券数量；最后独立填写三币种余额和证券数量对账。
- 缺估值时明确展示缺口。随后用现有、仅允许临时库的 `tests.investor.holdings_fixture` 提供明确标为虚构的价格/汇率及规则，执行真实 Python 估值计算；认证持仓 API 和页面独立复核整个人民币净值和构成。这个准备步骤是测试工装，不是普通用户估值按钮、真实供应商采集、真实行情资格或账户级投资建议。
