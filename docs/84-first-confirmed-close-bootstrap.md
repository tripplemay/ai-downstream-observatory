# 首个有效收盘与监测入流

状态：研发实现，未发布或完成真实来源验收。不批准新来源、历史任务重放、公司行动、税务、策略或交易。

## 2026-11-10 采集准备的纯校验复用（研发，未发布）

任务及时领取不等于实际采集及时开始。准备阶段仍须重新解析参考方案、重建历史、
核验当前来源和本次日历绑定；若这些工作耗尽最迟启动窗口，原传输围栏应拒绝调用，
而不是扩大窗口或重试。虚构首收盘夹具已复现：六份完全相同的事实在准备阶段共
完整校验 34 次。仅在准备入口增加作用域仍不够，内层历史重建和来源检查会重新
建立纯校验集合；两次中间回归失败均保留，不把部分减少写成最终修复。

本增量为准备入口建立独立、最多 128 个摘要的临时事实校验作用域。历史重建和
来源引用检查显式复用已有作用域；独立调用仍创建新集合，默认嵌套作用域仍隔离。
只复用 kind 与精确 JSON 数字表示绑定的成功纯校验，不缓存原文、返回对象、来源、
数据库读取、审计、所有权、最新版本、用途、期限、时钟或租约结论。变化后的内容、
无效事实和超出容量的内容仍完整核验。准备返回时作用域结束，延迟围栏提交重新
读取并完整核验当前来源；晚期撤权、过期、审计损坏和半份写入的原保护不变。

同一离线虚构样本的校验数从 34 降为 6。Mac 单次准备测量从约 0.538 秒降为
0.227 秒；未做统计重复，不能推断 Linux 或真实资料耗时，更不能承诺生产准时。
提交阶段没有沿用准备缓存。真实采集、完整 CI、实际应用时钟和生产发布均须独立
验收；原启动/结束窗口、最多一次尝试、无历史回退和所有测试预算保持不变。

本地九组 Python 回归 143/143、原两层根回归 509 通过及一项原有可选跳过，五个
跨语言发布器和标准生产构建通过。准备/提交计数随后收紧为不计入任务发现阶段，
独立重验通过。仍保留传输前窗口耗尽零次调用、撤权、租约耗尽、原件损坏和回滚
等全部原断言；这些离线结果不替代准确提交的 Linux CI 或生产真实来源验收。

## 用户路径

保存研究方案后，不应要求用户先手动构造监测输入才能监听收盘。历史接口仍要求过去的
市场当地日期，已耗尽的历史任务不能重试。新的首个收盘请求从当前已选、有效且已启用
观察的参考方案读取原授权、身份及明确接续的日历，独立登记一次监听；不编造旧监测
输入、价格、份额或起点。页面显示“首份监测收盘采集”、登记窗口、进度及下一步。
任务完成不等于监测已建立，用户无需来源编号或 JSON，也不应反复保存同一方案。

## 不扩大的边界

- 仅用于没有监测输入和检查点的当前重建模型，偏好、方案、控制和原来源仍须有效。
  原证券身份与币种一致，未知风险和费用不变成默认授权。
- 只计划本次时钟对应的当地交易日。休市不监听，标的间收盘或可用时刻冲突则停止。
  提前窗口、SDK 启动预算、尾部窗口和最大监听时长沿用既有规则，许可覆盖完整窗口。
- 每模型、市场、交易日只登记一次；数据库双向阻止与同日普通监听、自动历史任务重复。
  新任务纳入原全局行情互斥和收盘前保留窗口，最多一次尝试，暂停/恢复不重置请求。
- 部分、空、错过、失败或未知结果不重发，也不自动改走同日历史接口。之后只按原规则
  准备真正新的交易日，不把新会话当作旧请求重试。
- 不增加账户、购买、市场或提供方。ECB、发行人和 EODHD 的原每日次数、保管、单份
  本机备份及 AI 边界不变；无新增行动维护不替代新事件或历史更正批准。

## 采集和独立准入

准备阶段的来源重放和网络工作不占写锁。实际 SDK 调用前重新检查时钟、租约、停止、
控制、当前偏好/方案、是否已有首份输入，以及原授权/身份头信息。核验耗尽最迟启动
时间时零次调用；传输边界只缩短剩余监听，不延长原截止。运行只读、恢复锁及
`query_only` 连接均不能采集。采用原隔离 SDK 回调解析，其本地确认不冒充交易所签认。

最终提交仍须有效租约及完整当前来源复核，捕获、载荷、审计和任务结果原子登记。
晚期撤权、暂停、过期或写入错误不留下半份成功。这不是最终写锁耗时或生产 SLA 验收。
传输按时结束后，后续来源重放不误用网络截止作为原件作废时点；回执的实际起止仍须
落在原窗口，保管、许可、请求期限和租约仍按提交时钟检查，不延长或补跑网络。

默认 core 从保留的完整回执独立重放全部价格、身份、日历、公司行动、汇率和费用，
形成首份输入及归一化研究检查点。当前行动覆盖或 FX 未就绪仍显示证据不足；发行人
原规则可能要等下一日更新，不能承诺收盘后立即恢复。未知费用不填零，检查点不是
无需调整、实际资产或可执行的个人建议。首份输入建立后，普通监听接管后续交易日。
旧模型定义、历史请求、尝试和资料保留；不重新执行过去策略或拼接收益。

## 验收范围

隔离虚构来源覆盖默认任务的首个检查点、下一普通收盘、港股/美股独立日历和当前 FX，
以及部分/空/错过、传输前耗时、连接保留、并发撤权、只读、不可变请求和晚期回滚。
Node 独立读取实际回执进度与工作台状态，迁移使用真实非空旧来源、检查点和兼容收据。

## 实际应用时钟验收

新增独立 `test:first-close:http`：从空库普通登录、保存虚构偏好、默认后台生成参考、
普通保存观察及明确费用确认开始。拒绝过旧的保留价格后，实际等待虚构当日收盘，
仅替换隔离传输；应用、core、采集围栏与心跳均使用实际时钟。回调后由默认 core
建立首份输入和检查点，独立认证 GET 与 SSR 读取继续观察；撤回许可后隐藏当前估值，
仍只有一次采集尝试，九类金融事实表为空。没有预造监测输入、份额或检查点。

原生界面另从空库完成相同路径，验证登记、正在采集、继续观察、重载保留及撤回后
自动隐藏；组合方案与总览导航保留同一模型。桌面与 390 CSS 像素手机检查未见横向
溢出。来源、日历、费用、风险值与传输全为虚构，TLS 仅为本地临时证书；不是实际
交易所收盘、提供方、投资有效性或生产验收。

界面验收发现并修复费用状态覆盖问题：没有监测输入时，明确确认费用仍显示等待
合格行情，而不误称“监测输入已登记”。费用待应用缺口与估值隐藏不变，不改变准入。

此回归复用已构建应用，并在启动后先检查匿名 SSR 登录跳转，防止不完整构建仍进入
数分钟的监听。运行前须使用项目依赖齐备的 Python 3.11 和当前构建；在 `web` 执行
`npm run test:first-close:http`。通常约六分钟；若准备时接近虚构当地日期边界，实际
等待最多约四分钟进入下一日，不伪造应用时钟或扩展业务监听窗口。现有 HTTP CI 在
完整回归后串行执行，不增加生产采集次数或原 CI 作业期限。

同一实际时钟夹具追加了明确的虚构新资金研究输入，经正常来源准入和默认 core 生成
变化卡，再由普通认证 HTTP 登记暂缓并重新读取。它不是年度投入计划的午夜到期路径；
不预造观察、检查点或决定，不将假设资金计入原模型现金。原撤权场景保留独立有效输入，
不先让报价到期再把估值隐藏归因于撤权。

原生浏览器另在同一模型上验证继续观察、新资金变化卡、手机暂缓及重载保留，再用
明确缩短的虚构报价有效期实际等待到期，自动隐藏当前构成和变化卡，保留历史决定。
期间未撤回许可；这与撤权验收分开。全部成功和失败命令的原输出即时归档，成功步骤
另保留即时收据，三张截图逐张查看。最终核对一个采集尝试、三个输入、两个检查点、
一条决定，模型份额、现金、权益、应收与原检查点相同，九类金融事实表仍为空。
不因此宣称年度计划实际到期、三市场真实行情、性能或生产监测已验收。

`--serve` 仅供独立原生验收，输出本地临时登录资料的私有路径，不接受生产数据库、
URL 或调用方时钟。服务报告本身不代表原生通过，需另保存实际交互证据。测试结束
关闭临时监听和服务、删除临时库，并核对源码及构建标识没有变化。
