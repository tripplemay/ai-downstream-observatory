# 首个有效收盘与监测入流

状态：研发实现，未发布或完成真实来源验收。不批准新来源、历史任务重放、公司行动、税务、策略或交易。

## 用户路径

保存研究方案后，不应要求用户先手动构造监测输入才能监听收盘。历史接口仍要求过去的
市场当地日期，已耗尽的历史任务不能重试。新的首个收盘请求从当前已选、有效且已启用
观察的参考方案读取原授权、身份及明确接续的日历，独立登记一次监听；不编造旧监测
输入、价格、份额或起点。页面显示“首份监测收盘采集”、登记窗口、进度及下一步。
任务完成不等于监测已建立，用户无需来源编号或 JSON，也不应反复保存同一方案。

## 不扩大的边界

- 仅用于没有监测输入和检查点的当前重建模型，偏好、方案、控制和原来源仍须有效。
  原证券身份与币种一致，未知风险和费用不变成默认授权。
- 只计划本次时钟对应的当地交易日。休市不监听，标的间收盘或可用时刻冲突则停止。
  提前窗口、SDK 启动预算、尾部窗口和最大监听时长沿用既有规则，许可覆盖完整窗口。
- 每模型、市场、交易日只登记一次；数据库双向阻止与同日普通监听、自动历史任务重复。
  新任务纳入原全局行情互斥和收盘前保留窗口，最多一次尝试，暂停/恢复不重置请求。
- 部分、空、错过、失败或未知结果不重发，也不自动改走同日历史接口。之后只按原规则
  准备真正新的交易日，不把新会话当作旧请求重试。
- 不增加账户、购买、市场或提供方。ECB、发行人和 EODHD 的原每日次数、保管、单份
  本机备份及 AI 边界不变；无新增行动维护不替代新事件或历史更正批准。

## 采集和独立准入

准备阶段的来源重放和网络工作不占写锁。实际 SDK 调用前重新检查时钟、租约、停止、
控制、当前偏好/方案、是否已有首份输入，以及原授权/身份头信息。核验耗尽最迟启动
时间时零次调用；传输边界只缩短剩余监听，不延长原截止。运行只读、恢复锁及
`query_only` 连接均不能采集。采用原隔离 SDK 回调解析，其本地确认不冒充交易所签认。

最终提交仍须有效租约及完整当前来源复核，捕获、载荷、审计和任务结果原子登记。
晚期撤权、暂停、过期或写入错误不留下半份成功。这不是最终写锁耗时或生产 SLA 验收。
传输按时结束后，后续来源重放不误用网络截止作为原件作废时点；回执的实际起止仍须
落在原窗口，保管、许可、请求期限和租约仍按提交时钟检查，不延长或补跑网络。

默认 core 从保留的完整回执独立重放全部价格、身份、日历、公司行动、汇率和费用，
形成首份输入及归一化研究检查点。当前行动覆盖或 FX 未就绪仍显示证据不足；发行人
原规则可能要等下一日更新，不能承诺收盘后立即恢复。未知费用不填零，检查点不是
无需调整、实际资产或可执行的个人建议。首份输入建立后，普通监听接管后续交易日。
旧模型定义、历史请求、尝试和资料保留；不重新执行过去策略或拼接收益。

## 存储与视图

迁移 61 只增加独立不可变请求/结果和跨生产者防重复约束，不重建旧表；迁移 1-60、
既有行、rowid、原文和检查点保留。请求绑定原参考输入，不伪装成旧监测输入。结果
复用封闭回调结果形状，独立绑定新请求、任务和实际运行尝试。

新客户端明确请求 `X-Workbench-Investor-View: initial-close-v1` 并提供相同的绑定会话。
此视图包含既有资料维护摘要；旧或未知版本不接收新 `initial_close` 阶段，仅省略可选
任务进度，不改变独立研究结论。普通命令仍只返回原回执，不返回新状态或额外命令。
GET 只读任务元数据，不入队、不读取价格原文，也不批准数据。

## 验收范围

隔离虚构来源覆盖默认任务的首个检查点、下一普通收盘、港股/美股独立日历和当前 FX，
以及部分/空/错过、传输前耗时、连接保留、并发撤权、只读、不可变请求和晚期回滚。
Node 独立读取实际回执进度与工作台状态，迁移使用真实非空旧来源、检查点和兼容收据。

这不是实际时钟完整 HTTP/原生首个收盘成功、真实提供方或投资有效性验收。精确提交
CI、真实合法新窗口、全部当前数据、三态用户路径、性能/恢复、正式历史更正/长期接续，
完整 v2 P0/P1/P2 和受保护发布仍分别推进。
