# 年度投入监测的只读准备

状态：2026-10-09。本文保留只读准备与历史版本扩展的规则、缺口和验收基线，下面“未接入”描述对应这两个阶段，不是当前全部实现状态。后续默认 core 接入及其独立验收见[年度投入与默认持续观察](29-planned-funding-core-monitor.md)。仍不是到账、定投执行、收益预测、个人策略批准或生产发布。本文与测试仅使用虚构数据。

## 解决的缺口

[私有投入安排](18-private-planned-funding.md)已有计划版本，但持续观察模型仍使用独立监测输入中的投入意图。本切片先把当前保存计划、偏好、模型和登记时间绑定，准备可复核的年度批次假设，不修改旧输入或历史检查点。

只读入口为 `worker/investor/planned_funding_source.py` 和 `web/src/server/investor/planned-funding-source.ts`。它们独立核对工作区所有者、当前偏好、已选且启用的 reconstructed 模型、原研究来源、模型/方案哈希、当前投入版本及保存命令审计；无计划返回空，旧偏好、暂停、模型到期、失效来源或损坏证据拒绝准备。恢复只读模式允许读取，不写 revision、请求、审计、现金、单位或观察。

纯计算合同为 `contracts/v1/investor-planned-funding-monitor.schema.json`。纯函数中的 ID / 哈希只是绑定参数，不证明数据库所有权、市场来源或许可；不能用调用方提交的文档替代上述只读核验。

## 指定历史版本与当前有效性分开

`read_bound_planned_funding_monitor` / `readBoundPlannedFundingMonitor` 接收封闭的七字段版本绑定、原评估时点及当前检查时点。它们按指定计划 ID 读取，不自动改用最新计划；独立核对所有者、计划版本前缀、计划/模型/历史偏好原文和哈希、模型定义、登记时点、精确保存命令审计与未授权标志。评估不能早于模型/本版计划登记，也不能晚于当前检查；字符串时点必须是精确三位毫秒 UTC 格式。

新计划、暂停、新偏好或模型到期不会改写过去的**计划日历假设**。历史读取仍保留 `unadmitted_planned_funding_projection`，不核发当前行情、来源或模型资格。读取市场结果时必须另外检查模型及其全部来源/检查点留存期限；不能因计划历史仍可读取而重新展示到期观察。当前准备入口继续执行原研究来源、当前偏好/选中模型、启用控制及有效期核验，再委托历史版本读取。

两端准备返回内部 `context_hash`：从原计划重新计算后，将绑定、释放状态、归一化到期池、意图、下一批次及计划终点哈希。它排除每次轮询变化的评估时点和输入/结果摘要；同一释放区间内稳定，版本、当地午夜释放或期限边界改变时不同。这个摘要不是来源许可、到账证据或 AI 外发字段，不接受调用方自报的投影代替原计划。

SQLite 只读事务保持一致快照。限定测试通过另一连接保存新计划，验证在读事务仍看到原版本、结束后的下一读取看到新版；Python 则独立重放指定旧版与最新版本。此行为不等于默认 core 已在准备/提交期间持久冻结并重新核对了计划。

## 冻结计算口径

以下为研究准备算法，不是已经接通的投资者操作或策略建议：

- 起点是**模型创建与本版计划登记两个 UTC 时点的较晚者**。更早的年度释放批次明确排除；当日午夜已经过去也不倒填。起点正好等于释放时点则保留，晚一毫秒即排除。
- 只处理年度追加。初始计划本金作为比例分母，不再次加入归一化模型，也不模拟初始本金的三批买入；观察模型的固定初始名义值仍为 `10000`，不是个人现金、个人 NAV 或已完成建仓。
- 复用计划的当地日历、及时释放或第 0 / 30 / 60 个自然日三批。批次精确到分，余数归最后一批；当地午夜转换为 UTC，纽约夏令时不按固定 24 小时偏移。历史时区若没有唯一午夜，明确拒绝，不静默平移；负 Unix 时点和历史秒级偏移不舍入。计划日期不等于可交易日或到账证明。
- 到期但未执行的年度批次合并为**假设待研究资金池**。仅重复观察或采纳/暂缓/拒绝不会消费这笔假设资金；不能据此说真实资金尚未投资。真实成交回录与明确重建观察起点仍是独立链路。
- 先合计选中批次的整数分，再计算 `合计年度批次分 / 初始计划本金分 * 10000`，以整数有理数算术向下保留最多 18 位小数；不逐批舍入后相加，不使用浮点金额。输出金额是归一化研究单位，不能当个人应交易金额。
- 没有到期批次时，只准备下一释放时点的假设意图；已经到期时，意图绑定整个未执行假设池。当前计划版本、模型、偏好或选中批次变更都会改变意图哈希。没有年度追加、尚未到期、假设到期、全部早于起点和计划窗口到期分别表达。
- 计划期限终点不含在窗口内，期外批次明确排除；期限到达后停止输出投入意图。`valid_until` 只限制下一批次/计划终点的变化，**不是行情新鲜度、模型有效期、来源留存或许可的有效期限**。

日期运算使用各自运行时的时区数据库。跨平台规则变化若导致重放不一致，应阻断并重新核对版本，不自动改写已冻结日期；本切片没有为未来多年时区规则作保证。

输出有封闭字段、输入/绑定/结果哈希和 `unadmitted_planned_funding_projection` 资格。验证器必须从原请求重新计算整份结果，不能只检查调用方重算的结果哈希。所有到账、模型现金/单位变化、执行和实时建议字段固定为 false。旧监测输入/投影及 AI context 校验器明确拒绝这份新文档；没有资金金额、计划 ID 或日期外发到 AI。

## 默认监测接入前仍缺什么

1. 持久登记不可变计划版本与本次评估绑定；默认 core 去重必须包含计划版本及释放边界，不从可变最新计划重放过去。
2. 准备与提交之间再次核对版本、控制、来源和租约；计划改变或到期阻止旧结果发布。
3. 历史计划读取和稳定释放摘要已有实现；仍需在新请求/检查点中持久绑定它们并独立重放整条市场状态链。旧 SQL 的投影哈希约束和旧引擎历史语义不能放宽来容纳未登记假设。
4. 当前界面失效、未知费用阻断、下一批次提示及完整通知/AI 证据隔离；接受思路不能确认到账或执行。
5. 真实来源、适用用途与留存、认证 HTTP、原生界面、Linux / 构建 / 性能 / 恢复 / 生产验收。

本切片不更新模型 cash/units，不启动采集、core、网关、定投或交易，不修改用户真实计划。完整范围继续由 [v2 追踪](v2-implementation-progress.md)管理。
