# ETF 工作台行情源选型与接入准入

状态：2026-10-06 官方资料调研与工程选型建议，2026-10-07 补充 OAuth AI 工具及传统 API Key 路线；三地各一个 ETF 的本地 OAuth 报价/日线、API Key 短窗口日线读取已完成。代表性数据验收、持久采集与生产准入尚未完成。价格是页面公开参考，不是供应商对本系统的正式报价。

本文只描述通用产品方案，不记录个人资金、券商、持仓、账户或凭据。延续 [v2 组合优先方案](09-product-v2-portfolio-first.md)：系统形成研究参考组合并持续监测，用户自行决定是否交易。交易账户和数据服务解耦，不以额外开立证券账户、入金或交易换取行情权限。

## 1. 结论：优先验证既有授权、日频优先、按实际 ETF 和用途验收

**不新增券商账户，不等于排除已有账户的行情服务。** 运营者若已有长桥账户并明确选择复用，可优先验证 Longbridge/LongPort 行情，减少新供应商采购和新适配器开发；独立数据服务保留为补充及替代候选。这是有条件的接入顺序，不把“已开户”当作已取得 API、三地行情或长期留存权限。

长桥官方明确行情覆盖 A 股、港股、美股 ETF。当前 CLI、托管 MCP 和 ChatGPT App 支持 OAuth，不需要用户手工提供 API Key；传统 SDK 的开发者凭证要求不能当成所有工具的前提。API 数据权益仍需核验，不能从 App 可看行情推定全部可用。[新 AI 工具与授权](https://open.longbridge.com/zh-CN)、[API 行情权限](https://open.longbridge.com/zh-CN/docs/quote/overview)。本地交互可走 [CLI OAuth 验证](11-longbridge-ai-market-data-access.md)，后台容器候选路线见 [API Key 接入](12-longbridge-apikey-server-access.md)；两者均须独立验收样本、用途和部署条件。

既有账户路线的准入补充：

- 旧 SDK 只使用受控的 QuoteContext；新 CLI/MCP 只调用固定行情命令/工具，不读取账户资产/成交、不下单，也不全局放行交易能力。这不代表凭据本身已经被供应商限制为只读。
- 当前官方快速开始已将 SDK 名称由 `longport` 改为 `longbridge`，推荐 OAuth，仍保留传统 API Key；传统 Access Token 与 OAuth Token 不能混用。现有锁定的旧 SDK 不自动升级，也不能直接套用新文档的认证初始化；先核验兼容性或单独实施迁移。开通服务不要求运行官方交易/资产示例。[当前快速开始](https://open.longbridge.com/zh-CN/docs/getting-started)
- 日终观察不要求先买 L2。官方概览称基础港股为 BMP 延迟行情，定价/历史页另有 LV1 赠送说明，不能承诺统一免费权益；以实际 API 权限和可适用条款核验。A 股实时行情还有 IP 地域限制，日终可用性仍须实测。[概览](https://open.longbridge.com/zh-CN/docs/quote/overview)、[定价与地域](https://open.longbridge.com/zh-CN/pricing)
- 历史接口单次最多 1,000 根 K 线并有按月标的配额；回补须分页及完整性验证，不因市场总体历史较长而给近期 ETF 补造前史。[历史接口](https://open.longbridge.com/zh-CN/docs/quote/pull/history-candlestick)
- 现有适配器仅采不复权日线，不能直接提供完整总收益研究、分红/拆并份、历史 ETF 集合或持仓穿透；这些资料必须另外验收和补齐。行情存储、备份、non-display 与外部 AI 使用仍须满足第 5 节的准入要求。

**没有可复用的合格授权时，独立统一源的首选采购核验对象为 Choice，Wind 为替代候选。**

目标是用一个独立数据合同覆盖三地 ETF。这是工程和采购优先级判断，不是已经验证的数据质量排名。Choice 官方提供 Python 接口和 Linux 环境说明，适合进一步核验现有 worker 的接入方式；但公开的“港美股”或“基金”功能不能证明港、美 ETF 的全部字段和历史覆盖。必须先取得具体标的样本、服务器授权和正式报价，未通过就不作为生产主源。[Choice Python 文档](https://quantapi.eastmoney.com/Upload/EMQuantAPI_Python.html)、[Wind ClientAPI](https://www.wind.com.cn/portal/zh/ClientApi/index.html)

选择统一源的工程理由：减少三套证券映射、分红复权口径、授权合同和故障处理的维护。**不能据此假设它更便宜，也不能假设桌面终端授权允许无人值守的生产服务器。**

既有行情服务或独立统一源不满足覆盖、许可或预算时，采用以下分市场补充/替代路线，不要求新开户，也不退回网页抓取：

| 市场/用途 | 分市场首选候选 | 使用边界 |
| --- | --- | --- |
| 中国内地上市 ETF | Tushare Pro | 日线、ETF 元数据；分红/复权接口、服务器使用与留存权限逐项确认 |
| 香港上市 ETF | HKEX Data Marketplace 官方日终文件 | 直接交易所来源；文件规格、历史回补、公司行动和自动化使用许可另行核验 |
| 美国上市 ETF | Sharadar Prices 的基金价格与公司行动数据 | 日频、含退市基金的研究候选；不是实时交易报价；个人许可与留存条件需适配 |
| 产品身份、费用、净值、持仓披露 | 发行人/基金管理人和交易所产品资料 | 补充与交叉核验，不假设一个价格 API 提供全部研究资料 |
| 人民币统一观察口径 | ECB 参考汇率 | 信息性日频换算，不代表实际券商成交汇率 |

供应商依据分别见 [Tushare ETF 日线](https://tushare.pro/document/2?doc_id=127)、[HKEX EOSC 产品](https://data.hkex.com.hk/catalog/dataset/0a05f55287014916ab0ea3cff1c26000?lang=en)、[Sharadar 基金价格](https://sharadar.com/docs/funds)。产品资料和汇率口径见第 6 节。

**接入节奏采用日终数据，不先购买 L2、逐笔或分钟行情。** 这是针对长期组合和低频调整的产品选择；每天监测不等于每天交易。交易前的实时价格、买卖价差和可成交性由人工另行核对，日终研究价不能变成限价单依据。

当前没有任何一家供应商被本工程认证为三地 ETF 生产主源，也没有已授权、已验收的自动备用源。

## 2. 必须采购的是哪些数据

| 数据层 | P0 必须有 | 不接受的替代 |
| --- | --- | --- |
| 证券身份 | 挂牌代码、交易所、报价币种、产品类型、上市/退市日期、代码有效区间 | 仅凭名称或 ticker 后缀推定 ETF；把 ETN、杠杆或反向产品混入普通 ETF |
| 日价格与流动性 | 明确口径的未复权日价格、成交量/额、当地交易日期、币种、收盘定义 | NAV 冒充交易价；盘后价冒充正常时段收盘；空值填零 |
| 总收益研究 | 分红、拆并份等公司行动及可靠调整方法 | 将只处理拆分的价格称为含分红总收益；复权价再重复加分红 |
| 产品筛选 | 跟踪标的、费用、资产类别、规模及来源时点 | “全球股票覆盖”代替指定 ETF 字段清单 |
| 风险解释 | 有时点的持仓披露与披露完整性 | 将季度披露描述为当前实时持仓；将未知持仓归一化 |
| 日历与时间 | 各交易所完整/半日/休市日历、当地时区、数据发布时间或明确未知 | 周一至周五代替真实交易日历；用北京时间日期统一三地收盘 |
| 历史与修订 | 每只标的实际可得历史、历史标的集合、修订标识/更新时间 | 给新上市 ETF 补出十年价格；仅用今天存续 ETF 回测并忽略幸存者偏差 |

研究尽量使用十年以上历史及不同市场阶段；不足时显式缩短有效窗口或不纳入该研究，不伪造前史。今天下载的历史数据不自动成为当年已知的 PIT 数据。历史回补费用、退市数据和历史元数据必须单独列入报价。

## 5. 授权与长期留证：必须先解决的冲突

### 已核查的限制

- **Tiingo**：2026-08-05 更新的条款不允许 Starter 或任何试用方案持久保存数据，包含日志与备份；符合条件的付费订阅有效期间才允许按其条件存储，结束/降级后要求删除。不同保留期需要书面协议；派生输出也不能可重建底层数据。[条款第 1.6 节](https://app.tiingo.com/tos/)
- **Massive**：市场数据条款默认仅显示用途，non-display 或投资策略等派生用途需要适用授权/书面同意；账户终止、受限或暂停后有停止使用和删除要求。[市场数据条款第 2、5、8 节](https://massive.com/legal/market-data-terms-of-service)
- **Sharadar**：直接个人许可限定自然人的个人非专业用途，限制共享；终止后要求在 30 天内删除数据，可保留不包含且不能重建底层数据的研究输出。私有服务器运行、协作开发人员接触和长期证据保存需进一步确认。[个人许可第 2、4、10 节](https://sharadar.com/terms)
- **Tushare**：服务协议与个人权限也有用途限制，不能把个人 API 积分视为商业再分发许可。[服务协议](https://tushare.pro/document/1?doc_id=405)

这些是当前公开合同文本的调研摘要，不是已取得的本系统使用授权；具体订单、附加条款和供应商书面确认必须一并核对。**“个人自用”“有密码的外网页面”“没有下单”不自动豁免存储、non-display、开发协作或第三方传输条件。**

### 工程处理原则

当前价格路径把 SDK 原件放在不可变数据库 BLOB 中，并随数据库进入加密备份。该机制有审计价值，但不能兼容未经协议允许的退订删除要求，详见 [现有价格采集](market-price-collection.md)。不能先采进现有库，再以“加密了”“只是哈希”“是审计需要”作为永久留存的理由。

准入前必须选定一种经过批准的处理方式：

1. **取得明确留存许可**：合同允许内部保留原行情、研究输入及所需备份，明确终止后的期限；只在覆盖实际用途的范围内使用现有不可变留证路径。
2. **采用许可感知的行情存储**：将有删除义务的行情、可重建研究输入和副本隔离于真实事实账本之外，设计有效期、撤权、日志/备份清理和恢复后的删除规则。仅保留合同明确允许的研究输出与证据元数据；原数据删除后明确显示不能原件重放。此方案需要单独架构评审和验收，本文未实施。

真实成交、现金和用户自行上传的事实记录不因行情商退订而删除；同时，不能把许可行情复制进这些记录以绕过删除义务。不移除旧库触发器、不篡改既有不可变证据，也不承诺所有供应商都允许永久保留哈希。

公开仓库和 CI 仅使用合成 fixture。真实数据、样本、权限文件和供应商密钥放私有受控目录，不随源代码或测试工件发布。外部 AI 模型的推理传输、向量化和训练许可分别确认；未确认时不把供应商原数据送到外部模型，且“聚合过”不自动等于允许分享。

## 6. 汇率、发行人资料与价格口径

- ECB 公布以 EUR 为基准的 USD、HKD、CNY 参考汇率，可用同一发布日期/批次计算交叉汇率，例如 `CNY_per_EUR / USD_per_EUR` 得 CNY/USD。它是信息性参考，不是券商可成交汇率，CNY 也不能静默替代 CNH。[ECB 参考汇率](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html)
- ETF 发行人资料用于核对费用、NAV、披露和分配。比如 iShares 产品页提供相应资料入口，但价格、净值和持仓的时间与估值口径应分别保留；这里举例仅证明资料类型，不构成标的推荐。[发行人资料示例](https://www.ishares.com/us/products/239726/ishares-core-sp-500-etf)
- 产品公开披露不自动授予批量抓取、再分发或发送外部 AI 的许可；先核对下载和使用条件，再设计自动化。未具备完整授权时，可保留人工核验流程，不伪装为已自动接入。

核算继续区分两类价格：未复权价用于相应估值口径，含公司行动调整的序列用于相应总收益研究。显式分红现金流与复权总收益不能重复计算；已体现在基金净值里的管理费用也不能再按同一口径重复扣除。研究基准、策略、币种、费用和再投资假设应一致。

## 7. 对当前工程的影响

本轮只读确认了 `worker/market/providers/longport.py` 和价格采集文档：现有适配器固定 `longport==4.3.7`，使用 QuoteContext、日线及不复权口径；现有单次任务为同市场 1–4 个挂牌证券、最多 31 个自然日，不是完整长期历史供应链。[实现边界](market-price-collection.md)

该适配器保留为可选能力，默认禁用；若明确选择复用既有长桥账户，先验证 SDK 与当前服务兼容性、权限及数据准入，再有界接入。不自动启用生产，不要求开户，也不将其输出伪标为独立数据商。后续拟新增供应商无关的读数据合同，而不是用环境变量把其他供应商塞进 LongPort 身份：

```text
适用的数据许可与证券范围（独立服务或明确选择的既有行情账户）
  -> 供应商只读采集（API 或已授权文件交付）
  -> 证券/币种/交易日历映射与价格口径检查
  -> 许可允许的原件与规范化批次保存
  -> 有版本的数据质量、总收益研究与交叉核验
  -> 研究组合快照 / 监测状态 / 人工变化卡
```

新合同应明确供应商身份、许可配置版本、证券映射、当地日期、收盘定义、原始/调整口径、公司行动、收件时间、发布时间精度与修订情况；未知值保留未知。API 原字节与 SDK 投影分别标识。历史回补需要分页、续传和完整性核验，不沿用 31 日窗口冒充十年覆盖。

HTTP 成功不是数据合格；认证失败、限流、缺行、停牌/退市、未发布、日期未来、批次不完整、许可到期或来源异常必须输出具体缺口。旧的有效快照可以继续以其原截止时间展示，但不能标作“今日无变化”，也不能用于冒充当前有效的调整评估。

每个市场独立采集和判断新鲜度；跨市场研究须固定统一的已知时间截面及各市场最后有效会话，不将异步收盘拼成同时已知数据。备源只有独立授权、映射、同口径与差异验收后才能启用；切换产生新版本，不静默拼接两家的历史序列。

本轮未修改数据库、适配器、调度、页面功能或生产配置。UI 可以继续使用明确合成的测试场景开发，但真实参考组合仍受有效研究输入和策略门槛约束。

## 9. 样本、持续运行和故障验收

以下是拟执行计划，**本轮尚未执行**。免费/试用不允许持久化的服务，必须先获得适用许可再进入会落盘的测试；不能因“只是验收”忽略条款。

1. **许可与部署**：保存私有授权记录；从实际生产地域验证 HTTPS/证书、账号权限、Linux 运行、IP/并发限制及只读访问。禁止为解决连接故障回退明文传输 token。
2. **代表性标的样本**：至少 20 个挂牌样本覆盖三地、不同资产类别、分红/拆并份、多币种柜台和退市/改代码情形；每个具体标的核对身份、币种、字段、历史起点和缺失情况。
3. **价格与公司行动**：用交易所/发行人授权资料核对相同日期和口径，重放至少一种分配、一次拆并份及历史修订，验证未复权价和研究总收益不双计。若样本不含某类事件，不能称该能力通过。
4. **历史完整性**：测试十年窗口分页、截断、续传、重复和退市数据；近期 ETF 的不足历史有明确限制。历史元数据与今日快照不混用。
5. **持续采集**：至少覆盖各市场 10 个交易日，记录到达延迟、缺口、补发及告警；另用受控 fixture 验证半日市、节假日、DST 和不同收盘时间。短期通过不是长期可用率或 SLA 证明。
6. **故障与许可退出**：测试 401/403、429、5xx、超时、坏证书、缺行、异常公司行动及许可过期；确认不会返回“无需调整”、不会填零或悄悄切到未经许可的网页源。验证清理和备份恢复不会复活已撤权数据。
7. **首个纵切**：正常继续观察、新资金/策略条件触发待决策、数据陈旧导致证据不足；固定输入版本后可按许可边界重放。研究路径不写真实账本、批准或订单。

所有真实样本和验收证据放私有目录。公开测试只保留独立构造的合成数据；自动化检查、短期采集与人工数据核验分别记录，不把 CI 通过称为行情源已可靠。
