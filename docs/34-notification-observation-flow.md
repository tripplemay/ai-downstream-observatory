# 监测通知到观察记录

本轮沿用“快速形成研究组合，持续监测，由人决定交易”的主路径。通知只帮助发现和定位研究记录；不要求建立券商账户，不因打开消息或标记已读而采纳、成交或生成 AI。

## 1. 已复现问题与修复

在观察页打开研究通知，点击另一条观察的链接，原页面只发生 hash 导航，通知弹窗却仍然打开，遮挡目标记录。跨页面跳转不会复现这一问题，因此空通知和主导航验收不能覆盖它。

`investor-notifications-panel.tsx` 现在仅在 Next 的 `onNavigate` 中关闭弹窗。保留原观察 ID 链接；普通导航不标记已读、不改工作区版本或组合。修饰键/新窗口点击仍交由 Link 的原行为处理，不在普通 `onClick` 中关闭原窗口。

新增组件事件回归核对关闭、重新打开、未读数/发布身份不变，以及零 POST。事件工装不替代真正的路由、Radix 弹窗、键盘、焦点和滚动验收。

## 2. 隔离的发布纵切

新增两个只用于测试的入口：

- `tests/investor/browser_notifications_fixture.py`
- `web/scripts/seed-investor-notifications-fixture.ts`

它们只接受专用临时目录中的 `workbench.db`，要求空金融表、单一测试所有者。Node 种子入口要求空工作区，Python 研究阶段拒绝已有来源，监测阶段要求唯一的新模型；这些是测试目录/状态保护，不是普遍的真实资料识别器。使用固定虚构偏好、资料、价格与 SDK 替身，先通过实际服务命令保存偏好，再经默认 core 研究、服务命令保存模型、监测收据准入及两次默认 core 发布。通知不是手工 INSERT 的伪造 outbox。

网络/API/界面验收使用默认 Next 生产构建、真实登录/会话绑定和通知接口；不模拟 JSON 响应。只在故障场景中让真实已读 POST 提交后丢失其 HTTP 响应。价格/许可仍全部是合成 fixture，不能升级为真实行情或策略证据。

测试发布发生在固定历史时间。今天读取时，当前结论必须为证据不足；通知仍是历史发布提示。以此核对“历史记录保留”不等于“过期建议仍有效”。

## 3. 验收记录

新冻结 **977** 份来源下，**12** 个串行阶段、**280** 项限定回归通过：Python **42**、Web **69**、迁移 **169**。五个 worker 重建，来源前后不变。完整 `tsc` 在默认 Next 构建前后均零诊断；构建 `MNHatDVGgTc5LfEtjK41c` 通过。不是全工程回归或 Linux Node 22 验收。

实际 Next / 登录 / 安全 cookie / API / Radix 页面在桌面 **1440px**、手机 **390px** 各 **8** 流程，共 **16/16**：

1. 两次默认 core 合成发布、实际登录及 Secure/HttpOnly/Strict cookie。
2. 实际通知 GET、不可缓存、两种历史记录状态；当前结论独立为证据不足。
3. 已读在服务端提交后响应丢失；人工 GET 恢复，不自动 POST。
4. 同一发布重复已读复用同一回执；旧哈希、附加字段、跨源、缺会话绑定和查询参数分别拒绝。
5. 恢复锁下可读历史，UI 禁用已读，实际 POST 返回 423；解锁后恢复。
6. 键盘跨页及同页 hash 定位，两条目标均进入可见视口，弹窗关闭；刷新保留已读状态。
7. 正常已读 POST 回执与 GET 独立核对，未读归零；Escape 关闭/焦点恢复和刷新持久化。
8. 实际注销 303，刷新显示登录页、保护内容/portal 移除，通知 API 返回 401。

各步骤独立核对原始工作区/偏好/方案/模型/观察/决定/监测/任务/outbox/AI 等受保护行哈希不变、九张金融表零行。已读仅增加两条独立审计，不消费通知、不改工作区 revision 或投资事实。没有模拟 API JSON，仅故意丢弃一次真实提交响应。
