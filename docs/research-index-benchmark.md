# 研究历史检索优化与可复现基准

## 优化范围

仅修改 `worker/research/snapshot.py` 的冻结数据检索，不修改策略、执行、费用、资金流、FX、收益算法、研究 schema 或准入等级。

原实现每次选价遍历历史观察值，再为每条观察值遍历日历。长窗口反复估值会形成接近三次方的工作量。新实现预解析时间、按价格/FX 的观察与可见时点建立索引，并预计算“截至该可见时点，经济时间最新的可选观察值”。日历也按收盘/可用时点及可交易日期索引。

- 构建成本约为 `O(N log N + S log S)`，占用 `O(N+S)` 索引空间。
- 价格查询为二分检索加常数次检查；下一交易日也是二分检索，不再逐次解析全历史时点。
- 数据须在创建 `MarketView` 后保持冻结；索引不是可变行情订阅缓存。
- 相同观察/可见时点仍保留输入首行；冲突 revision、缺失所需交易日、FX 过期等保持原有拒绝结果。
- 晚到的旧观察值不会覆盖经济时间更晚的观察值；可用时间非单调的交易日历、实际摄取边界、跨市场时差、收盘后可见与事后估值的区别均保留。

## 冻结证据与回归

修改前的源码 SHA-256、旧检索 oracle 与 13 日完整报告 hash 保留在 `tests/research/performance_baseline.json`。其中 `multi90` 段于 **2026-09-12** 使用下述通用虚构资金参数重新建立：真实重跑未修改的旧 oracle，并与当前索引实现逐字段对照。该段不是旧参数的修改前冻结证据；原历史冻结基线仅保留本地。旧算法保存在测试专用 `tests/research/market_reference.py`，不被生产代码调用。

自动测试逐字段比较旧/新 90 日完整回测报告，覆盖晚到 revision、相同 rank 的稳定选择、冲突来源、缺价、非单调日历可用时点、不可交易日、实际摄取延迟、FX 过期和 A/HK/US 不同收盘时刻。另有 3300 日完整回测 golden 回归与“查询期间不得重新解析历史时点”的复杂度防退化测试。

## 本机测量

环境：Python 3.11.15，macOS 26.6.2 ARM64；本轮实测开始时间为 `2026-09-12T03:30:41.632052Z`。测量记录及源码、fixture、oracle SHA-256 见 `tests/research/index-benchmark-result.json`；不同机器或并发负载会改变耗时，测试不硬编码性能阈值。

|---|---:|---:|
