# 分页观察归档与完整人工决定

本增量补齐 v2 P1 的长期观察记录，不代替真实参考组合、持续行情、策略准入或生产发布。
总览仍回答当前结论；归档只回看历史，不能采纳、批准、预占、下单或确认成交。

## 普通用户路径

- “观察记录”每页最多 20 条，可向更早或较新记录翻页，不再只提供最近 50 条。
- 每条记录展示原状态、核对后仍可展示的理由、数据截止及约束版本；条件、缺口与输入版本放在折叠区。
- 每条观察分别读取自己的最近人工决定。点进详情可分页查看这次观察的全部决定，不受全局最近 50 条决定的影响。
- 通知链接显式指定观察编号，即使这条观察已不在最近记录中，也能进入对应详情；查看不会标记已读。
- 同时刻的记录按实际写入先后排序，不用随机编号推断哪个决定最后发生。刷新归档才纳入新观察和新决定。
- 原记录状态不等于当前建议。来源已失效时保留原状态标识，但仅展示原核验器仍允许的缺口说明；不恢复权重、金额、原始行情或已不可核对的历史条件。
- 恢复只读期间仍可翻阅归档。退出、会话失验或切换目标会清除私人显示并取消旧读取；迟到响应不能进入新范围。

## 读取与存储边界

`GET /api/workbench/investor/history` 返回历史页；可选的 `observation` 定位单次观察，`cursor` 翻页。
接口两次认证、强制当前会话绑定，拒绝多余/重复查询，所有者只取服务端会话；响应私有且不可缓存。
未知响应只允许显式 GET 恢复，不自动重试，不提交研究、AI、审阅或金融命令。

游标只定位归档，不是授权凭据。每次读取仍核对当前所有者与工作区，解析封闭的规范游标，并重新查找同范围的头与锚点。
一次浏览固定观察与决定的 append-head；后来的记录即使时间戳相同，也不会混入旧页。
前后页均采用键集定位，不读取全体历史、不全表计算总数，也不把界面的一页称为全部记录。

观察详情复用原有独立观察读取器，包括模型来源的资格与失效核对；归档 API 不返回模型金额、权重、价格或 AI 正文。
人工决定另外核对所有者、原审阅审计、原指令摘要及持久回执，不仅信任表中的文字。
历史读取不改变工作区版本、已读、审阅、账本、任务或 outbox。

迁移 46 仅追加四个查询索引，保留版本 1-45 的文件摘要、全部原行、rowid、外键和原保护规则；没有回填、删除或重写。
同时间的写入顺序由私有数据库核对，原始 rowid 不返回浏览器。查询计划回归检查追加头、按观察的决定和时间键集索引，
不将少量 fixture 的计划检查升级为十年满载性能证明。

为避免归档首屏重复重放旧的 50 条记录，观察页的通用状态仅读取最新观察摘要；归档另行分页。
归档页不轮询整份当前组合状态，只保留“刷新记录”一个内容刷新入口。其他页面与默认状态 API 的近期记录边界不变；通知保留自己的只读轮询。
