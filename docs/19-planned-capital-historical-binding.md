# 计划资本与连续历史比较的显式连接

状态：2026-10-08，本地研发计算、独立日期/本金绑定与经济字段重放。纯接口仍无数据库或发布副作用；独立[私有比较任务](20-private-funded-comparison.md) 已连接有期限的结果留存、按需独立经济重放与私有历史比较展示，尚未部署生产。不是未来收益预测、真实到账或交易授权。个人金额、券商和账户不进入本文。

## 为什么需要独立版本

[投入表单](18-private-planned-funding.md) 保存未来当地日期，[连续计算 v1](17-continuous-funding-path.md) 要求参数冻结时间早于研究窗口。现在设计策略、再用过去的资料比较投入方式时，不能把当前登记时间倒填为过去的预注册，也不能把不同年份或阶段重启后拼成十年收益。

新增 `investor-long-horizon-input-v2` / `plan-v2` / `result-v2` 明确限定为 `retrospective_exploratory`。保存调用者声明的参数记录、比较登记和信息截止三个时点；允许参数记录晚于历史窗口，但不允许记录晚于登记、登记晚于信息截止，或窗口尚未结束。资料取得/发布时点不能晚于信息截止。三个时点在此纯接口仍是声明，不是独立数据库登记证明。旧 v1 的合同字节、冻结约束及贡献资金必须晚于起点的规则保持不变。

## 映射规则

`investor-funded-history-input-v1` 包含已填计划、明确历史起点、历史数据与研究上下文，不接收调用者提交的计算结果或授权。

1. 历史起点须与计划起点同月同日，按整年平移每笔计划日期；不读取结果后改变月日或自动选择收益最高的窗口。历史起点限定 1970 至 2199 年，且整个研究窗口必须在信息截止前结束。
2. 保留同月同日年度追加、每笔本金、笔数和最多十年期限。闰日无法映射时明确拒绝，不移到 2 月 28 日、不删除一笔资金。
3. 计划结束日不含在窗口内。转换成连续引擎的含端点 UTC 窗口时，结束为当地结束日零点减 1 毫秒；不包含下一年第一笔资金或新一年的行情。
4. 计划到账仅在历史反事实中假设为该当地日期零点，不声称真实到账时点。上海、香港、纽约分别转换 UTC；自然日批次跨夏令时时不按固定 24 小时倍数。不存在或不唯一的当地零点拒绝猜测。
5. 每笔资本均比较及时释放和 0 / 30 / 60 日三批。原计划选择仅标记偏好路径，不依比较胜负修改选择。比较三批要求每笔至少能分成三个正的分金额；不能以舍入或改变计划本金规避。
6. 开始日同时有初始计划和首笔年度追加时，两笔释放表独立保留并分别向下等分、末批承接余数。连续账户的起始权益包括两笔，后续贡献只统计起点之后的资金；不将同日金额先合并再等分。其他贡献日期仍严格递增。
7. 本连接的研究现金精度必须在数值上等于一分人民币，接受 `0.01` 与等价拼写，拒绝其他精度。表单按分展开，不能让引擎按五分等其他精度重分批后仍声称保持同一计划；直接连续 v1/v2 内核的独立精度能力不变。

映射输出分别列原计划日期、历史日期、UTC 假设到账、逐笔三批与期外标记。本金合计保持一致；映射不确认现金，也不制造投资收益。

## 计算和独立检查

- Python `worker/investor/funded_history.py` 从封闭计划构造连续 v2 输入，实际调用两条资金路径的连续引擎，保留参数/成本/决策/资料不变。没有数据库、凭据、券商或网络操作。输入与输出继续使用 16 MiB / 1 MiB 上限和固定错误码；默认拒绝 synthetic。
- Node `web/src/server/investor/funded-history.ts` 独立生成日历、精确分金额、时区和连续输入；绑定检查核对原计划、所有日期/批次、登记字段、数据/参数/输入/结果哈希、起始权益、后续贡献及本金损益恒等式。
- **原绑定检查不是经济重放。** 自洽地同时篡改净资产与损益仍可能通过 `verifyFundedHistoryBinding`，故原函数继续返回 `economics_independently_replayed=false` 和 `publication_eligible=false`，旧合同字节与资格不变。新增独立接口的边界见下节，不能将两者混称。
- 包装结果固定 `source_independently_verified=false`、`parameters_independently_preregistered=false`、`actual_arrivals_confirmed=false`、`execution_authorized=false`、`live_advice_eligible=false`。当前登记时点和哈希不证明来源、许可或未使用保留期。

工程 CLI 为 `python -m worker.investor.funded_history`；直接连续 v2 CLI 需显式 `python -m worker.investor.long_horizon --retrospective`。均通过标准输入/输出处理仓库外私有 JSON，普通用户无需制作这些文件，也不能从公共 API 提交它们。

## Node 独立经济重放

`web/src/server/investor/funded-history-economics.ts` 提供纯函数 `replayFundedHistoryEconomics` 与 `verifyFundedHistoryEconomics`，不调用 Python/SDK、数据库、网络或真实账户。输入仍为上述明确历史连接，默认拒绝 synthetic；显式 fixture 权限不能改变来源资格。

- 独立行情索引核对来源模式、发布时间/重建假设/实际摄取、修订歧义、最新所需收盘、生命周期、FX 时效及三地日历。现金按到账进入 NAV、按批次解锁；所有决策、固定数量/预算、卖出交收后激活依赖买入、价格/FX/费用/舍入、分红应收/支付、拆分和期末未完成订单由 Node 从输入重建。
- 重算所有输出经济字段：本金/损益、持仓、等待现金、费用、TWR、ACT/365 XIRR、单位回撤/恢复、月/年最后观测快照与失败次数；不用待核验结果反推现金或收益。XIRR 范围仅为正的资本投入与非负期末价值，不将此接口当作通用多根现金流求解器；365 日口径参见 [Microsoft XIRR 定义](https://support.microsoft.com/en-us/excel/functions/xirr-function)，不是对 Excel 迭代实现或通用多根结果的兼容认证。
- 派生十进制数允许 `min(1e-12, max(1, abs(expected))*1e-40)` 的跨语言舍入差；原计划、到账/批次、时点、身份、哈希、布尔状态和整数计数仍精确核对。允许差异上限远小于一分人民币；自洽重封错误净资产/利润、费用、现金、单位收益或风险不能取得经济核验。
- Python 的 `engine_trace_hash` 是完整原引擎序列化摘要，包含超越函数最后位数；当前核验输入没有携带原完整轨迹。因此不会声称对这个不透明摘要做了逐字节认证，返回 `engine_trace_hash_independently_certified=false`。Node 单独重建的完整事件/曲线参与跨语言测试，而被核验结果的所有经济字段均重新计算。
- 此新接口核验通过时返回 `economics_independently_replayed=true` 及独立经济摘要哈希，但 **`publication_eligible=false`**。它不改原 Python 结果中的 false、不升级迁移 36 作业状态，也不自证来源/许可、历史预注册、未曝光保留期、到账、风险适配或交易资格。

## 尚待贯通

纯连接及新经济核验本身仍不读取数据库或获得发布资格。独立[私有比较任务](20-private-funded-comparison.md) 从迁移 35 核对当前记录，迁移 36 固定请求/作业元数据，迁移 37 限期留存私有计算结果。专用认证只读请求重建当前来源与候选输入，经固定 Node 子进程独立重放后才展示回顾性经济字段；旧作业合同及参考方案表不升级、不复制结果进去。该私有比较仍未认证独立预注册、策略有效性、真实来源或交易资格。

资料缺少多年覆盖、真实产品适用/成本/权益/FX 或许可时，应保持缺口，不能用本映射认证资料。60 日仍仅是释放上限，不保证研究成交完成；后续投入决策截止、阻断后的修复及重试设计继续保留。真实候选风险比较、自动更新/留存、AI、通知、实际账户回录、恢复/性能和生产发布仍在 [完整 v2 目标](v2-implementation-progress.md) 内。
