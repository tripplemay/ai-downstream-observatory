# 研究执行缺口与低峰值发布

本轮只改研究读模型、交互说明和代码镜像运输。没有修改研究内核、参数、风险答案、
试验预算、已曝光窗口或真实账户；没有批准新的经济研究协议、模型采用或交易。

## 1. 区分执行证据不足与风险预算不满足

内核的候选筛选同时要求：指标完整、候选与基准都没有模拟执行缺口、历史回撤及
冻结压力情景满足已确认预算。既有 `NO_CANDIDATE_WITHIN_CONFIRMED_RISK_BUDGET`
可能包含执行证据不可用，不能仅凭这个汇总代码建议提高风险预算。

Web 在核验原始结果哈希、登记试验和来源绑定后，按候选投影 `train_checks`：

- 训练指标是否完整；
- 该候选的模拟执行缺口数量；
- 同口径基准的模拟执行缺口数量。

这些字段不触发计算、改写旧结果或开放后续阶段。旧响应可不含该投影；没有检查
不能补成零缺口。所有训练候选不可用时，首屏明确说明证据问题；具体原因未在
原记录中分类时，不从数量推断是价格、汇率、分红或真实交易失败。
过期来源仍先失效；验证/保留期失败仍保留冻结候选，不改选或自动重跑。

## 2. 公司行动协议：待审，不在本轮悄悄改规则

当前有界模型遇到公司行动时取消对应冻结订单，固定数量、预算和价格上限不重写。
依赖该笔卖出的买单不能把未收到的款项当现金。因此取消与关联阻断是当前合同的
明确行为，不能仅因某次研究因此失败，就删除失败计数来使方案通过。

下一版本协议需单独明确以下问题，再冻结版本与试验预算：

| 问题 | 不可改变的边界 |
| --- | --- |
| 拆分或现金分红使旧提案失效后，何时允许形成新提案？ | 新决策使用其当时有效的价格、汇率和公司行动证据，不改旧订单 |
| 新提案是否等待新收盘，如何处理尚未支付的分红？ | 应收款不是已到账可用现金；不能用未来收盘或未来支付日资料 |
| 卖单取消后如何解除或重建关联关系？ | 原关联买单仍保留取消/阻断证据，不挪用不存在的卖出款 |
| 冷却期从提出、部分执行还是完成开始？ | 写成版本化规则，不能事后选择使历史结果最好的一种 |
| 如何区分正常提案失效与不可实施的执行缺口？ | 原始事件与旧版失败记录保留；不改变旧结果哈希或曝光记录 |

是否采用新协议及新试验需单独确认。观察、取消、重算均不等于用户批准交易。

## 3. 构建移出 VPS，保留完整发布门槛

受保护的 release job 在 Runner 上从准确提交构建 Linux/amd64 镜像，构建步骤不接收
VPS 凭据、个人资料或行情。随后才建立已核验的 SSH 信任并传输源码与镜像包。
不新增镜像注册表或长留的大型 Actions artifact。

`scripts/release-image-bundle.py` 提供 `build / pack / check / load / verify`：

1. 固定镜像名、准确 SHA、UID 10001、OCI revision 和平台；拒绝已知秘密类型的镜像环境变量。
2. `docker image save --platform linux/amd64` 仅保存本次两张核心镜像，可显式增加 provider。
3. 包含压缩包字节数/哈希、运行时配置和有序的未压缩 rootfs layer diff IDs。
4. 加载前核对私有文件、有限大小、重复 JSON 字段、归档路径/类型和准确 tag 清单。
   限制压缩包 4 GiB、展开内容 8 GiB、10000 个归档条目、JSON 1 MiB；不向宿主解包文件。
5. VPS 加载后重新核对层与运行时配置指纹，再进入原有备份、停写、迁移、恢复演练及健康检查。

保存和加载支持 gzip 和显式平台筛选；平台参数需要 Docker API 1.48+。
见 [Docker save](https://docs.docker.com/reference/cli/docker/image/save/) 和
[Docker load](https://docs.docker.com/reference/cli/docker/image/load/)。

经典与 containerd image store 可能使用不同形式的 image ID，因此记录两端 ID，
但不把它们直接相等作为唯一依据。跨端比较有序 layer diff IDs 和规范化后的
User、Env、Cmd、Entrypoint、Labels、Healthcheck 等运行时配置；不能只凭同名 tag 或 revision 放行。
这不是第三方签名或供应商认证。

每次上传使用 `incoming/<SHA>/images-<run-id>-<attempt>/`，不覆盖同次上传文件。
`--image-bundle` 必须属于该发布路径，并与服务器的 provider 启用状态一致；不一致
明确失败，不自动禁用角色。手工未提供镜像包时仍保留原构建路径。

## 4. 验收与限制

- 合成单测覆盖 hash/tag/平台/配置/秘密变量/权限、异常归档、跨后端 ID 差异及失败前的零 daemon 写入。
- Linux 容器 CI 实际 pack/load 两张镜像，后续迁移、账本隔离、恢复与 HTTP fixture 使用加载后的 tags。
- 三张实际发布镜像、生产指纹、资金摘要及外网页面仍需每次单独验收。
- 本轮不能以合成用例、save/load 成功或 CI 代替策略有效性、满载性能、异机恢复或完整 v2 验收。
- 移出构建不等于无限空间：镜像载入、三次备份及新目录恢复仍占用磁盘，原有空间门槛继续执行。
  不自动 prune 任何共享缓存、业务镜像、容器、数据卷或备份。
