# 私有工作台的反向代理连接生命周期

## 观察到的问题

外网登录/退出验收中，Nginx 在投资者读取和退出路径记录 `upstream prematurely closed connection`。同期应用容器没有 OOM 或重启；实际 Node 运行时默认后端空闲超时为 5 秒，未配置覆盖值，而站点启用了上游连接池。证据与复用已关闭后端连接的竞争相符，但没有包级证据证明所有此前传输失败都出于同一原因。

不通过延长页面等待、开放非幂等请求的代理重试，或重复已提交业务命令来掩盖错误。退出返回 502 后，先用同一浏览器只读确认会话仍有效，再验证修复；不把浏览器等待超时直接解释为操作未发生。

## 最小修复

仅在本站点的代理位置将后端 `Connection` 改为 `close`，避免私有低流量工作台复用后端连接；前端 HTTPS/HTTP2、回环上游地址、转发的 Origin 信息和现有读取期限不变。没有开启 `proxy_next_upstream non_idempotent`，不自动重发 POST，也不改应用、数据库、行情用途或交易权限。

运维应用前保存精确原配置，校验候选差异和完整 Nginx 配置；校验失败且文件仍为本候选时，只还原本文件，不加载失败配置。成功后平滑重载，核对所有其他 Nginx 配置哈希及应用容器标识不变。该过程不修改已发布的应用源码目录或镜像版本，回滚也必须绑定本次精确文件，而不是覆盖整个代理配置。

## 验证范围

- 配置合同测试检查后端关闭语义、没有扩大 POST 重试或期限，以及 TLS、回环路由和转发来源边界。
- 实际配置已通过语法检查并平滑重载，其他代理配置及四个应用容器未改变。
- 同一既有会话从有效状态，经真实页面退出后，会话与投资者 API 均返回 401；未重复登录，没有金融业务写入。
- 修复后用独立临时 Cookie 完成一次新的外网 HTTPS 登录、认证读取、版本化进度读取及退出；旧 GET 保持封闭响应，新 GET 保持会话绑定。密钥、个人金额和行情原文不进入公开证据。

配置合同、一次实际路径及有限观察窗口不等于满载性能、长期故障率或全部 v2 功能完成。此前的传输失败、浏览器任务空闲释放、首个导航超时和失败退出均保留，不改写成通过。公开默认配置与运维热修复分别核验；公开提交仍须经过完整 CI。

Nginx 上游连接缓存语义参考[官方文档](https://nginx.org/en/docs/http/ngx_http_upstream_module.html#keepalive)。应用中任何手动事实、资金和审阅操作继续遵守原有 CAS、幂等与未知结果核对规则。
