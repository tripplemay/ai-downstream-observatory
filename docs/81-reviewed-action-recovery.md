# 新公司行动的明确审阅与观察接续

状态：研发中。当前完成后端纯检查、已留存资料的未批准草稿、短时确认见证、
明确回答后的原子人工登记、不可变接续及完整新审阅接续关系的独立 Web 原文复核；
持久后台任务桥、独立私有预览读模型、普通确认 API 和表单已实现并完成本地定向验证；
普通监测重新准入及本增量生产启用仍未完成。
这不是“新增事件已经可以自动批准”，也不是完整 v2 验收。

## 产品目标

[有界维护规则](80-no-new-action-maintenance.md)只处理没有新增行动的日期。
发现分红、拆分或更正后停止是必要的，但不能让普通投资者重新填写来源标识和 JSON。
最终路径应为：看到具体变化 -> 核对必要假设 -> 明确确认 -> 登记新的审阅和接续关系 ->
后台以完整来源重新准备观察输入。历史记录及旧阻断保留，不重试未知采集或授权交易。

普通确认界面、持久接续及监测恢复属于本需求，而不是可用一个“需联系运营”提示替代的后续愿望。
历史更正也需要明确的人工复核、重述或新研究起点路径，不能以永久阻断冒充该能力已经完成。

## 已实现的准备边界

`worker/investor/reviewed_actions.py` 提供两层检查：

- `check_reviewed_action_append` 接受旧事实、明确填写的新事实、前后两组已解析资料和显式时间边界。
  它只准备追加证明，不验证所有者、来源授权或持久发布。
- `preview_reviewed_action_successor` 在只读事务中核对所有者、原规则及控制、新的未启动规则、
  分别存在的人工审阅、当前来源声明和控制、保管期限、传输、原文字节及解析结果。
  新人工审阅必须使用独立来源记录，不改写旧来源或旧人工行。

旧规则即使已阻断或暂停，其最后成功发布也只能作为历史比较依据。
准备器重新计算原始输入证明、候选事实和截止，不相信自洽重封的摘要。
这条比较路径不把旧发布恢复成当前合格输入，不清除隔离，也不启用新规则。

### 未批准草稿不先创建人工批准

`worker/investor/action_review_draft.py` 的 `preview_action_review_draft` 从既有规则定位当前纽约日期的
正常采集批次，在所有者检查之后重放保留原文、授权、控制和身份；不要求先创建新人工审阅或新规则。
缺失或失败批次不回退到昨天、不排队或重试。旧成功发布只提供已经完整重放的历史比较依据。

草稿按日期并列展示发行人分配组件、EODHD 原始/调整金额、记录与支付日期、拆分分子分母及前后差异。
旧报告精确变化显示为历史更正，不混入普通追加；晚于两源交集的已报告行仍保留并标出。
每行绑定完整原解析记录的哈希，未投影字段的变化不能被显示子集隐藏。金额不舍入或采用容差。
日期字段不被猜成精确时刻，税额、有效时刻和支付时刻均为空，不默认填零或午夜。

这是包含具体资料的私有所有者预览，与只输出摘要的追加证明不同；不进入既有外部 AI 解释上下文。
草稿明确列出金额单位/币种、时点、税额、报告完整范围、知识协议及继续维护授权的待确认项。
草稿 DTO 保持 `confirmation_supported=false`，不因生成草稿而取得批准能力。
以下领域函数由持久任务桥及普通 API/表单调用；登记成功仍不能称为普通监测已经恢复。

草稿依赖摘要绑定所有者、规则、控制、旧发布与事实、前后完整资料及当前原文出处，不把每次检查的动态时间
混入稳定摘要。预览仍保留自己的原始截止，最多 60 秒且受底层期限截断；未来确认必须同时验证原截止及重新计算的
依赖摘要，不能因为摘要相同就延长原确认，也不能因为单纯刷新时间变化就丢弃未改的输入。

### 明确确认的持久领域协议

`worker/investor/action_review_workflow.py` 和迁移 55 新增两张只追加的元数据表，
不重建旧人工审阅、价格或模型表，不复制价格历史：

- `register_action_review_preview` 仅登记服务器检查时间、原截止、工作区版本和完整依赖摘要。
  所有者检查先于私有资料读取；预览不会创建已批准来源、规则或交易事实。
- `resolve_action_review_preview` 以只读事务重放同一基础，并私下提供原税务说明供核对。
  税务原文不出现在公开契约示例或 AI 上下文。过期或版本变化不能自动延长旧确认。
- `confirm_action_review` 只接受逐个新报告日期的显式研究有效时刻、支付时刻和税额，
  不能由客户端填写毛额、拆分比例、证券、旧事实或新期限。金额/比例由保留原文精确推导，
  不能表示为既有事实精度的比例拒绝而不舍入。税额中的空白、超范围和隐式零值均不接受。
- 必须逐项明确确认金额单位/币种、两源差异、研究时点、税额、原税务说明仍适用、
  报告范围而非客观无遗漏、不重述历史，以及登记新默认停用规则。
  是否启用新规则另用显式布尔选择，不从旧的无新增授权推断。
- 同一事务重验来源/控制/身份/版本/截止，创建独立来源与人工审阅、新默认停用规则、
  不可变接续收据及旧规则退役；只有显式选择才启用新规则。提交末尾再次检查真实时钟及恢复锁。
  来源变化、晚期错误、并发版本变化或超时全部回滚。退役规则不能重新启用或另建分叉。
- 请求在入口深拷贝绑定；并发相同请求只返回同一登记结果。回执丢失后可恢复原元数据回执，
  不重复批准或延长原见证。历史回执恢复与当前来源资格重验是不同接口，前者不授予监测准入。

Python 当前合格读取重新核对原始字节、两代规则控制、所有者回答、完整追加证明及原预览依赖摘要。
不能通过修改证明并重封哈希/审计冒充原始来源。多代接续只有精确不变的旧事件继承原人工审阅及知识时点；
新增事件使用新确认的真实登记时间。不仅凭同额、相同 ID 或旧哈希推断更早知识。
递归有上限及环路保护，不放宽既有来源到期、撤回或检查点重述保护。

此领域层仍固定 `monitor_data_readmission_required=true`、`research_admitted=false`、
`quarantine_cleared=false`、`trading_permission=false`、`raw_ai_sharing=false` 和 `provider_calls=0`。
独立 Node 已实现下面的跨人工审阅原文证明，但不能据领域登记和读取成功称为普通用户端到端恢复。
当前同步领域提交会再次执行完整来源检查，尚无普通长任务/写锁性能验收，不应直接暴露为长耗时同步 HTTP 操作。

### 持久交互任务桥

`action_review_jobs.py`、独立 Node `action-review-jobs.ts` 和迁移 56 将交互请求与实际审阅登记分开：

- 入队只保存所有者的明确请求，不递增工作区版本，不为了排队使自己的原预览失效。
  幂等恢复先读取原请求；旧规则已退役也不能令同一请求重选新规则或重复批准。
  同一工作区只接受一个尚在有效窗口的未完成请求，不按时间最新掩盖无关规则歧义。
- 默认 core 发现并处理固定本地任务；行情角色不能处理它，也没有 SDK/HTTPS/AI 或交易调用。
  每项任务最多一次尝试，失去租约或结果未知不自动重试、不换请求或放大来源预算。
- 原文草稿与确认准备在作业写事务外完成，使用绑定同一连接的提交闭包；提交仍重新核对
  版本、原截止、来源、控制、停止、恢复及真实时钟。原文登记过程仍有既有写内复核，
  不能把准备已移出写锁说成所有写内原文工作或生产性能已验收。
- 领域变更、任务结果及作业完成共享最终租约围栏和原子提交。请求过期时，已经暂存的领域写入
  回滚后可保存明确拒绝；租约丢失或恢复锁出现时，领域变更及成功结果一起回滚。
- 任务结果只保存引用、哈希和固定状态，不再复制行情或整份原文。确认请求私下保留用户填写的
  税额/研究时点和明确回答，便于审计；不公开、不发送给 AI。状态接口只读元数据，不返回可重放的确认正文。
  新会话可以读本人的登记状态，但客户端仍不得在会话变化后自动重发旧确认。

普通交互使用显式 `owner_review_15m` 见证政策，为阅读和后台排队保留最多 15 分钟，
受原来源期限和当前纽约日期结束截断。既有运维调用默认仍为 60 秒；既有见证行、原截止及原知识时间不变。
客户端不能传入此政策或期限，只能由新的普通请求在服务器建立。刷新读取不延长原见证或自动保留旧同意。
任务自身最多等待/执行五分钟，并受原见证截止截断；确认时仍完整重放当前来源及原预览基础，
不因窗口变长而复用失效许可或更改税务、资金和交易权限。

任务桥验证普通 Node 入队 -> 持久任务 -> 默认 core -> 领域登记 -> 独立 Node 状态/确认读取。
以下普通入口已接线；明确选源、旧检查点接续和完整持续监测恢复仍须独立完成。

### 普通私有预览与明确审阅入口

`GET/POST /api/workbench/investor/action-review` 与 `InvestorActionReview` 提供无需内部标识/JSON 的入口：

- 用户主动打开后才读取状态，从唯一未退役规则选择 VT/BND。多个无关规则仍是歧义，不以最新记录替代；
  后台准备及最终提交也重新检查同一唯一选择，期间出现无关新规则则登记拒绝，不批准来源。
- `preview_ready` 仅是历史任务收据。服务器另在同一只读快照从保留字节重算完整预览基础、
  当前纽约日期的正常批次、来源许可/控制、身份、原截止和工作区版本，才能展示具体两源差异及原税务说明。
  读取不请求来源，不采用昨天资料，不创建批准或延长原见证；失败隐藏具体旧预览。
- 表单把日期和两源未舍入金额并列，研究有效/支付时刻及税额初始为空。用户明确填写 UTC 研究假设，
  换算后的纽约日期须与来源一致；零税额必须主动填写，不能从旧文本推断。所有八项确认陈述均须同意，
  启用新有界规则是另一个默认不勾选的选择；更改输入或见证清除旧同意。相同基金的未确认草稿可保留，
  不同基金不得因日期相同而继承税额或时刻。历史更正、共同范围外报告或不支持的差异只展示，不普通追加。
- 原始请求在同一会话内固定正文/nonce。响应丢失先按 nonce 只读查询，未找到不回退别的最新请求；
  仅用户明确点击才原样重发，不自动 POST 或生成新 nonce。接受回执后只轮询同一任务标识。
  会话变化清除本地原文/输入，不跨新会话自动重放；历史登记状态与当前研究准入始终分离。
- 认证、Origin 和必需的会话绑定先于正文；最多 512 KiB 严格 UTF-8、重复键拒绝的封闭输入，
  非等待式超限取消，正文后及返回前重验会话。私有响应不缓存，错误不回显正文或原生细节。
  浏览器独立校验响应范围、原请求意图哈希、见证哈希与时限；元数据不能单独打开确认能力。
- 打开审阅期间暂停父工作台刷新并锁住其他修改；本入口自己的状态读取保持可用。
  旧回调也不能越过该锁。预览过期禁用确认，读取失败隐藏具体资料；登记收据明确表示监测仍须重新准入，
  不清除旧阻断，不表示行情、费用或模型已验收，不生成交易。

本地定向 Web 116 项、Python 141 项及 TypeScript、Next 生产构建通过；根目录 409 项通过、1 项可选测试跳过，
集合不重复相加。浏览器使用真实本地登录及空规则 GET，表单的来源/确认响应明确替换为虚构资料，
验证 390 CSS 宽度无横向溢出及键盘单次提交。后者是呈现层证据，不是完整实际来源 HTTP/后台闭环。
精确提交完整 CI、重新准入、真实来源与生产界面验收仍开放，本阶段没有提供方/AI 调用或生产变更。

### 独立 Web 接续复核

`web/src/server/investor/action-review-lineage.ts` 不调用 Python 获取可信结果，
而是从数据库中的原保留载荷、传输收据、来源授权/控制及人工审计独立重放：

- 先核对所有者，再读私有见证或事实；确认封闭契约、原始 JSON、行列、哈希、审计、幂等请求、
  工作区版本、原见证截止和原规则哈希相互一致。历史回执不成为当前来源资格。
- 旧退役或隔离规则的最后成功发布仅作为历史比较依据，仍核对其完整原文和派生证明；
  该比较接口不复活旧规则。正常当前来源读取仍拒绝已退役或隔离的旧规则。
- 从原文独立计算原人工基准、已发布覆盖、新人工事实、所有者逐项回答、原/退役/新控制，
  再计算完整追加证明及原预览依赖摘要，不只检查工作进程给出的若干计数或哈希形状。
  自洽重封假证明、原见证基础、税额、支付/有效时点或启用选择均不能代替这些证明。
- 只有完全核验的不可变接续可以继承逐事件原审阅和知识时点；两代接续分别保留根事件、
  第一代和第二代新增事件的实际可用时间。没有接续的同事实新人工审阅仍使用自己的时间。
  递归上限 256，并拒绝环路，不修改旧输入、旧检查点或金融事实。
- 逐事件继承及完整 v4 监测快照分别使用同一延迟只读事务，避免在来源/控制分代变化间混读。
  真正只读连接可完整重放；原文损坏、来源撤回、审阅失效或到期仍拒绝当前资格。

虚构原文 -> 明确领域确认 -> 原始行情接收器替身 -> 价格/FX/行动 v4 快照的 Python 构建与独立 Node
逐字段一致已验证，包括窗口外旧知识引用和窗口内新增行动。负向夹具先暴露了旧事件时间被换成新审阅时间的缺口，
再验证修复；测试不把假收据、假行情或显式模拟的时钟称为真实市场证据。
该独立复核纵切本身不证明监测重新准入、旧检查点接续、真实三态或生产安装；普通入口见上节。

### 追加事实

- 原事件及其顺序、原税务说明、证券和起始范围必须精确不变。
- 新事件必须晚于原先已经登记的覆盖截止，而不只是晚于最初人工审阅截止。
  补报旧覆盖内的事件属于历史更正，不能以“新增事件”绕过重新复核。
- 分红毛额与支付日期、拆分比例分别与保留资料精确核对；EODHD 新名义差异另计，
  不舍入、不设置接受容差，也不自动接受。滚动窗口自然移出的旧行不制造负差异计数。
- 税额必须明确提供，不从旧自由文本、历史比例或零值推断。
  当前准备范围不修改原税务说明；改变税务规则须走另行明确确认。
- 当前仅支持保守的资料接收时点作为新增事件最早可用假设。
  知识时点不得早于完整保留资料的传输完成/记录时间，也不得晚于新审阅。
  更早公告时间需要独立证据，不把除息日或供应商日期字段冒充精确公告时刻。
- 发行人报告的较晚事件不能被另一源的较早截止裁掉；缺失、日期/币种冲突、
  旧记录变化、使用许可失效和保管到期继续停止。

毫秒记录时间与微秒传输时间分别保留。知识下界取两者最大值，不把晚于同毫秒记录头部的
真实传输完成时间向前截断。准备结果最多展示 60 秒，并受已知依赖期限截断。

### 不把事后接收伪装成事件前已知

既有研究数据集要求 `published_at <= at`；当前接收时点若晚于事件发生，
准备层明确返回 `late_knowledge_event_count`、`continuation_timing_ready=false` 和
`requires_separate_knowledge_or_start=true`。这是结构化事实已经核对、但普通连续监测还不能接续，
不是点击确认就可绕过的门槛。测试实际调用原数据集验证器，确认它仍然拒绝这种未来信息。

若用于原研究协议，仍必须核对可保留的事件前来源记录，或采用另行明确、带依据并诚实标记的重建假设协议。
下面的独立监测版本允许按实际评估时点使用晚到资料，不等于事前知识或历史回测准入；
原追加准备标记不能单独证明它与某个既有检查点可以连续接续，不能为了通过验证回填更早的公告时间。
监测晚到处理必须以实际评估时点核对已知范围，不能改写早先决策或放宽研究回放的未来信息保护。
发行人原文的全部归档范围与所选历史窗口也须区分：窗口外日期提示只能用于发现待核对资料，
不能单凭提示证明该新事件的金额、身份或时点。此类时点证明尚未在当前准备层实现。

已有模型状态内核本身区分有效时点与实际获知时点：旧检查点截止早于事件、资料在当前评估前已知时可以推进；
评估时仍未知则不产生检查点，已完成历史中的补报仍要求重述。新增纯内核性质测试分别验证这些边界，
以及首次观察不领取入场前分红，不代表来源接线已经完成。

版本化接线还必须保持旧事件的原始可用时点。旧 v1 投影使用当前审阅头部的创建时间，
而规则续接的虚拟头部随发布更新；直接换算法会改变已处理事件的哈希，触发 `ACTION_RESTATEMENT_REQUIRED`。
性质测试保留该保护：即使经济金额和事件 ID 未改，不能悄悄重写其知识时点。
新协议通过原文与既有固定规则解析原人工基准时间；跨不同人工审阅的逐事件继承仍需不可变接续关系，新事件才采用新审阅时间。
不能在读取旧输入时原地换算法、改变既有 `projection_hash`，也不能从旧哈希反推出更早时点。

### 独立的 v4 监测来源协议（研发中）

`build_audited_monitor_dataset` 与 `build_monitor_data(..., audited_action_knowledge=True)` 显式产生
`investor-monitor-source-snapshot-v2`、监测专用数据集、v4 元数据输入和 v2 投影。
原 v1/v2/v3 输入继续使用原算法读取、重放原哈希；普通首次采集/CLI/界面尚不默认切换到新版本。

- 资料与人工审阅在同一只读事务中冻结。快照逐事件绑定当前审阅、完整原事实哈希、原人工审阅及其哈希和实际 `known_at`，
  覆盖该审阅的全部事件，不因所选价格窗口裁掉旧知识绑定；缺项、额外项、重复项或来源变化都拒绝。
- 固定无新增行动规则只改变覆盖日期，其事件事实和税务说明必须与原基准精确相同。
  原人工审阅时间成为稳定的事件可用时间，续接发布头部仍保留真实登记时间，二者不混淆。
  新的无接续关系人工来源不会仅因金额相同而借用旧时间。
- 监测专用数据集保留原事件时点和原 `published_at` 字段作为原事实，不将它认定为提供方公告。
  实际审阅知识时间不得早于声明可用时间或晚于冻结评估时点；税额、比例、支付顺序、身份和精度校验保持。
  Python 和 Node 分别要求除息/拆分有效时刻落在对应市场的已有交易日期，且不晚于当日未复权收盘。
  缺少该交易日或时点在收盘之后必须复核，不能把已除权价格先用于尚未发生的行动；
  支付时刻是独立语义，不要求支付日也有交易收盘，不猜测开盘或提供方精确事件时间。
  它不是 `research-dataset-v2`，普通研究契约和原回测验证仍拒绝该专用结构及晚于事件的历史知识。
- 价格/日历的共同校验只作用于明确标记行动不完整的内部市场事实子集，该局部对象不返回、不准入研究。
  行动日志另以专用契约和逐项语义完整验证；没有把删除行动后的价格对象冒充公司行动完整研究资料。
- Python 与 Node 分别重放原始价格载荷、人工审计、固定规则和原文，分别重建知识绑定、数据集及投影。
  自洽改封更早知识、另一原审阅或投影摘要，不能代替独立来源证明。Node 不调用 Python 来获取待相信的结果。
- 后续确认收盘和费用更新保留已选新协议，不降回旧版本；资料到期、撤回、未知费用、缺新行情和恢复锁照常停止。
  AI 上下文的全目标用途检查识别新版本确认收盘引用，但不增加任何外发授权或向 AI 发送该日志/原文。

迁移 54 仅重建监测输入元数据表以扩展版本约束，显式复制全部旧列和 `rowid`；不复制价格历史或重置模型。
非空升级、原 v1/v2/v3 输入、子检查点与外部 FK、原触发器和晚期失败全部回滚均单独验收。
新 v4 还绑定既有费用假设；已存在生效记录时，缺失、空或伪造费用绑定不能用新版本绕过。

当前已验证虚构保留收据 -> v4 准入 -> 普通 core -> 独立 Node 读取与普通状态、费用更新及下一确认收盘的路径。
这不是普通新事件确认与恢复已完成：新人工审阅的不可变接续及独立 Node 证明已实现，但普通入口和重新准入尚未接通；旧协议已有检查点不能静默换时间或自动重启；
晚报落在已完成历史内时仍须明确重述。真实来源、普通表单、完整接续及生产启用继续开放。

### 输出不是批准

新契约 `investor-action-successor.schema.json` 将纯追加证明和只读准备分开。
只输出标识、摘要、截止、计数及明确状态，不输出原金额或税务文本。
两层均固定 `handover_registered=false`、`research_admitted=false`、`trading_permission=false`。
只读准备可以证明一个既有人工审阅记录和来源绑定已经核对，不代表本次调用进行了人工确认。
该输出不进入 AI 上下文，不扩充现有外发许可。

## 必须继续完成的整条流程

1. 将已实现的**未批准**后端草稿接到普通界面，展示新事件、原始差异、单位/币种/时间及税务待确认项。
   不得为了预览先创建已批准审阅或启用规则。普通用户不填写内部标识或 JSON。
2. 明确确认绑定当时所见的完整草稿、所有者、来源、控制、期限和版本。
   来源变化时保留输入但使旧确认失效；新税务假设和继续维护授权不能默认勾选。
3. 将已有原子领域确认接到受控普通任务；完成新事件的实际监测时点资格或明确的新起点协议。
   领域确认已登记人工审阅、默认停用规则、不可变接续及旧规则退役，但不是重新准入。
   仅在用户明确选择时启用新规则。失败全部回滚，丢失回执仅重取原请求结果，不重复批准。
4. 已有 Python 与独立 Web 完整接续/原文核验还须接到普通选源和来源恢复。只替换明确绑定的旧基准及派生行，
   不按时间最新覆盖其他重叠来源；新链失效也不回退到旧隔离规则冒充当前资料。
   新基准已覆盖当日、尚未产生更大范围发布时，仍须正确处理明确核验的“覆盖未扩大”状态。
5. 原监测输入只能提供历史引用，不直接恢复估值。新输入重验价格、FX、行动、成本、
   模型和完整链；不重置本金、原失败槽、原始订单异常或已曝光研究。历史更正另作影响范围复核。
6. 完成普通页面、认证/会话/恢复锁、默认 core、独立重放与正常/新资金/陈旧三条纵切，
   再经精确提交 CI、受保护发布和真实生产验收。不能把当前准备器当成这六步均已完成。
