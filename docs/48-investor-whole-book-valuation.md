# 普通用户的全账本估值入口

## 使用路径

账户资料保持可选，不影响研究参考组合。需要对照已记录的真实账户时：

1. 将已发生的资金、成交和实际交收导入或回录到自己的关联账本。
2. 使用独立原件核对每个账户，包括停用账户。对账后出现新事实时，先重新对账。
3. 在“对账后生成组合估值”点击“核对估值准备情况与任务”。读取不计算、不入队、不采集行情。
4. 核对共同截至时点，显式选择已发布的价格/汇率来源、当地预期交易日及汇率最大时效；填写核查资料说明，确认公司行动完整后提交。不要求手写 JSON，不预选来源或勾选批准。
5. 核对后台任务，再点击“复核对照”。只有既有持仓验证器独立确认的完整快照才展示人民币净值；任务受理或计算结束本身不是完整估值证明。

这是记录快照，不是券商实时同步或交易建议。共同截至时点取全部有效独立对账的最早截至时点，不把不同日期的账户拼成实时资产。价格和公司行动要求保守包含历史曾记账证券，以覆盖该时点可能仍有的持仓；不是认定这些标的现在仍持有。

## 实现边界

- `GET /api/workbench/investor/valuation` 必须登录、提供当前会话绑定，不接受查询参数；重新核对 SID 与用户，返回私有不缓存的元数据。读取有事件、标的、来源及对账附件容量上限，不截断资料伪装完整组合。
- 来源仅显示本用户在本账本提交且已发布、可重验的价格/汇率。人工来源须有原队列审计、成功发布任务及匹配计划；官方来源继续核验原采集回执。`manual_verified` 仍只是人工来源声明，不能升级为供应商认证。此入口不新建数据许可或生产采集授权。
- `request_linked_valuation` 是封闭投资者命令，重新核对账本所有权、当前关联、工作区与账本 CAS、全部独立对账和来源上下文哈希。明确确认仅用于本次估值规则，不改研究偏好、资金计划或交易授权。
- 复用 `enqueueWorkbenchTask`、core 任务租约/栅栏和既有 Python 十进制定价引擎。新增可选 `expected_inputs` 绑定账本 revision 与所选行情发布头；排队后改变则以 `VALUATION_INPUTS_CHANGED` 跳过，不静默改用新版本。准备后的并发变化仍由原持久化复核拒绝。
- 复用上层不可变请求和原 idempotency key 的显式丢失响应重试；不自动再次提交、不新增资金或持仓事实。恢复只读锁也阻止成功请求的再次提交。
- 表单编辑重置确认；草稿锁定账户切换、关联、CSV、资金/成交回录、对账及其他父级操作。换范围、注销与会话失效清理私有草稿，旧响应/回调不能提交；请求 `finally` 中止未读取的响应体。
- 任务状态只表述后台执行，不显示任务结果中的 NAV。完整性、行情新鲜度、当前账本、独立原件和目标身份仍由既有 holdings 读取链逐次核验。
- 没有数据库迁移；旧不带绑定的高级估值请求保持兼容，新增普通入口固定使用绑定的 `restated` 模式。

## 验证与未完成项

跨语言测试覆盖含证券/外币和人民币纯现金的真实队列计算、不可变重试、所有权、全部账户对账、来源发布证据、恢复锁、迟到审计回滚、排队输入变化，以及计算结束但结果不完整仍隐藏 NAV。路由测试覆盖登录、会话绑定、同源、SID/用户切换、闭合请求与错误脱敏；组件测试覆盖惰性读取、空白选择、重新确认、旧回调与草稿锁。

工装仅接受隔离临时库。行情是明确虚构的人工声明，经认证 API 入队和真实 core 发布；估值必须从实际工作台表单提交并由真实 core 计算，不直接写成功结果。它覆盖桌面与 390px、资金及估值各一次已提交但响应丢失的原请求重试、精确人民币净值和新事实使旧快照隐藏。

本地工装不代表真实券商原件、数据授权、三地连续行情、容器/满载性能、生产可用性或完整 P2 已通过。简化来源的自动准备、真实研究与监测、账户级待审/执行报告、完整发布和独立外网业务验收仍需继续推进。
