# 公司行动资料的只读交叉复核

状态：研发中，尚未发布。本文不批准公司行动完整性、税务、持续派生规则或交易。

## 目的与用户路径

持续监测需要完整、有效的公司行动输入；“来源已采集”不能直接转换为“资料已批准”。
本增量将私有来源的人工排查整理为可重复的只读复核入口，减少逐份读取 JSON 的工作，
但不要求普通投资者在首次研究时填写这些标识。

当前入口属于高级运营。普通工作台已有的四项草稿进度仍只读取任务元数据，
不会因本入口重放成功而改称已验证行情或当前投资建议。后续审阅界面、明确的来源优先级、
日期时点重建、税务和完整性批准、可续接的长期来源仍须分别实现和验收。

## 输入与证据

显式选择同一证券的当前身份审阅，以及同一纽约采集日期的三份已保存资料：
Vanguard 分配清单、EODHD 分红记录、EODHD 拆分记录。
当前范围仅为已实现的两组固定请求映射，不据此声称覆盖全部美股、港股或 A 股。
请求代码与基金号一致只是请求绑定，不是原文自证身份、美元或每份金额。

```sh
python -m worker.investor.data_pipeline \
  --db /private/data/workbench.db --workspace WORKSPACE --actor OWNER \
  check-action-crosscheck \
  --listing-review LISTING_REVIEW \
  --issuer-capture ISSUER_CAPTURE \
  --dividend-capture DIVIDEND_CAPTURE \
  --split-capture SPLIT_CAPTURE
```

数据库与父目录沿用私有文件要求。该命令以 SQLite `mode=ro` 和 `query_only` 打开已有库，
保留原 schema、迁移清单和 WAL 检查；关闭 `query_only` 也不能将该连接升级为写者。
其他命令保留原默认读写行为，没有迁移。

一次延迟读事务核对所有者、当前身份审阅、当前来源声明和控制头、请求与回执、原文字节
及解析哈希。暂停、重新启用后的旧控制、过期、已清理、错误证券/基金/资料种类、不同采集日
和合成资料均不能通过普通命令。内部测试必须单独显式允许合成资料，结果仍标记测试范围。
本命令不读取 Token，不发出来源请求、不发现或入队任务、不登记审阅、不清理载荷，也不调用 AI。

## 比较含义

- 只在三份资料的日期交集比较，保留各输入总数和交集内数量；交集不是历史完整性证明。
- 以除息日关联；只有组件种类唯一、登记日和支付日不歧义的 `INC/CGLT/CGST` 组才用 Decimal
  精确合计。重复组件、不同日期、缺失记录、未知可选日期和币种差异单独计数，不填零。
- 比较发行人所报数值与 EODHD `unadjustedValue`，不以复权 `value` 替换。
  [EODHD 官方字段说明](https://eodhd.com/financial-apis/api-splits-dividends)区分两者：前者用于历史每份金额，
  后者以当前份额口径复权。发行人原文缺失的币种、单位与税，仍需要明确审阅。
- 不舍入任何原始金额或经济输入。不同数值保持“差异待审阅”，另外输出 0 至 18 位、
  half-up/half-even/toward-zero 的数值关系计数及规范化小数位直方图。
  多种规则可以同时拟合一份样本，不能据此确定供应商规则、设置接受容差，或证明未来结果。
  官方文档没有给出本工具可据以放行的固定舍入精度承诺。
- 空拆分清单不是实际没有拆分的证明；非空清单也不自动批准比例方向、身份或行动覆盖。

输出采用封闭的 `investor-action-crosscheck-v1`，只含标识、哈希、数量、日期范围、诊断和明确缺口。
不输出原文、事件金额、税务假设、密钥或个人预算。`refresh_after` 最多 60 秒，且不超过身份、
来源政策及原文保管期限；它要求重新检查当前控制，不代表历史资料被变成最新行情。
每次调用都重新核验；输出自身不是可供研究准入信任的来源证书。

## 权限与后续工作

所有输出固定为未审阅、行动不完整、研究未准入、不可用于当前建议或交易；数值全匹配也不改变这些状态。
既有草稿授权不升级为长期自动批准，旧研究、观察模型、失败槽、资金与费用假设均不修改。

下一阶段需让审阅者明确核对身份、金额单位、日期重建、税务和覆盖范围，再通过独立批准流程使用资料。
长期更新还必须保持历史输入和检查点可重放，不能简单覆盖旧行动审阅，亦不能把多个有重叠范围的
独立来源随意标作唯一当前来源。此入口是该流程的证据准备，不替代完整 P0/P1/P2 验收。

## 验证边界

虚构单元及来源存储纵切覆盖精确数值、舍入诊断、日期/币种/组件差异、真实只读连接、控制撤回、
错误绑定、原文损坏、保管到期、CLI 和独立 Node 契约。测试中的官方传输分支由明确的虚构接收器替身驱动，
不是实际提供方成功证明。精确提交完整 CI、生产安装、真实资料复核和普通界面仍须独立核验。
