# 人工执行跟进：回报、已记事实与预占分开

本功能补齐 P2 的一段普通用户路径，不代表完整 P2、真实策略准入或生产发布已完成。
研究模式不自动建单、批准、发送券商订单、推断成交或交收；个人记录仍只留在私有工作台。

## 用户路径

“账户资料”在逐笔成交回录之后增加可选的“清单与人工执行跟进”：

1. **核对执行记录**只读取当前私有账本、所选账户的既有历史清单、已记成交、原件候选和回报。
   历史数量、限价和有效期不是当前可执行建议；没有清单时明确说明，不从研究方案或计划资金建单。
2. **关联已入账成交**要求逐项选择清单明细、同账户/证券/币种/方向的已记买卖、支持该关联的独立原件。
   不预选、不按数量相近自动匹配，也不让用户在此新填成交数量。实际事实须先在回录或导入流程确认。
3. **登记券商状态回报**由用户明确填写提交、部分成交、全部成交、撤销或拒绝，以及回报原始数量、来源和唯一编号。
   即使填写“全部成交”，它仍不是已确认事实，不改变证券、现金、收益或剩余预占。
4. 可直接存证 UTF-8 CSV/JSON 原件，无须先建立导入任务或手写政策 JSON。最多 4 MiB，保留 BOM/CRLF 等原始字节；
   不解析成金融事实，不认证券商原生格式。原始文件名不进入此上传协议或审计，也不发送原件给 AI。
5. 逐项确认后只提交对应受控命令。关联成功后仍须按实际交收资料记录现金，并独立对账和估值；采纳、回报、成交、交收彼此独立。

回报和关联历史显示原始来源、说明及中文偏离原因，原始代码另行折叠。历史记录不能恢复已经终止或过期的交易权限。

## 金融边界

- 新关联只复用所选成交原有的持久账本收据。重新核对原指令摘要、行字段、来源、审计、去重收据、证券变动和对应分录；
  调用原 `recordExecutionFact` 服务后必须仍返回原事件的重复收据，且账本版本不变。任一不符整笔回滚。
- 核销仅使用原服务的有效剩余预占与数量逻辑。重复关联不再次核销，不把回报数量当成成交数量；另一清单或另一原件不能静默重绑。
- 已终止、过期、超量、限价及旧版本情形保留原偏离；不自动复活预占或追认过去获得授权。
  对已经入账的事实做事后关联时，关联时账本已经变化会留下相应版本偏离，不伪造过去审批状态。
- 券商状态回报单独复用 `recordExecutionReport`。本次只将这两个执行入口的原件读取扩展到既有安全读取器支持的 CSV/JSON；
  G/S 准入、账户能力等需要 JSON 结构的入口仍保持原有 JSON 校验。
- 未决更正、损坏事实或原件、不同账户、停用账户和恢复写屏障均不绕过。历史参考方案与 `live_advice` 准入仍不混用。
- 日精度保留原日期和资料时区。未交收读模型使用资料时区核对当地日期，不用 UTC 日期拒绝合法的当地日期，也不补造盘中时刻。

## 接口、持久化与并发

| 接口 | 用途 |
| --- | --- |
| `GET /api/workbench/investor/execution-followup?account=...` | 历史执行资料的只读、完整范围核对 |
| `POST /api/workbench/investor/execution-evidence` | 有界 multipart 原件存证；不导入事实 |
| `POST /api/workbench/investor`：`link_recorded_execution_fact` | 显式关联已经存在的成交 |
| 同接口：`record_linked_execution_report` | 记录非事实的券商状态回报 |

新接口要求当前登录、会话绑定、禁止多余查询；写入要求同源，读取完整请求后再次认证。
原件请求体最多 5 MiB、文件最多 4 MiB，拒绝重复/多余字段、压缩编码、非法范围和非法 UTF-8。
回报及关联继续使用原 32 KiB 严格 JSON、不可变投资者请求和回执；不接受浏览器提供任意账本指令。

工作区、私有账本关联、账本、账户版本和上下文摘要逐项绑定。摘要还纳入原清单及创建收据、已记事实、审批、预占、原件元数据和回报：
别处取消清单、更新事实或添加原件都会使旧草稿失效，不静默换用新输入。
历史清单原件及其输入摘要独立复核，不仅信任同名 ID 或数据库状态文字。

上传有独立、持久的请求摘要与回执。未知响应保留原文件字节、范围和键，必须由用户显式重试原请求；
只返回已经核对的原存证，不重复产生金融事实。既有同内容附件可复用，但审计和账户范围仍分别验证。
原件存证不改变投资者或账本版本，成功后重新读取上下文，再重新确认关联。
恢复写屏障也拒绝已经提交过的请求重试。原件落盘后事务失败可能保留无引用私有文件，不声称已获得成功回执或物理擦除。

当前简化入口有完整范围上限：组合 10,000 事件、账户 200 条既有清单明细/买卖事实/回报、50 份原件、400 条预占及 1,000 条审批事件。
原逐笔成交入口的证券/未交收上限继续有效。超限明确要求高级复核，不截断后称为全部记录。
这些是资源保护边界，不是十年规模、满载性能或所有券商格式验收。

## 交互保护

原件与执行草稿冻结同账户的其他写入口、账本/账户切换和组合数字读取，但不把自己锁死。
父工作台继续负责关联/回报命令的未知响应恢复。取消本地草稿不会删除已存证原件、撤回已受理请求或撤销券商操作。
退出、会话失验或范围变化清除私人草稿并中止旧读取；迟到的旧响应/401、旧提交及上传回调不能污染新范围。

## 软件复现与验收边界

所有测试数据均明确虚构，不是实际券商或 G/S 准入证据：

```sh
cd web
npm run pretest
npx tsx --test --test-concurrency=1 tests/investor-execution-*.test.ts
WORKBENCH_DIST_DIR=.next-fixture-production npm run build
cd ..
node web/scripts/serve-workbench-fixture.mjs --production --with-execution-records > /private/test/fixture.log 2>&1
# 在另一终端执行，保留隔离 fixture 直到验证完毕。
python3 tests/investor/browser_execution_followup.py \
  --fixture-log /private/test/fixture.log --output /private/test/browser-result
```

只允许脚本新建的临时 fixture，不接收普通数据库作为初始化目标。fixture 停止会删除自身临时数据库与原件；
生产凭据、私有个人资料、真实行情和 AI 服务不进入该测试进程。
浏览器验证包含真实 HTTPS/认证路由、桌面/390px、已成功提交但丢失响应的原件与关联请求、
不可变请求重试、回报不入账、重复关联不二次核销、金融表原样保持及恢复屏障。
自签 loopback 仅验证软件会话流程，不认证外网 TLS、Linux、真实来源、完整账户级建议生成、全量负载或生产发布。
