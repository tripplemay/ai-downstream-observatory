# 无经济变化时的明确人工维护恢复

状态：已确认的产品恢复缺口及待实现设计，不是已可用功能、规则变更或生产授权。
本路径属于 v2 的持续观察，不替代新增行动审阅、历史更正、长期接续或其余 P0/P1/P2。

## 缺口

无新增行动的维护遇到终态采集失败、缺失或其他阻断后，原规则保留隔离，暂停/恢复不能
清除。之后的新日期即使按既有授权取得完整资料、两源精确无变化，普通新增事件审阅
仍要求至少一个新事件；其无变化预览明确不能确认。因此目前没有普通用户可完成的
无变化恢复路径。不能伪造一个事件来通过追加校验，也不能让后台偷偷清除原阻断。

## 必须交付的普通路径

1. 只有后续已授权新日期的资料确实完整、有效，才提供“复核维护恢复”的入口。
   当日失败或结果未知仍不重试，不复制昨天的资料充当今天，不额外调用提供方。
2. 独立重放原审阅、最后合格覆盖和当前两源原文，检查身份、许可、保管、控制、
   滚动窗口连续性及全部重叠记录。旧名义差异必须精确未变，双方均无新事件或更正；
   空清单不升级为客观不存在行动的证明。缺失、变化或来源不可读仍停止。
3. 页面明确显示原停止原因、旧/新报告范围和未变的经济内容；请求单独的恢复确认。
   原有自动维护授权、旧的新事件回答及“没有新增记录”都不视为本次恢复同意。
4. 确认必须有独立、封闭、版本化的意图和不可变收据。原新增事件协议的非空要求及
   原追加证明的至少一个新增事件要求保持，不把空数组偷渡进旧协议。
5. 原子建立新的明确维护接续关系，保留原失败、隔离、原文、人工事件、税务、知识时刻、
   模型起点和检查点。新规则默认关闭，只有另行明确选择才启用；不原地擦掉旧隔离。
6. Python 与独立 Web 从原件和回答重新核对该关系，不只相信缓存摘要或哈希。
   后续监测仍须重新核验当前价格、行动覆盖、汇率、费用及连续模型；恢复收据不是
   当前估值、金融事实或交易权限，也不能复用陈旧结果冒充“继续观察”。

## 兼容与验收

- 新旧协议明确分开；旧严格客户端和既有已保存记录继续按原协议读取，不静默放宽。
- 默认 core 持久任务、所有者/会话绑定、原 nonce、版本、短期见证、来源最终围栏、
  停止/恢复锁和原子回滚沿用。结果不明只查原意图，不自动重新确认。
- 正例必须从真实存储的失败发布出发：下一合格新日期的无变化资料 -> 普通明确确认 ->
  新接续 -> 当前数据独立准入 -> 同一模型继续观察。不是直接插入“已恢复”行。
- 新事件、历史更正、旧差异变化、窗口缺口、撤权、清理、到期、跨所有者、重复/变化
  请求和晚期并发变化均拒绝；不得重置采集次数或产生金融写入。
- 另验收认证 HTTP、桌面/手机、键盘、重载、过期隐藏及零外部 AI/提供方调用。
  这组验收不能被现有新增事件流程、单元绿灯或生产健康接口替代。

实现及端到端验收完成前，现有隔离保持有效，不宣称采集失败已经可以自动或人工恢复。
