# 账户级清单复核入口

## 目标与边界

普通账户页可复核本人的既有账户级清单，不必手写治理 JSON。该入口不生成目标比例、不批准账户政策或策略准入，也不把研究权重、“采纳思路”或计划投入转成交易指令。

已有月度生成器仍只接收明确批准的 `manual_weight_targets_v1` 目标和完整账户证据，经原风险引擎生成未批准清单。新入口复用该真实服务链路，不另建简化计算器。

这是 P2 的复核增量，不表示完整 P0/P1/P2、真实参考组合、收益目标或生产发布已经完成。

## 用户流程

1. 在账户资料页按需点击“核对账户级待审清单”。GET 只读，不保存风控、批准、预占、成交或订单。
2. 明确选择整张清单；不默认选第一张。范围覆盖关联账本的全部相关账户，不仅是页面上方当前回录账户。
3. 核对原数量、原限价、费用、当前风控、历史批准及剩余预占。原限价不是实时价格，历史通过不是当前授权。
4. 明确选择一步，确认其影响后提交：
   - 记录风控：保存本次核对结果，不批准或预占。
   - 批准：重验当前输入与原风控，通过后记录人工批准和预占，不计成交。
   - 执行前复核：再核对原批准、账本、行情、权限及原完整剩余预占，不发送订单。
   - 终止或登记到期：只释放工作台剩余预占，不向券商撤单，不撤销已发生事实。
5. 如自行在券商交易，仍须通过独立事实回录和[人工执行跟进](52-manual-execution-followup.md)核对。券商状态回报、批准和预占均不替代成交事实。

## 核验与一致性

- 只展示当前登录人有创建审计的关联账本。既有清单、创建命令、原收据、摘要、明细顺序、风控、批准和预占分别核对；不信任孤立的 PASS 标记。
- 非终态清单和到期后仍有预占的清单都须可复核；超过完整核对上限明确受阻，不截断后声称全部可用。
- 命令同时绑定研究版本、账本版本、关联版本及当前证据摘要。调用方不能注入原治理命令、运行版本、时钟、风险阈值或订单数量。
- 部分核销后的原清单不能再次准备其完整旧数量。后续行动须基于真实新状态和新的有效清单；入口不补造差额订单。
- 风控、批准、预占与投资者收据在原事务内完成，晚期审计失败全部回滚。复用原不可变请求恢复，回执丢失不换键重复批准或释放。
- 恢复屏障也阻止已成功原请求的回放。读取可以保留核查能力，但不提供写操作。
- 草稿与账户、现金、成交、执行跟进、CSV、对账、估值及顶部状态刷新互锁，不锁死自身。旧请求、旧回调、注销和范围切换不能跨作用域提交。
- 界面期限只作保守提示；时钟回拨不恢复旧操作，提交始终由服务端重新核验。所有 API 保持认证、强制会话绑定、同源、封闭 JSON 和私有 no-store 边界。
- 核对时全部通过的逐项说明默认收进原生可展开依据，保留时间、批准与预占摘要；阻断原因仍直接展示。折叠不改变服务端准入和提交复核。

## 本地验证与未验收项

- 合成服务测试覆盖只读零写入、明确复核/批准/执行前检查/释放、回执重试、旧行情、到期、部分剩余、晚期失败回滚和恢复屏障。
- 真实 Python 月度发现/领取与 Node 发布器产出的合成清单，接通上述普通用户服务链路；每一步的原金融事实保持不变。这不是实际策略准入证明。
- 组件与 API 测试覆盖空选择、确认重置、旧回调、期限回拨、跨范围、同源/会话、错误脱敏及互锁。
- 实际 Next 生产构建的桌面/390px 浏览器已验证到期清单、禁止旧批准/准备、终止、已提交回执丢失后的原件重试、恢复屏障与注销。
- 在 Next.js 15.5.28 的新临时库中，桌面与 390px 手机各自完成有效期内的明确风控、批准及执行前复核。批准回执丢失后重试原请求只预占一次；其他清单的剩余预占变化后，旧输入不能继续准备执行。最后显式释放两张清单，原金融事实不变，恢复屏障仍拒绝已成功原件重试。键盘可展开通过依据，截图已查看，无页面错误、外部请求或手机横向溢出。
- 新增 `--with-proposal-records` 仅在新建空的临时浏览器库生成当前时点的虚构资料；拒绝已有库、非 fixture 路径和 worker 并用。治理/工程/策略通过记录全部明确为合成测试，绝非真实 G/S 认证。生成器同步平移虚构事实、审阅、行情、估值与期限，并以行情当地日期绑定价格交易日；不修改进程/浏览器时钟，不向生产入口增加时钟或风控开关。旧固定时点 fixture 保留默认语义。
- 无真实券商、供应商或外部 AI 调用，无真实账本写入；没有修改经济策略、风险、取消/交收规则或旧研究。当前精确提交的全 CI、实际策略与账户准入、性能及生产发布仍须分别验收。原生合成正向流程通过不表示真实个人投资主路径已完成。
