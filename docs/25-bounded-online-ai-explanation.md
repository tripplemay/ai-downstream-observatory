## 1. 与产品主流程的关系

[v2 设计](09-product-v2-portfolio-first.md#4-能力设计与复用边界)要求策略和确定性核验先产生结果，AI 只解释证据、提出反证及不确定性。当前新增 `worker/research/ai_gateway.py`，先隔离并验证线上传输；没有把旧主题分析器直接接到组合页，没有把旧网关配置视为真实行情外发授权。

默认探针 CLI 仍只发送源码内固定的虚构模型偏离/换手证据，不能通过填 `synthetic` 标签发送另一份真实或个人资料。另一个内部服务模式只接收新的封闭派生指标合同；其可信 Web 调用者先核验数据库、当前来源、私有共享许可和网关受众。HTTP 请求只接收观察 ID 和绑定摘要，不接收上下文、资金、网关地址或密钥。原 `request_review()` 和 investor core 尚未接入；旧总体 `ai_status=not_configured` 字段不作为这个独立按需入口的状态，界面读取独立 API 的当前状态。

```sh
python -m worker.research.ai_gateway --config-file /absolute/private/ai-gateway.json
python -m unittest tests.research.test_ai_gateway -v
```

配置结构见 [`config/ai-gateway.example.json`](../config/ai-gateway.example.json)。必须显式给出绝对路径；文件为同运行用户所有的 0600 单链接普通文件，不接受叶子 symlink、环境凭据或自动读取旧配置。域名、密钥和模型在私有配置中设置，公开示例不选择个人供应商或包含可用密钥。VPS 尚未安装该配置或启用该功能。

旧 v1 配置仍不携带思考模式参数，不自动改变模型默认行为。新增[显式非思考示例](../config/ai-gateway.deepseek.example.json)使用 `readonly-ai-gateway-config-v2` 与 `request_profile=deepseek_non_thinking`；只向识别的 DeepSeek 模型发送固定 `thinking.type=disabled`，不接受任意 `extra_body`、工具或供应商参数。示例中的公开模型别名不是个人模型选择或可用性保证。

## 2. 调用与证据边界

- 固定 HTTPS Chat Completions POST、单次请求、非流式、一个返回，不发现系统代理、Cookie 或任意工具。重定向拒绝，不重发携带 Bearer 的请求。
- 隔离子进程使用临时 HOME、最小环境和 30 秒内核/父进程时限；HTTP 超时 25 秒。输入限 32 KiB、响应限 256 KiB、模型正文限 128 KiB，不写原始响应日志。
- 请求声明 JSON 对象及 `store=false`，输出 token 参数只允许 512 至 2048；本轮请求 1024。这是客户端请求限制，不是已经核验供应商收费、保留策略或实际 token 上限的证明。
- HTTP 状态、JSON/重复键、返回数量、角色、完成状态、工具/拒绝、正文、模型标签及 token 计数逐层检查。只接收 `finish_reason=stop`；错误输出只能是固定白名单，不能靠异常前缀放行私有文本。
- 成功正文必须通过既有 [`ai-research-review` 合同](../contracts/v1/ai-research-review.schema.json)，事实的指标、数值字符串、日期和引用逐项匹配；不接受数值等价但字面改写、重复事实或未知引用。固定探针还要求覆盖两条输入事实。
- 自由解释仍是不可信文本，引用合法不证明其推理真实。成功只取得解释格式资格，不修改确定性状态、风险预算、目标、真实账本、策略批准或订单。

完成状态的标准含义参考 [OpenAI Chat API 文档](https://developers.openai.com/api/reference/resources/chat)：正常完成、长度限制、过滤或工具调用是不同情况。该文档用于协议参考，不证明本项目私有兼容网关完全实现该协议。

## 5. 当前观察的按需解释纵切

- 本地先经现有独立 Node 重放核验参考研究、监测结果和完整前序检查点；仅接受当前有效且已启用的收据资格模型观察。不完整、暂停、过期、偏好/来源改版或旧无资格观察不能调用 AI。
- 所有依赖窗口（原研究、当前监测及前序检查点）的原始权利审阅都须含 `external_ai`，并仍是最新、有效、已审计的版本。另行绑定私有用户共享许可和网关受众；许可不是提供方授权。旧快照的 `external_ai_authorized=false` 不改写；新增派生用途核验不提升整份快照或策略资格。
- 出站合同 [`ai-monitor-context`](../contracts/v1/ai-monitor-context.schema.json) 仅含两到三个比例/计数、固定触发代码、评估时点、既有确定性结论和固定限制。最大证券目标偏离不等于资产类别策略阈值；模型估算成本缺失时省略比例，不补零。比例单独舍入到 18 位，不修改金融计算。
- 不外发资金金额、风险答案、真实持仓、账户、证券代码、原始价格、来源原文、个人自由文本、内部对象 ID 或密钥。输出须完整逐字引用全部指标，并经过 Python 和 Node 的窄合同核验；自由推断仍标明未经人工验证，以 React 文本而非 HTML 渲染，不提供执行工具。

## 6. 持久的按需外发登记

迁移 `0038_investor_ai_requests.sql` 只追加 AI 请求、外发登记、结果头、限期文本载荷和清理记录；不回填任务、升级来源或写金融事实。此前 37 项迁移不改写。请求只存本地对象/版本摘要及期限，不存资金、风险答案、账户、原始行情、密钥或完整出站上下文。文本仍可能有未经验证的推断，只允许私人查看。

- `POST` 仍需当前会话、同源、明确绑定与完整本地证据重放。请求和唯一随机外发令牌在同一写事务中提交，再调用网关；没有“先调用再登记”的可重复窗口。
- `(workspace_id,binding_hash)` 为持久唯一键。同一 SQLite 数据库中的并发进程、页面刷新及冷进程读取复用已登记状态，不依赖内存缓存。当前 binding 包含科学来源、上下文、配置、许可、实现与期限；新 binding 仍须用户显式点击，不能据此自动循环计费。
- 外发登记不更新、不删除、不重试。进程在登记后崩溃，不能确定是否已经外发或计费；45 秒登记期限后显示 `INVESTOR_AI_OUTCOME_UNKNOWN`，再次点击也不重新调用。这是保守的本地 at-most-once 调用登记，不是提供方 exactly-once、费用核销或保证成功返回。
- 同库写事务和 SQL trigger 限制每工作区一个、全局两个有效外发登记，文本载荷最多 64 个。实际传输仍受既有 Python 内核 30 秒及 Node 35 秒界限约束；取消中的本机调用在实际结束前继续占本机名额。时钟、进程阻塞、共享文件系统和负载 SLA 尚未认证。
- 成功发布前重新检查会话、许可、当前来源和版本；随机令牌及不可变审计绑定结果，过期、旧令牌、已清理或迟到结果不能发布为成功。读取重新核验来源、全部绑定、审计、完整字面事实和结果哈希，数据库中的摘要不自证研究资格。

## 7. 显式请求的独立后台生命周期

当前 HTTP `POST` 只在会话/同源/请求绑定和完整来源核验后登记本地意图，不等待网关传输；排队或运行状态返回 HTTP 202。`GET` 与界面轮询只读取状态，不创建意图、不调用网关。每个新观察/绑定仍需用户明确点击，不会因监测更新或后台重启自动产生新付费请求。

状态区分如下：

| 状态 | 持久含义 | 重启后的行为 |
| --- | --- | --- |
| `queued` | 有明确请求头，尚无外发令牌 | 固定后台重新核对当前来源、许可与实现后，才可竞争外发登记 |
| `running` | 已有不可变外发令牌，可能已经发送/计费 | 只读取，不重复传输；期限后无终态则显示结果未知 |
| `complete` | 同令牌的结果通过逐字事实、当前绑定和期限校验 | 可读取当前有效文本，不重新生成 |
| `failed` | 失败、结果未知或文本已清理 | 保留去重记录，不自动重试 |

- HTTP 连接中断、关闭页面或退出登录**不撤销已经提交的意图**；这是经过认证登记的后台工作，不依赖 Cookie 长期保存。暂停观察、撤回许可、来源失效、实现/配置变更或到期会阻止排队意图发送并将其清理。已经登记外发的请求不能推断尚未发送，也无法撤回外部服务已有数据。
- 复用迁移 38 的不可变请求头，迁移 `0039_investor_ai_queue_guards.sql` 只增加未外发意图的 64 项全局上限、已清理意图禁止外发的 SQL guard 与扫描索引；不回填意图，不改写此前 38 项迁移。领取前只是本地核验，没有外部副作用；同一即时写事务生成唯一外发令牌，两个进程只有获令牌者可调用。无需可重试的网络租约；令牌提交后的任何不确定性均不得重发。
- `web/scripts/run-ai-explanation.mjs` 只启动固定构建的 worker，不能通过 DB 或 CLI 选择程序、对象主体或上下文。生产认证目前只有 `owner`，后台主体固定为该值，不宣称多租户支持。启动与每轮先执行独立清理，默认 15 秒间隔；清理不依赖浏览器访问，也不产生网络请求。恢复锁拒绝清理、外发和发布。
- 构建 manifest 固定 bundle 和所有服务器/合同/迁移/相关 Python 来源的摘要；启动/每轮检查，外发前和结果发布前再检查。镜像来源为只读、非 root；摘要是本地构建一致性证明，不是来源许可、供应商签名或投资准入。
- `WORKBENCH_AI_ENABLE_DISPATCH=0` 默认只清理。只有显式设为 `1` 才处理已登记意图；Web 同步使用 `WORKBENCH_AI_BACKGROUND_ENABLED=1` 才提供提交入口。此标志是运营部署声明，不是活跃 worker 心跳证明；正常 HTTP 202、后台健康或 Compose 模型通过都不能代替端到端验收。
- `Dockerfile.ai-explanation` 为 Node 22 + Python 3.11 独立运行镜像；不安装长桥 SDK、不挂载券商凭据、不提供交易工具或外部端口。`docker-compose.ai-explanation.yml` 为显式叠加文件；AI 服务不读取认证密码、会话 Secret 或旧 runtime.env。Web 为本地绑定核验仍需只读挂载同一私有网关/许可文件，因此不是网关凭据对 Web 的完全隔离；只有后台携带传输运行环境。宿主私有文件须 0600、uid 10001、单链接普通文件，不能使用公开例子作为有效许可。
