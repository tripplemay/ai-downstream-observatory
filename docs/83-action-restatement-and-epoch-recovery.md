# 历史更正、经济重算与长期观察接续

状态：独立经济重算内核研发中；未接来源审阅、批准、新检查点、普通页面或生产恢复。
本文补齐 v2 的长期恢复路径，不缩减 P0/P1/P2，也不以重新起点取代应完成的历史更正。

## 问题与结果口径

既有监测可以发现已处理分红、拆分或获知时刻发生变化，但不能静默覆盖原记录。
普通新增事件审阅和无新增事件维护都不批准历史更正。兼容协议只沿用旧账，不是重述。

需要分别保留三个结果：

1. **当时实际记录的观察**：原输入、原知识、原检查点和原人工决定，不改写。
2. **以本次更正知识重算的历史经济状态**：在同一个原估值点、相同原价格与汇率下，
   比较份额、现金、应收和估值差额。它不是当时可知的策略结果，也不是当前净值。
3. **确认后接续的当前观察**：必须有独立来源核验、明确确认和合格当前数据，不能由
   第二项的算术结果直接恢复。

历史策略判断不进行事后美化。经济重算不模拟过去重新交易，不把获知时间移到事件之前，
不把更正后历史拼成原策略的样本外业绩。金额均属于以原标准化本金开始的研究模型，
不是实际持仓、到账或账户税务事实。

## 已实现的内核边界

`worker/investor/action_restatement_kernel.py` 与独立 Node 内核使用封闭的新合同。
输入包括原定义、首个及末端检查点、它们各自的原投影、完整原行动账、更正后行动账、
完整覆盖声明和本次检查时刻。没有来源 URL、凭据、数据库写入或交易接口。

- 先重算原首个标准化份额及剩余现金，再从原起点重放完整原行动账，逐字段核对末端的
  份额、现金、应收、权益和已处理哈希。格式或自洽摘要不能代替这项算术比较。
- 更正账采用本次真实获知时刻，但只重算原末端行情截止前的经济事件。按时点、拆分、
  除息、支付的稳定次序处理；应收金额使用除息时的份额，不使用后来拆分后的当前份额。
  起点收盘前的事件不产生持有权益，支付不能重复，取消旧事件通过完整重放计算差额。
- 两边固定使用原末端的同一组未复权报价与汇率。原件当时有效与当前仍有许可是两项
  不同检查；本内核只核对前者的算术/时点关系，不能批准当前读取或发布。
- 原固定规则和资金绑定属于原件绑定的一部分，但计划本金不入现金。重算不重置或
  执行策略状态，不重算原历史决策。原方案、检查点与所有输入对象均不修改。
- 完整行动账沿用状态协议的 20,000 项上限，不误用单个投影窗口的 500 项限制。
  这不提高既有检查点、保管期限或生产任务预算，也不证明上限性能。

结果明确为 `source_evidence_verified=false`、`checkpoint_created=false`、
`state_published=false`、`monitoring_resumed=false`，且不认证当前建议或交易。
它没有普通检查点的版本或序列，不能作为监测输入提交。Python 与 Node 的算术验证入口
均从输入重新计算，再逐字段比较结果；合法形状不等于数值正确，更不等于来源证明。

## 必须继续接通的完整路径

| 阶段 | 需要完成的事实与证据 | 不可替代的边界 |
| --- | --- | --- |
| 原件与来源准备 | 从完整原链及保留字节核验所有者、许可、日历、价格/FX 和行动原文；明确更正范围及不可重放缺口 | 算术输入不能自行声明来源已验证；撤回或缺失仍停止 |
| 更正事实审阅 | 普通页面展示旧/新来源差异，明确毛额、税额、时点、取消或拆分更正及实际获知时间 | 不推断未知税额为零，不把新增事件的授权借给历史更正 |
| 同口径影响预览 | 接入本内核并独立复算，展示原记录、更正后状态、差额和不确定性 | 不显示为当前 NAV，不美化当时策略业绩，不自动批准 |
| 原子确认与新协议 | 短期见证、版本/来源最终围栏、独立只追加收据和明确的接续状态/epoch，保留原记录 | 不覆盖旧输入、删检查点、回填收益、暗中重建本金或自动开监测 |
| 当前恢复与长期运行 | 新来源和新状态独立重放，普通 HTTP/原生流程、下一有效收盘、三态监测、长期轮转及受保护发布 | 工程绿灯不能替代真实来源、性能、恢复或投资资格 |

有依据的更正与没有足够原件的中断应走不同结果。只有原件无法支持原起点时，才能另行
提出明确的新观察起点；必须显示期间中断，不把新起点当作已修复的原收益。达到检查点
上限或期限轮转也需要透明的接续协议，不能扩大上限或绕开保管约束制造十年可用声明。

当前只完成这条完整路径的经济重算基础。来源准备、事实审阅、不可变确认、接续状态、
普通界面、真实资料和生产恢复仍未实现/验收；现有历史更正阻断继续有效。
