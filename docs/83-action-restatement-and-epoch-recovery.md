# 历史更正、经济重算与长期观察接续

状态：独立经济重算、原件重放、普通假设比较及明确更正同意/冻结基线已具备研发实现；普通更正确认已取得合成实际时钟验收。更正资料准备及明确来源接续已接通双引擎和默认 core；普通接续交互、新状态/检查点和生产恢复尚未完成。
本文补齐 v2 的长期恢复路径，不缩减 P0/P1/P2，也不以重新起点取代应完成的历史更正。

## 问题与结果口径

既有监测可以发现已处理分红、拆分或获知时刻发生变化，但不能静默覆盖原记录。
普通新增事件审阅和无新增事件维护都不批准历史更正。兼容协议只沿用旧账，不是重述。

需要分别保留三个结果：

1. **当时实际记录的观察**：原输入、原知识、原检查点和原人工决定，不改写。
2. **以本次更正知识重算的历史经济状态**：在同一个原估值点、相同原价格与汇率下，
   比较份额、现金、应收和估值差额。它不是当时可知的策略结果，也不是当前净值。
3. **确认后接续的当前观察**：必须有独立来源核验、明确确认和合格当前数据，不能由
   第二项的算术结果直接恢复。

历史策略判断不进行事后美化。经济重算不模拟过去重新交易，不把获知时间移到事件之前，
不把更正后历史拼成原策略的样本外业绩。金额均属于以原标准化本金开始的研究模型，
不是实际持仓、到账或账户税务事实。

## 已实现的内核边界

`worker/investor/action_restatement_kernel.py` 与独立 Node 内核使用封闭的新合同。
输入包括原定义、首个及末端检查点、它们各自的原投影、完整原行动账、更正后行动账、
完整覆盖声明和本次检查时刻。没有来源 URL、凭据、数据库写入或交易接口。

- 先重算原首个标准化份额及剩余现金，再从原起点重放完整原行动账，逐字段核对末端的
  份额、现金、应收、权益和已处理哈希。格式或自洽摘要不能代替这项算术比较。
- 更正账采用本次真实获知时刻，但只重算原末端行情截止前的经济事件。按时点、拆分、
  除息、支付的稳定次序处理；应收金额使用除息时的份额，不使用后来拆分后的当前份额。
  起点收盘前的事件不产生持有权益，支付不能重复，取消旧事件通过完整重放计算差额。
- 两边固定使用原末端的同一组未复权报价与汇率。原件当时有效与当前仍有许可是两项
  不同检查；本内核只核对前者的算术/时点关系，不能批准当前读取或发布。
- 原固定规则和资金绑定属于原件绑定的一部分，但计划本金不入现金。重算不重置或
  执行策略状态，不重算原历史决策。原方案、检查点与所有输入对象均不修改。
- 完整行动账沿用状态协议的 20,000 项上限，不误用单个投影窗口的 500 项限制。
  这不提高既有检查点、保管期限或生产任务预算，也不证明上限性能。

结果明确为 `source_evidence_verified=false`、`checkpoint_created=false`、
`state_published=false`、`monitoring_resumed=false`，且不认证当前建议或交易。
它没有普通检查点的版本或序列，不能作为监测输入提交。Python 与 Node 的算术验证入口
均从输入重新计算，再逐字段比较结果；合法形状不等于数值正确，更不等于来源证明。

## 行动原件的独立只读核验

`worker/investor/retained_action_evidence.py` 与独立 Node
`readRetainedActionEvidence` 区分“原件仍可合法读取”与“来源当前可用于监测”。
它们不修改原有解析器的当前性判断，也不把历史更正包装成无变化续接。

- 普通旧审阅逐一核对原来源、审计、事实及其后有界版本链。允许后续已批准版本的经济
  内容不同，但工具只返回原事实；原件和最新版本均须未过期，身份不变，撤回/拒绝、
  缺版本或未来记录停止。仅有人工审阅记录时明确标为 `owner_review_record_only`，
  不声称存在发行人原文证明。
- 旧维护发布独立重放锚点和发布时的两源原始字节、回执、身份、当前供应商许可与
  原维护规则，重算原无变化结果和发布哈希，而非只核对摘要。旧维护被暂停或隔离
  不等于原件存储许可被撤回；供应商撤权、原文清理、缺失或到期仍停止。
- 新封闭证明只包含绑定及边界，不含原始金额、税务文本或行情。原事实通过专用
  `original_*` 字段返回给私有比较调用者，不返回普通 `VerifiedSourceReview`/`review`
  对象，不建立可供正常准入解析器使用的历史作用域，也没有路由、任务或自动发现器。
- 原观察与原始字节不变；不把后来获知时刻回填为原时刻，不批准新税额、来源更正、
  检查点或交易。结果始终 `current_source_eligibility_restored=false`、
  `economic_correction_approved=false`、`monitoring_resumed=false`，提供方调用/数据库
  写入均为零；全部内容仅限本人私有研究，不发给外部 AI。

该层只证明所选行动原件，不证明完整原检查点链、价格、汇率、日历、旧协议确认和
资金/费用绑定已经全部核验，不能据此将算术结果的 `source_evidence_verified` 改为真。
合成集成覆盖实际保存的 v3 输入、显式 v5 接续与原检查点：更正后仍能比较原行动来源，
独立算术结果不变，而当前来源依然被阻断。它不是实际行情或投资有效性验收。

## 完整已保存监测链的原件准备

`retained_monitor_history.py` 与独立 Node `readRetainedMonitorHistory` 从所有者和当前
已选模型开始，重新读取每条输入、原价格/回调字节、许可、身份、日历、汇率和行动，
重建原快照、数据集及投影，再从第一条检查点逐条重算原状态，而非信任已存份额或摘要。

- 输入 v1-v5 分别保持原协议；固定策略与真实保存的资金计划绑定按原时点评估，计划
  本金不进入现金。全行动账、父哈希、原份额、现金、应收、策略状态和资金/费用绑定
  必须与原载荷精确一致。保留既有 1,000 检查点、行动数量与字节限制，不承诺上限性能。
- 已确认的新事件谱系重新核对原人工答案、前后供应商原文、维护控制和时点，继承的
  获知时间仅来自经核验的原确认。v5 额外核验原兼容预览、原链前缀、明确确认、首次
  原子准入和保守知识桥；不能仅凭一份形状正确或重新封哈希的收据恢复旧投影。
- 所有来源读取和撤权/清理判断使用**本次时钟**；原时钟仅用于重建原计算、费用和
  已记录选择。新人工版本较短的可读期限单独限制本次证明，不改写原输入有效期。
  行动的当地日期使用原快照绑定的、当前仍有效的上市资料；不把纽约日期套给 A/H 股。
- 返回专用原历史包及封闭的无金额证明，始终标明 `original_history_replayed_not_recovered`。
  该证明只核验已记录历史，不核验提出的新更正，也不直接改变经济内核的来源资格、
  写新状态、恢复监测、运行外部 AI 或授权交易。没有普通页面、任务或准入入口调用它。
- 当前入口要求原模型仍为当前已选模型，且原偏好和参考方案来源仍有效。参考方案本身
  已失效、源许可撤回、原文/检查点清理、保管到期或原始链缺失仍停止；不能把这类
  情况伪装为已修复，也不通过新起点覆盖中断。参考方案上游更正与长期轮转仍需独立恢复。

快照组装与原估值计算只提取为内部共用计算步骤；普通解析器继续先执行原有当前性、
接续和许可检查，没有“信任调用者已准备”开关或全局历史例外。合成跨语言场景覆盖
三市场当地日期、原 v1/v2/v4、真实保存的资金绑定和实际旧 v2/v3 到 v5 链，以及原来源
更正后仍保留原历史但不恢复当前投影。此为软件证据，不是实际提供方或投资资格认证。

## 来源绑定的假设影响比较

`action_correction_impact.py` 与独立 Node `compareActionCorrectionImpact` 将已登记的
当前资料差异预览、逐日明确假设、完整保留监测链和经济内核接在一起。调用者只提供
当前模型、预览和版本、逐日选择及必要假设，不能提供原行情、旧状态或自报的发行人毛额。
当前入口仅接现有 VT/BND 的美股发行人/EODHD 流程，不宣称已完成三市场的通用更正。

- 每个历史变化日期必须明确选择保留、替换或取消并说明原因。替换的分红毛额只汇总
  当前保留的发行人原文；税额、当地日期内的有效时刻、与发行人日期一致的支付时刻
  均须明确填写。拆分比例只来自当前 EODHD 原件，须显式接受分子/分母作为新旧份额
  方向的**研究假设**，不是发行人已确认的经济方向。保留旧值不会消除来源差异。
- 取消必须在本次两源共同覆盖内，且两源均未报告该日行动，再加明确取消假设；空清单
  本身不作为客观不存在事件的证明。滚动窗口之外的缺失、未知组件、重复组件、币种
  异常、遗漏/重复回答和不明确税额均停止，不自动填零或沿用普通追加的“不重述”确认。
- 完整原链仍从保留字节重放；被替换日期的原经济事件必须与原审阅事实逐项一致。
  其他日期、其他标的和原获知时间不变，新假设的知识从本次比较时刻开始。只比较
  原末端价格/FX 下的份额、币种现金、应收和估值差额，新增报告日期明确列为未处理，
  不顺便扩大覆盖、不用当前行情或事后重算当时策略决策。
- 所有者、当前模型、预览期限、工作区版本、规则叶节点、控制、日历、许可、原文和
  历史链仍须通过当前检查。结果只读、无提供方调用、不创建批准/检查点/金融事实，
  不开启维护或监测，也不清除隔离。`source_evidence_verified=false` 表示仍未批准
  更正事实及新覆盖，不把“比较所用原件已核对”偷换成“来源更正已获准”。
- 结果使用独立封闭协议，包含假设事件和绑定，不返回可直接用于准入的已批准事实
  对象。内容仅限本人私有研究，不发送给外部 AI。对完整历史的重放是较重计算，只在
  下述异步审阅任务执行，不接入普通 GET；比较本身不批准更正，独立同意后端见下节，普通确认及当前接续入口仍待接通。

此核心已用虚构的真实存储/任务生命周期进行双引擎比较。它不是新的普通页面或生产
恢复，也不从旧的“无变化续接”授权推断历史更正批准。仍需独立不可变确认及新的
状态/epoch，不能直接把假设比较写为检查点。

## 普通异步影响比较流程（研发实现，未发布）

- 迁移 60 新增所有者显式意图与不可变结果，既有迁移 1-59 字节不变。普通历史差异
  页面传入当前观察模型，逐日选择保留、替换或取消，说明理由并明确税额/时刻。
  默认选择、金额假设及确认均为空；修改输入清除确认，缺少模型不另建起点。
- `correction-impact` 私有路由严格检查登录、来源、会话绑定、封闭 JSON、字节上限、
  工作区和预览版本。POST 仅登记原 nonce 的意图；GET 只查原请求、原 nonce 或同一
  来源预览下的记录，不入队、不调用行情或 AI。会话切换前后的私有结果均被阻断。
- 默认 core 发现并执行单次任务，完整原件/经济计算在写事务外。短写事务重新核对
  租约、原请求、期限、工作区版本、实现标识和保守元数据变更围栏，再登记成功或固定
  拒绝码。没有新审阅、维护开关、检查点、金融事实或工作区 revision 的隐式推进。
  请求最长排队有效期 5 分钟，结果不超过原来源预览及许可期限；刷新不延长原期限。
- GET 展示的是**上次完成的假设结果**，不是重新核验后的当前来源或当前净值。
  它检查不可变请求/结果、审计和任务尝试，并用限定本工作区的标量头信息与原文保留
  存在性检查变化；撤权、清理、新模型/头/版本或到期隐藏旧差额。该围栏不是来源证明，
  不读取原始价格字节、不重新重放完整历史，也不使缓存结果获得准入或批准资格。
  元数据总量与字节有独立上限，不声称最大历史规模的延迟/SLA 已验收。
- 普通表单显示原价/FX 下的份额、币种现金和应收差额及估值差额，明确归一化模型的
  初始 10,000 CNY 不是个人真实资金，不冒充当前持仓、当前行情或当时策略业绩。
  编辑中的未提交假设不沿用上次差额；提交结果不明时保留原请求，只能先查原 nonce
  或明确重发原字节。自动轮询只用 GET，不被每秒显示时钟反复推迟，不自动补发 POST。
- 历史假设正在编辑、比较排队或受理状态不明时，父级预览刷新暂停，已经在途的父级
  读取取消并作废，不能稍后替换子表单。旧的准备、刷新或清除事件回调也须读取当前
  保护状态，不能仅依赖按钮禁用。用户可在子表单核对原比较状态；清除本地假设后才
  恢复父级预览轮询。站内链接离开及页面卸载均提示未确认输入，会话失效清除保护；
  离开不撤销已受理的后台任务。这不是跨页面草稿持久化或浏览器历史导航保留保证。

这关闭了普通异步比较的实现连接，不等于正式历史更正已完成。新流程的实际时钟普通
HTTP/原生完整成功路径见下方专节；新 epoch、真实资料恢复和生产发布仍分别验收；
既有普通追加和兼容流程的原生证据不能替代新更正流程。任何后续批准必须重新核验完整
原件、假设和经济结果，不能仅凭上述缓存、形状合法或自洽摘要写入新状态。

## 明确更正同意与冻结基线后端（研发实现，未发布）

- 新封闭 `investor-correction-consent` 协议与迁移 63 将最终更正同意和假设比较分开。
  请求只引用确切的已完成比较及结果哈希、原工作区版本、独立不可变 nonce 和七项明确确认；
  不接受调用方报价、经济状态、税额补丁、维护开关或交易字段，不推断原假设同意就是
  更正批准。暂按原记录比较仍有效，但保留未解决来源差异的选择不能登记正式基线。
- 默认 core 单次作业重新核对当前两源原文、身份/许可、控制、完整原链和原人工假设。
  当前来源核验后，仅用纯算术的旧比较时点重现完整旧比较及哈希，核对原先究竟展示了
  什么；不把旧时钟用于绕过当前撤权、保管或原文检查。自洽重封的假缓存不能获准。
- 短事务再次检查租约、当前版本、源码实现、请求期限、来源日和元数据围栏，原子登记
  同意、冻结基线、工作区 revision、任务结果及审计。故障发生在基线插入之后也整体
  回滚；旧任务维持单次终态，不重置采集尝试，不自动以新 nonce 再确认。
- 新经济事件从本次明确意图之后的实际作业核验时刻获知，不倒填到旧比较或事件日。
  准备和落盘时刻允许不同，比较时间使用解析后的 UTC instant，不用不同小数精度的
  时间字符串作大小比较。原初始本金/时点、原价格/FX、历史策略状态和原记录均保留。
- 冻结基线只保存一份更正后经济状态、必要的新事实及原件引用；完整行动账和比较保留
  哈希与有界差额摘要，不重复保存大状态。它是独立业务基线，不是数据库备份或恢复
  副本；业务备份策略没有改变。批准回答与基线在独立表中，未写入普通来源审阅表、
  模型输入、控制或检查点，也未选择/开启新的维护规则。
- Python/Node 的历史收据 DTO 只有登记元数据，不包含金额、份额、税务文本或事件。
  即使期限已到或供应商撤权，仍可核对旧登记而不泄露未重新合格的经济载荷。独立
  Node 的较重基线读取从保留字节、人工答案及完整原链重算原比较和新经济状态；篡改
  原文或自洽重封错误份额仍被拒绝。该重放不进入普通 HTTP GET，不返回普通监测输入。
- 提交期限与源资料可读上限分开：确认必须在短期意图/预览内完成，但冻结记录不伪装
  成只有五分钟的来源许可，也不延长原源资料上限。之后每次使用仍须重新检查全部
  当前许可和数据；登记收据明确 `historical_registration_only=true`、
  `monitoring_resumed=false`、`checkpoint_created=false`。
