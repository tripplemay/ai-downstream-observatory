# 证券身份与交易规格的人审版本

## 用途和权限

`/workbench/market/listings` 为本组合保留证券身份、挂牌状态、交易单位和风险分类的
有来源人工审核。先登记证券并加入本组合目录，再保存私有结构化来源原件，最后
明确审核内容、有效期和理由。原件保存不等于审核，审核不等于账户可买或策略获批。

审核依据固定标为 `human_reviewed_not_provider_verified`。它证明本系统收到的原件、
人工陈述、版本和审计记录一致，不证明原件出自发行人，也不认证发行人/交易所的事实。
个人原件和审核记录只进入私有数据库，不随公开源码、镜像或 CI 工件发布。

## 显式填写

- 产品种类：ETF、ETN、股票、其他基金、其他或未知。
- 挂牌状态：正常、暂停、退市或未知。正常挂牌不等于已经取得交易许可。
- 产品结构：杠杆属性和方向分别填写；未知、杠杆或反向产品不能通过首版产品范围检查。
- 最小数量单位和报价单位：正的精确十进制，或者明确未知；禁止用零、指数记法或
  浮点舍入代替资料。资料缺失可以保存为新版本，但不能继续沿用旧版本的交易许可。
- 基金/份额标识、来源自述日期：可留空，不根据名称或代码自动合并等价产品。
  来源日期不能晚于审核时点在该挂牌市场的当地日期，也不能代替实际收到资料的时间。
- 指数、地区和行业分类：人工逐项确认，不能从研究目录自动复制。它们是整只基金的
  分类标签，不是成分股权重、完整穿透或多地区风险分解；E-16 的完整验收仍未完成。
- 明确的审核截止时间、理由和确认，不生成永久有效或默认认可的审核。

## 版本、原件与并发

迁移 0019 新增 `listing_review_versions` 和 `listing_review_heads`。版本由
`portfolio_id + listing_id` 隔离，独立于账本与目录的版本号；不更新全局
`instruments`、`listings` 中的旧核验字段，也不改真实现金、持仓或估值。

命令绑定当前证券身份哈希、预计审核版本、私有原件 ID/UTF-8 哈希、完整事实、
截止时间、理由和幂等键。证券身份在审核事务中再次核对；用户看到的代码、市场或
币种已经改变时拒绝提交，不能静默审核另一个身份。原件来源和审核人不能冒充
`system:` 身份。确认重试只复用同一完整命令的回执，不能改变 CAS 或原件后沿用旧键。

版本绑定服务器实际已知时间、来源已知时间、证券身份快照、内容哈希和精确审计。
SQLite 约束、Web 验真和独立 Python 验真分别检查这些关系；新版本不能覆盖旧原件。
历史读取可以展示当时已知的版本，但当前身份已经改变时只能作为带缺口的历史证据。

## 风控和月度评估

风控只消费当前组合有完整证据且未到期的人审版本，不回退使用全局 `verified_at`，
也不把其他组合的审核当成本组合许可。最新审核为未知、暂停、退市、不支持的产品或
缺少必要分类时阻断；不能挑选更旧的正常版本通过。

证券审核版本和来源哈希进入风险输入指纹。持仓、在途证券、待执行买入预留及新提案
中的相关证券都需要核对；更新审核后，旧风险结果/批准不能不经复核继续执行。
审核到期同样阻断执行，但不会删除已发生事实、自动释放预留或清仓。

月度评估同时核对原周期已知版本和当前版本/有效期。之后才收到的审核不能填回旧周期；
之后发生的审核变更或到期不能被旧周期快照掩盖。没有实际仓位且目标为零，也不能跳过
相关证券所需的审核与账户许可。

v20 在周期创建事务中冻结该组合的证券审核序列水位，prepare、提交和人工重试均复用；
不能仅靠相同 `known_at` 判断同一毫秒内的提交先后。普通时间查询仍取时间范围内的最新
revision，不等于某个已完成月度评估的原快照。旧周期不补猜历史水位，详见
[月度证券审核知识边界](monthly-listing-boundaries.md)。

供应商价格读取按明确 `listing_id` 绑定证券，而不是把 `PRICE:<listing_id>` 当作
裸证券 ID。FX 仍使用独立币种序列。歧义的同时间价格、错误身份和缺失的流动性指标
阻断；日线收盘价不变成可执行报价，SDK 原件里的成交量也不会被静默补成未发布指标。

## 验证与剩余门槛

回归覆盖正常来源到审核、范围/哈希/审计/身份冲突、未知和不支持的产品、版本与到期、
旧批准失效、月度周期的双时点以及真实采集代码到价格读取。用例只使用合成原件、
人工身份和 SDK 响应；不得作为真实发行人或券商认证。

本轮仍不授予账户权限，不生成真实 G/S 准入证据，不自动执行交易。真实来源质量、
账户可买性、完整加权穿透、当前价差/折溢价、连续前向模拟、生产部署及原生浏览器
完整验收仍需独立完成。实际测试数量和提交/CI 绑定见开发进度和验收证据图。
