# 私有研究数据链路

多年范围已增加[有界分片与断点续采](23-bounded-history-collection.md)：基于当前审阅日历生成稳定计划，仅采缺失窗口，每次最多四次串行调用；仍保留全部来源、留存和投资资格门槛。真实早期样本结果另见该文档，不改变本链路尚未完成真实资料留存验收的边界。

## 1. 当前能力与产品边界

本模块把明确提供的私有资料、人工审阅版本、官方 SDK 采集收据与研究历史连接起来。它是后台高级运维入口，不是投资者首次使用的必填流程，也没有改变“简短约束 -> 研究方案 -> 持续观察 -> 人工决定”的主路径。

已实现独立工作区的来源/审阅、最长 31 自然日的日线采集、不可变收据、受限留存载荷、三地日历/企业行动/FX 重建、共享合同及只输出摘要的操作 CLI。新增证据准入、默认后台研究、探索历史参考方案及保存为观察模型的链路；**真实适用资料尚未录入，真实来源纵切和持续真实监测未验收，不代表 P0 完成，也没有部署。**

本轮只用虚构资料与模拟 SDK/子进程测试；没有新增真实行情采集或留存，没有写入真实账户、持仓、现金、批准、预占或执行。

## 2. 来源与人工审阅

迁移 29 在现有独立投资者工作区内追加五张表；25-28 及更早的迁移不改写：

| 表 | 用途 |
| --- | --- |
| `investor_data_sources` | 明确提供的标题、参考位置与资料摘录，不自动抓取任意 URL |
| `investor_data_reviews` | 按来源追加 approved/rejected/withdrawn 版本，绑定所有者审计与有效期 |
| `investor_price_captures` | 收据、来源审阅版本、请求、SDK 投影哈希与留存期限，不含价格载荷 |
| `investor_price_payloads` | 与收据分开的受限 SDK 投影字节 |
| `investor_price_purges` | 所有者审计绑定的逻辑删除记录，不能撤销或重新插入载荷 |

五种事实使用 `investor-data-facts.schema.json`：

- `rights`：账户适用地区、市场、明确用途、有效期、留存期限与条款位置。当前采集要求 private research/retention/display/backup 四项均有记录；没有默认许可，也不由密钥前缀推断地区。
- `listing`：产品身份、币种、交易单位、生命周期、未杠杆/非反向 ETF、角色、基金费率及资料日期、经济暴露。未知费率不能记为零；未来资料日期拒绝。此目录不是历史无幸存者偏差宇宙，不证明真实账户可买。
- `calendar`：覆盖区间内每个自然日必须明确 closed/full/half，分别记录收盘、假设可用时间、交收时间和交收规则已知时点。缺日、混市场日期、倒置时间均拒绝，不假设每个工作日交易。
- `actions`：明确覆盖区间、税务假设与拆分/分红事件；空事件也必须是明确的人工完整性审阅，不能由价格存在推定无分红。
- `fx`：每币种人民币计价的精确十进制序列，观察时点与假设可用时点分开。缺 FX 不补 1，陈旧约束仍由研究计划检查。

这些是 `owner_reviewed_not_provider_certified` 的操作记录。勾选或填写事实不会自动证明摘录支持结论，也不是发行人、交易所或数据商认证。资料哈希只证明版本绑定。

2026-10-07 复读官方 [新加坡 API 许可](https://open.longbridge.com/docs/legal/api-license-agreement-sg)与[香港 API 许可](https://open.longbridge.com/docs/legal/api-license-agreement-hk)：页面许可围绕个人非商业用途的 API Code，许可可撤销。工程判断是：仅凭这两页不把行情历史留存、备份或外部 AI 使用权标为已确认；仍须核对账户适用行情条款及具体用途。这不等于断言私人 VPS 使用一概禁止。本模块没有替用户接受条款或伪造适用授权。

## 3. 采集与重建

`data_evidence.collect_prices` 在网络调用前检查工作区所有者、可写/恢复锁、当前审阅、用途与完整过去窗口；官方传输固定为 `longport==4.3.7`、隔离 UTC 子进程和 QuoteContext 日线查询，不提供交易或任意服务地址。

显式私有凭据文件复用原有严格解析器，不执行 shell，不修改环境，不搜索其他 `.env`，不把凭据传入 argv。原有默认环境接入仍兼容；本操作 CLI 强制指定文件。Python 内部测试注入不能同时读取凭据；采集资格始终为 `injected_test_client`，不能由 JSON 切换。

网络返回后再次以事务核对全部审阅；调用期间的撤回或改版不能提交旧绑定。价格原文是 **SDK 投影而非网络原始报文**，精确十进制与 int64 成交量保留；完整请求、调用微秒时点与版本进入哈希。收据元数据使用应用毫秒，读取器允许同一毫秒内的真实 SDK 返回时点，但不截断 SDK 证据。

`data_snapshot.build_dataset` 只读取保留收据和当前审阅，不接收调用方价格数组。逐资产/交易日覆盖必须完整；重复采集块即使数值相同也拒绝，不静默选 latest。企业行动和所需非人民币 FX 必须显式提供。输出最多 20 标的、100,000 观察、16 MiB 数据与清单。

数据模式严格区分：

- 官方采集路径的历史下载只能得到 `reconstructed`；今天下载的历史不是当时保管的时点档案。目录明确为回溯选定，不能称无幸存者偏差。
- 内部模拟采集只能生成 `synthetic`；默认读取器和操作 CLI 拒绝它。混合官方/模拟采集也拒绝。
- `published_at` 不从 SDK 的日期或日历猜测。价格和 FX 使用独立的 `assumed_available_at`；研究引擎在该时点之前不能将其用于决策。此字段不准进入普通行情发布路径。
- 清单固定 `historical_archive_verified=false` 的研究来源、外部 AI 未授权、非实时建议资格。不能重新贴标签升格为 historical point-in-time 或 actual replay。
- 企业行动/交收里的已知时点也是人工审阅的历史假设，不是独立归档证明。基金费率用于资料筛选；原价格所含基金运营费用不在此重建器额外重复扣除。

`investor-data-snapshot.schema.json` 固定所有收据、审阅和来源引用；纯研究内核支持重建模式，但继续输出探索研究与保留期独立资格未验证。检查历史本身不改队列，只有显式的 `admit-research` 将合格来源绑定到后台研究。

迁移 30 追加 `investor_evidence_inputs`，只保留快照引用、数据/目录哈希和有限研究设计，不复制价格载荷。准入会为已有最新偏好入队；之后保存偏好也自动绑定最新来源。相同来源和设计重复准入复用原记录，不因时钟变化增加实验。源记录的冻结时点保持不变，但每次使用都核对当前审阅、留存期限和载荷。

默认 core 可计算该 reconstructed 输入，不需要 synthetic 开关。风险未知只比较训练期候选与损失情景；风险确认后才冻结候选、检查验证及保留窗口，后期失败不换候选。每个阶段及合作式心跳检查来源有效性，最终提交再次完整核对；中途撤回只保留曝光意图，不能发布新结果。所有结果仍非实时建议资格。

迁移 31 追加不可变方案证据链接。风险已确认、同一冻结候选各阶段通过且来源仍有效时，默认 core 原子提交探索参考方案，不再次优化权重。未知风险或合成计算不自动发布该方案。Node 独立复核运行/试验/来源，再重建全部权重与解释并比较哈希；保存登记独立观察模型，不创建真实金融事实。撤回/过期/删除或设计过时隐藏旧权重、拒绝再次保存和恢复；历史链接不被改写。收据投影监测已接入下述默认 core，但真实来源纵切与自动采集尚未验收；reconstructed 模型拒绝合成快照，不能展示测试 NAV 冒充真实监测。

Web 只读读取器独立重放保留 SDK 投影、日历、企业行动和 FX，核对数据/目录、策略、试验、冻结与收据，不运行 SDK 或研究。首页区分合成测试与历史重建，显示研究区间、有效期、标的配置和假设损失。每次读取发现正常过期/撤回/删除便隐藏旧候选并显示具体缺口，不把旧权重当成当前结论，也不使偏好表单无法保存。可见页对运行/等待任务每 5 秒、阻断且无方案每 15 秒、其他状态每 60 秒只读复核；编辑、待提交或会话失效时不替换表单。本地已知有效期到达时独立隐藏旧研究/方案并禁用恢复，即使离线或正在编辑也不延长有效期；这不代表完整持续策略监测或严格刷新 SLA。损坏的哈希、作用域或证据仍固定报错。

## 4. 本地操作入口

仅由持有私有库的本地运维者执行。数据库与 JSON 文件要求仓库外绝对路径、所有者私有常规单链接文件和私有直接父目录；输入拒绝重复 JSON 键、非有限值和超限字节。CLI 不显示资料摘录、事实、价格、密钥或 Token。

```sh
python -m worker.investor.data_pipeline --help
```

所有子命令前指定 `--db /private/workbench.db --workspace WORKSPACE_ID --actor OWNER_ID`：

| 命令 | 额外参数 |
| --- | --- |
| `store-source` | `--kind rights\|listing\|calendar\|actions\|fx --file /private/source.json` |
| `review-source` | `--source SOURCE_ID --file /private/review.json` |
| `collect-prices` | `--rights-review ID --listing-review ID --calendar-review ID --start YYYY-MM-DD --end YYYY-MM-DD --credentials-file /private/longbridge.env` |
| `check-snapshot` | 重复 `--capture ID --actions-review ID`，按需 `--fx-review ID`，以及 `--start/--end` |
| `admit-research` | 同上，另加 `--design-file /private/research-design.json` |
| `check-monitor-snapshot` | `--model ID --file /private/monitor-data.json` |
| `admit-monitor-snapshot` | 同上，只准入引用元数据，不入监测队列 |
| `purge-price-payload` | `--capture ID` |

来源文件为 `{title,reference,excerpt}`；审阅文件为 `{decision,facts,reason,valid_until}`，facts 符合共享合同。只使用真实适用资料，不复制测试的虚构授权。命令不建工作区、不迁移库、不接纳任意数据为真实方案，也没有 synthetic、任意 client/endpoint 或自动交易开关。

`check-snapshot` 返回模式、哈希、数量和有效期，不导出价格文件、不新建研究输入或请求。`admit-research` 的私有设计文件只有 `{plan,policy}`，符合共享研究计划及投资者策略合同；不接受 dataset/价格。角色必须和审阅目录一致，策略设计/费用/税假设仍须另行核验，软件准入不会替用户确认真实性。它输出输入/请求标识与哈希，不输出行情或权重；没有偏好时保留来源而不新建偏好。错误仅返回固定错误码；恢复锁和 read-only 模式阻止修改。CLI 的 actor 参数是本地操作上下文，不替代网页登录认证或多租户授权。

### 监测数据检查入口

`check-monitor-snapshot` 是只读投影检查，不保存模型输入、不入监测队列、不启用模型，也不读凭据或调用 SDK。它要求当前工作区所有者、最新偏好、已选择的 reconstructed 模型及仍有效的参考来源；核对模型/偏好/方案哈希与目标，并拒绝相同内部证券 ID 更换交易代码、挂牌市场或币种。

私有文件只包含 `{windows,settings}`。旧 window 为 `{capture_ids,action_review_ids,fx_review_ids,start_date,end_date}`；需要收盘回调时另加非空 `confirmed_capture_ids`，两种 ID 不可互相代用。一地一个窗口，最多三地；不同市场可使用不同结束日期，不把三地强制对齐。settings 为 `{policy,funding_intent,max_quote_age_seconds}`，其中 policy/funding_intent 使用现有监测合同，费用、偏离阈值和时效必须显式提供；不接纳调用方价格数组或默认零成本。该高级入口不成为投资者首次填写的必做 JSON 流程。

`monitor_data.py` 只从已审阅收据和资料重建：分别确定最新已完成收盘、收盘前后与半日市，缺日历不假定节假日；日历自身的已知范围在当地午夜到期。价格 known_at 来自实际 SDK 接收时间，FX 来自实际审阅时间，不把历史假设可用时间冒充当时获取。最新 FX 可晚于美股最后交易日期，但必须在当前审阅内且满足独立时效。拆分、除息与派息分开，分红净额和税务假设显式绑定；企业行动 known_at 使用本次真实审阅时点，而非重建的历史 published_at。

封闭 `investor-monitor-data-input-v1` 仅含历史来源引用、窗口、设置与哈希；独立 v2 允许至少一段下述监测专用回调快照，同时保留其他市场的旧历史段。两者不复制报价，价格投影只在内存中；旧文档按旧算法重放，不静默升版。重放核对全部来源与冻结哈希，撤回、过期、载荷删除或投影到期不能继续返回旧报价。CLI 只输出数量、哈希、缺口和期限，不输出报价、费用参数、计划金额或资料摘录。它仍是 owner-reviewed reconstructed，不是数据商认证或实时建议资格。

### 监测元数据准入与独立读取

迁移 32 只追加不可变 `investor_monitor_evidence_inputs`，不重建旧表，不修改既有行、rowid 或迁移校验和。`admit-monitor-snapshot` 使用同一个私有文件，要求投影无质量缺口且尚未过期。准备完成后在写事务中重查模型、最新偏好/选择和完整参考来源，重放全部保留载荷并再次核对身份与时效；途中撤回、损坏、到期或恢复锁不能留下准入、审计或 revision 的部分写入。

记录只含引用、设置与哈希，绑定所有者、模型、目标定义和不可变审计。相同来源与设置再次准入复用原记录，不因当前时钟变化重复追加；准入不入队、不启用模型、不更新检查点、观察结论或真实金融事实。CLI 只输出输入 ID、哈希、资格和边界标记，不显示价格、费用设置或投入金额。

Web 后台读取器 `monitor-source.ts` 独立重放保留 SDK 字节及审阅事实，不运行 Python、SDK、研究或写库。它检查封闭合同、哈希、工作区/模型、审计、当前偏好/已选方案和原研究证据，再独立计算三地有效收盘、FX、企业行动和投影期限。重新封存的伪造投影或错作用域仍拒绝；来源正常失效则不返回旧报价。它已接入默认 core 的监测发布和首页读取；测试仍只使用虚构事实和模拟 SDK。

迁移 33 将收据准入绑定为独立 `investor_evidence_monitor` 作业。模型单位、分红应收、现金和拆分状态持续推进；成本和计划投入仅形成研究变化卡，不执行再平衡或入账。请求冻结 profile、控制、输入及前序检查点；提交时复核当前来源、实现与租约，原子追加检查点、运行、观察引用、revision 和本地通知元数据。GET 只读，不采集或调度。

不可变表只保存绑定、期限与哈希，派生模型及评估保存在可删除载荷中；观察行保存运行引用，不复制报价。前端独立重放完整来源链、模型单位、NAV、触发条件、费用和新资金修复，不仅相信 worker 的结果哈希。审阅决定只追加记录，未关联真实账户。归一化模型起点为 10,000 CNY，不是个人本金或扣费后账户收益。

模型定义 v1 的新请求使用 `investor-evidence-model-watcher-v2` 稀疏状态策略：有效收盘时点或单位/现金/应收/企业行动状态变化才追加检查点。只有价格、FX、费用、日期化计划投入或评估时钟变化时，仍独立计算新评估和变化卡，但引用已核验的原检查点，不重封状态收据、不延长期限。休市或重复轮询不会每 15 分钟消耗一个状态序号。旧 v1 请求和检查点继续按原算法重放；引擎版本参与调度去重，升级不修改旧请求。

绑定冻结低频规则的模型定义 v2 使用独立 `investor-evidence-model-watcher-v3`、监测输入 v3 与政策检查点 v2。周期、类别、证券容差、冷却和时区来自已重放研究来源与参考方案，不从传输设置的旧单证券 band 取得；规则不一致、旧未绑定低频方案或缺少合格输入时明确拒绝/等待，不回退旧监测。政策复核状态也采用稀疏封存；Python 与 Node 独立核对来源、前序状态和完整评估。具体边界见 [冻结低频监测](16-long-term-portfolio-policy.md#有状态监测发布链冻结规则和稀疏检查点)。另有[连续资金路径算术接口](17-continuous-funding-path.md)，尚未进入此发布链，不能以离线十年向量替代真实来源监测。

重放仍保留 1000 个状态的安全上限，不以扩大数字或丢弃祖先冒充十年连续性。上限处无变化评估可复用已核验状态；需要推进状态时明确返回 `MONITOR_CHECKPOINT_LIMIT_REQUIRES_RESTART`，不发布估值或自动重置。完整重新起点/重述与长期规模治理仍未实现；这项优化不是十年运行验收。

派生载荷期限受原方案、当前来源及所有前序检查点来源共同约束，不能以新报价延长旧许可或旧策略。到期载荷可通过所有者审计删除；此逻辑删除不证明 WAL、备份或物理介质已清除。历史链失效、行动改版或覆盖中断时阻断，尚无明确重述/重新起点流程。

**这不是持续真实监测已完成的证明。** 历史日线仍仅允许过去自然日，不因收盘而放宽当日采集规则；独立回调可通过下述新格式加入监测，当日所需回调缺失时仍阻断。企业行动审阅改版后的检查点重述、自动采集与留存联动、长期链规模及延迟、真实资料资格和生产部署仍待完成。

### 独立收盘回调接收器

新增 `worker/market/providers/longport_confirmed.py`，采用固定 SDK 的 `Confirmed` 日线/常规时段回调，而不是将历史接口返回的当日快照直接贴上“已确认收盘”标签。确认位来自 SDK 本地 K 线引擎，不是交易所签名或原始网络证明；订阅时 SDK 内部会读取最多 1000 根未复权历史 K 线用于初始化，返回快照不作为本接收器的事件证据。依据为[官方推送说明](https://open.longbridge.com/zh-HK/docs/quote/push/candlestick)和[固定版本源码](https://github.com/longportapp/openapi/blob/72e9be585d2724358ddaf7d6afbb64bb9e01205d/rust/src/quote/core.rs)。

请求在读取凭据或启动子进程前复制冻结，显式绑定证券映射、当地日期、收盘/假设可用时点、日历哈希与 watch ID；调用方中途改变原对象不能扩大监听范围。单次最多 32 个标的、900 秒，另有 30 秒启动预算。只有指定日期的已确认常规日线、且实际接收时间不早于声明可用时间，才能返回候选投影；早到事件不改写时间。日期只保留日期精度，SDK 原时间戳和实际接收微秒分开，不伪造 published_at。相同回调去重，冲突、协议损坏或后期失败使整个内存批次失败；无事件/部分覆盖明确显示，不用订阅历史返回补齐。收盘后才启动的短窗口不能恢复漏掉的确认事件，三地不同收盘仍需独立调度和真实验证。

隔离子进程只持有行情上下文，固定端点，封闭 UTC 环境及私有临时 HOME/空 dotenv；凭据只经 stdin，禁止 core dump。父进程限时/停止和内核 timer 独立约束，结束后终止/回收自己的进程组并删除临时文件。投影采用封闭 canonical NDJSON、请求/时间/哈希重放和字节比较，拒绝 `true/1`、`false/0` 等 Python 等值别名。纯解析只得到 `parser_only_not_network_authenticated`；固定传输的资格也不证明用途许可、日历、挂牌或真实账户可买性。

接收器本身不审阅许可或写库；下述私有包装器、监测专用格式和准入/core 已补上持久证据及独立读取，**自动行情生产者仍未完成**。不改变迁移 29 的历史收据格式，也没有真实推送/VPS 验收。已有检查点将来源留存与行情新鲜度分开，不能通过放宽期限绕过该缺口。详情和可复跑专项见[行情模块](../worker/market/README.md#sdk-confirmed-daily-callback-receiver-foundation)。

### 私有收盘回调收据与独立读取

`confirmed_capture.py` 在网络调用前要求当前工作区所有者、最新有效且有审计的 rights/listing/calendar 审阅；用途须包括私有研究、留存、展示与备份。审阅日历明确当地日期、正常/半日/休市及收盘后可用时点；超出本次监听加启动预算的过早请求在 SDK 前拒绝。请求只有审阅 ID 与日期，不接纳调用方价格、证券映射或日历事实。

等待不持有 SQLite 写事务。停止轮询核对所有者、恢复锁、来源头和期限，完成后在短事务中重新核对完整事实、来源字节/审计和冻结绑定；撤回、变版、到期、损坏或最后停止不能留下部分审计/收据/载荷。正式路径使用服务时钟和固定接收器，注入测试接收器始终记为 synthetic；其返回的价格数组、状态和交易权限标签不被采用。

迁移 **41** 只追加四张独立表：`investor_confirmed_captures`（不可变封闭收据）、`investor_confirmed_targets`（全部目标及审阅绑定）、`investor_confirmed_payloads`（可删除的有界协议封装）和 `investor_confirmed_purges`（审计删除收据）。不回填旧数据，不将当日回调冒充历史价格收据。协议封装绑定生产路径资格和父进程调用区间；它保存 canonical 回调投影，不是原始网络报文。无回调/部分回调仍记录尝试，但不升级为完整价格覆盖。

Python `resolve_confirmed_capture` 与 Node `confirmed-source.ts` 各自重放保留字节，核对所有者/审计、作用域、当前来源、全部目标、日历、接收时间、精确金额/int64、确认位和覆盖状态。重新封哈希的错误确认位、元数据改为正式路径的 synthetic、延长留存及已删除标记均拒绝。默认不读取 synthetic；Node 读取不运行 Python、SDK、写库或 AI。

高级私有 CLI 使用现有 `--db --workspace --actor` 参数：

- `collect-confirmed-prices --file /absolute/private/request.json --credentials-file /absolute/private/longbridge.env`。文件严格只有 `{targets,watch_seconds}`；每个 target 只有 `rights_review_id`、`listing_review_id`、`calendar_review_id`、`session_date`。最多 32 个标的，监听 1–900 秒。文件/父目录须私有且位于仓库外。
- `check-confirmed-capture --capture CAPTURE_ID`：只读核对，输出数量、状态、哈希和期限，不输出报价或资料。
- `purge-confirmed-payload --capture CAPTURE_ID`：到期或当前 rights 失效后审计逻辑删除，重复操作核对原删除审计且零写。

这不是首次使用的必做 JSON 流程。采集不创建金融事实、不改变研究 revision、不入队、不发布结论或发送 AI。留存取**全部监听目标**的权利授权、审阅截止与采集时点加声明天数的最早值，不因漏掉某目标回调而忽略其期限。默认 core 已在共享维护预算内清理这类到期/rights 撤回载荷，不重放价格或读取凭据。

### 监测专用回调快照与版本化准入

`build_monitor_dataset` 独立生成封闭 `investor-monitor-price-snapshot-v1`，要求 `use_scope=monitor_only`、至少一个回调来源和显式种类。`historical_sdk` 引用原收据/投影哈希；`confirmed_sdk` 引用新收据/载荷哈希。旧 `build_dataset`、研究快照及研究准入没有扩大接受范围，不能把回调 ID 填入历史 ID 字段或只改 schema 标签取得研究资格。

Python 与 Node 分别解引用全部监听目标，核对相同证券的审阅版本、日历、行动和 FX，并要求逐证券/交易日完整覆盖；重复报价即使相等也拒绝。无事件和部分批次不能靠丢掉未返回目标制造完整覆盖。一个多目标回调收据产生的观察 ID 同时绑定证券和日期，不因同日共用 capture 而碰撞；三地休市/半日和不同结束日期分别处理。

原回调保存实际 SDK 时间戳、日期精度与真实接收时间；用于模型算术的日线观察由审阅日历映射收盘/假设可用时点，继续标为 `reconstructed`、使用独立 parser 版本，不虚构 provider `published_at` 或原始回调的秒级收盘精度。监测投影 `known_at` 仍绑定实际获取/审阅时间，行情新鲜度与来源留存期限分别检查。

迁移 **42** 为原监测元数据表增加 v2 文档 CHECK 支持。按 [SQLite 官方通用重建流程](https://www.sqlite.org/lang_altertable.html)在专用迁移连接 BEGIN 前关闭外键执行，原子重建该表、复制显式 rowid/全部列并恢复原索引/触发器；提交前检查**全部**外键，成功后恢复该连接外键执行。迁移清单仅新项声明 `foreign_key_rebuild=true`；旧 SQL、版本/校验和、元数据字节及子表引用不重写，违规子引用使整个迁移回滚。不能在业务连接关闭外键，也不能据合成升级测试省略生产停写、最终备份和真实副本演练。

同一高级检查/准入 CLI 接纳上述新窗口字段，v2 仍只持久化引用、设置和哈希。准备后在写事务重新核对当前模型、偏好、参考来源和完整回调；期间撤回不得部分登记。新输入通过既有默认 core、稀疏检查点、观察引用和本地通知元数据发布，Node GET 独立重放且零写；并未新增金融事实、订单、自动监听或外部推送。

AI 上下文仍只包含已授权派生比例/偏离/触发码。除原研究和所有历史祖先用途外，还逐一核对回调收据**全部目标**的当前 rights 审阅；任一目标缺少 `external_ai` 即拒绝，不能由用户派生证据授权或另一个目标的许可覆盖。测试里的正向虚构授权不是长桥香港资料用途批准，不实际调用网关。

### 日历驱动的自动监听与后台准入

`confirmed_feed.py` 只从当前已选、启用的 reconstructed 研究模型及**已准入的监测 seed 输入**发现任务。三地按当地自然日查审阅日历，不猜测工作日、休市或夏令时；closed 不安排，缺日/来源失效登记固定缺口。每个模型/市场/日期只登记一次，冻结模型/控制/seed 哈希、全部目标及日历窗口；这是内部任务，不接纳调用方 command 或价格。

- 监听窗口从审阅 `close_at` 前 120 秒到 `available_at` 后 120 秒，最迟在收盘前 30 秒启动，单次总监听不超过 900 秒。晚启动只记录 `missed_window`，不启动 SDK，不用历史查询追回回调。
- 只有 longport 角色持有行情运行时与凭据。与历史价格采集共享数据库级 mutex；未来 120 秒内有可启动监听时，历史任务先让出连接预算。单任务最多一次尝试，租约死亡不自动重发；失败任务保留诊断，不能声称事件已追回或已有完整 feed 回执。
- I/O 期间不持写锁，检查控制/来源/停止及租约，按租约周期 heartbeat。原采集器返回内部冻结字节闭包；完整来源/审计和当前模型再次核对后，在 `complete_job` 事务内写回调证据、feed run 和任务结果。晚期错误整批回滚；提供方异常原文不成为 feed 状态或外发内容。
- complete、partial、no_confirmed_events、missed_window、superseded、transport_failed 分开。默认 core 不访问行情凭据，只为成功任务的完整、当前授权且保留中的回执尝试准入；不完整批次不推进输入或模型检查点。正常撤回/到期使准入 blocked，暂停/模型控制改变使其 superseded。
- 新输入保留既有窗口起点并追加完成的日回执，不丢弃前序行动覆盖；发现多个完成市场时合并完整回执后复用原准入与监测链。仍需全部目标、行动/FX、新鲜度、历史祖先和政策检查点有效，不能由监听成功自行认证“无需调整”。

迁移 **43** 仅追加不可变 request/run/admission 元数据、索引和 owner/audit/父引用 guard；旧表、版本 1–42、rowid 与迁移校验和不变。合同 `investor-confirmed-feed.schema.json` 不含原始报价或账户资料。没有新订单、实盘启用、自动 AI 计费或外部通知。

### 首个监测输入的自动建立

`monitor_bootstrap.py` 在默认 core 的来源清理、完成监听回执准入之后、监测任务发现之前运行。只处理当前已选、启用的 reconstructed 模型，且该模型从未有过监测输入。不会覆盖高级操作已登记的输入，不自动延长旧输入、重启过期链或启用模型。投资者无需准备监测 JSON；但缺失行情及其审阅不能由后台猜测补全。

- 只发现保留期内的完整官方历史或 Confirmed 收据，每次最多 128 个候选；全部选中凭据重放原始载荷、来源/审计、挂牌与日历版本。各市场使用审阅日历中最新已完成的收盘日，不把工作日或周末当作交易日。每个目标的代码、币种、市场仍与参考方案一致。

- 每个证券的所选日期必须由唯一当前行动审阅覆盖；非人民币币种要求唯一当前 FX 审阅。单类审阅候选最多 128 个，歧义不靠“挑最新”消除。上限是扫描预算，不是规模或延迟 SLA。

### 缺失首份监测价格的受控自动采集

`initial_prices.py` 为当前已选、启用且从未有过监测输入的 reconstructed 模型发现缺失价格。它只复用原冻结研究收据所绑定的 rights/listing/calendar 审阅；这些来源必须仍是当前版本，日历必须覆盖当地当前自然日。不是首次 ETF 宇宙取得、自动批准许可、选择替代来源或重新冻结研究的入口。

## 5. 留存边界与未完成项

留存截止取采集时间加声明天数、rights 审阅有效期、用途授权有效期的最早值。过期或当前许可撤回/改版使读取立即阻断。所有者可在到期或许可不再有效时删除载荷；不可变收据和删除记录保留，不重新提供历史价格。

默认 core 在新研究/监测发现前执行 `source_retention.purge_due_source_payloads`，自动处理行情载荷到期或 rights 审阅失效，并处理监测检查点/运行载荷到期或来源失效。原参考研究来源、当前监测输入和全部检查点祖先均参与判断；新输入不能洗掉旧祖先的撤回或延长期限。SQL 仅筛候选，未到期的监测删除还核对所有者、不可变输入/来源哈希、审阅审计、范围与链头关系，不重放价格或读取凭据。

历史行情、收盘回调载荷、检查点和运行共享一次 `discovery_limit` 删除预算（默认 100，允许 1–1000），按期限/种类/ID 稳定排序。每个删除的审计、删除收据和 BLOB DELETE 独立原子提交；停止或后续项失败不撤销先前已提交项，剩余项待下一轮。恢复锁/read-only 阻止维护；停止回调在扫描前和各项之间检查。core 停止时不会及时删除，SQL 候选扫描与最多 1000 个祖先核对的真实规模成本仍待验收，不能将删除条数上限称为硬延迟 SLA。GET、longport/verifier 角色不执行这项维护，清理不新增观察、任务、通知、revision 或金融事实。

**目前仅完成上述 SQLite 逻辑删除，不能宣称物理安全擦除。** WAL、旧页、备份副本和其他已生成资料可能仍有字节。资金比较和 AI 结果沿用各自的清理器，不以此次四类载荷表的维护声称全部下游清理完成；备份到期/撤回、介质清理、恢复批准后的强制清理/读取闸门、长期规模与生产验收仍未完成。恢复锁期间不会跳过审批执行删除；不得把此模块当作完整留存治理验收。
