# 已有观察方案的行动知识协议接续

状态：只读 Python 核验层已实现，尚未提供普通确认入口或正式迁移。
新方案默认 v4 不会自动升级旧 v1/v2/v3；本页不改变原有数据、投资或交易授权。

## 为什么不能直接切换版本

旧连续模型对完整行动对象保存哈希，其中包含 `known_at`。旧输入可能记录维护发布时刻，
而 v4 从原人工审阅及明确接续中恢复逐事件的实际知识时刻。即使金额、税额和拆分比例
没有变化，直接切换仍会触发历史重述要求。不能通过删检查点、清空已处理记录、重建本金
或回填历史收益来绕过。

已记录知识时刻较晚而审计原文证明实际知识更早时，可以准备一个明确、保守的协议沿用：
旧账保留自己的原时刻和哈希，新事件仍使用实际审计知识。若反而发现知识更晚、金额/税务
等经济事实变化、记录缺失，或在已完成区间发现新的入模后事件，必须另行审阅历史重述。

## 当前只读核验

`worker/investor/legacy_action_transition.py` 从真实数据库读入所有者、当前模型/选择/控制、
最新旧输入及完整检查点链。每个旧输入重新核对原准入审计、保留 SDK 投影、发行人/EODHD
原文、使用许可及明确后继关系；按原输入和原计算时刻重算状态，逐字段核对载荷、链、
已处理行动及原资金/策略绑定。沿用既有 1,000 个检查点安全上限，不延长原保管期限。

退役来源的比较范围只在同步只读核验内部短时生效，异常退出即清除；普通当前来源解析
仍拒绝旧输入。它不是监听授权、普通监测准入、税务更正或过期资料复活。

随后从当前有效且明确关联的行动原文构建审计来源，逐事件核对旧经济事实及知识先后。
报价过期可能使正常投影不再列出行动，因此比较另外读取已核验行动记录，不据空投影
推断“无行动”，也不伪造新报价、时点或新估值。旧链最早期限继续约束预览有效期。

输出只有模型/输入/控制/链的绑定、逐事件原记录与当前审计哈希、两类知识时刻及资料缺口，
明确为 `awaiting_explicit_protocol_confirmation`，`admission_performed=false`。
它不返回行情、净值或原始税务文本，不持久化映射或副本，不写入、采集、调用 AI 或交易。
封闭 JSON 契约只检查形状，不能把一个格式正确的哈希提升为证据或确认授权。
