# 已有观察方案的行动知识协议接续

状态：明确确认、不可变兼容收据、独立 v5 输入及首条连续消费已在虚构资料上验收；尚未接普通确认入口或生产迁移。
新方案默认 v4 不会自动升级旧 v1/v2/v3；本页不改变原有数据、投资或交易授权。

## 为什么不能直接切换版本

旧连续模型对完整行动对象保存哈希，其中包含 `known_at`。旧输入可能记录维护发布时刻，
而 v4 从原人工审阅及明确接续中恢复逐事件的实际知识时刻。即使金额、税额和拆分比例
没有变化，直接切换仍会触发历史重述要求。不能通过删检查点、清空已处理记录、重建本金
或回填历史收益来绕过。

已记录知识时刻较晚而审计原文证明实际知识更早时，可以准备一个明确、保守的协议沿用：
旧账保留自己的原时刻和哈希，新事件仍使用实际审计知识。若反而发现知识更晚、金额/税务
等经济事实变化、记录缺失，或在已完成区间发现新的入模后事件，必须另行审阅历史重述。

## 当前只读核验

`worker/investor/legacy_action_transition.py` 从真实数据库读入所有者、当前模型/选择/控制、
最新旧输入及完整检查点链。每个旧输入重新核对原准入审计、保留 SDK 投影、发行人/EODHD
原文、使用许可及明确后继关系；按原输入和原计算时刻重算状态，逐字段核对载荷、链、
已处理行动及原资金/策略绑定。沿用既有 1,000 个检查点安全上限，不延长原保管期限。

退役来源的比较范围只在同步只读核验内部短时生效，异常退出即清除；普通当前来源解析
仍拒绝旧输入。它不是监听授权、普通监测准入、税务更正或过期资料复活。

随后从当前有效且明确关联的行动原文构建审计来源，逐事件核对旧经济事实及知识先后。
报价过期可能使正常投影不再列出行动，因此比较另外读取已核验行动记录，不据空投影
推断“无行动”，也不伪造新报价、时点或新估值。旧链最早期限继续约束预览有效期。

预览输出只有模型/输入/控制/链的绑定、逐事件原记录与当前审计哈希、两类知识时刻及资料缺口，
明确为 `awaiting_explicit_protocol_confirmation`，`admission_performed=false`。
它不返回行情、净值或原始税务文本，不持久化映射或副本，不写入、采集、调用 AI 或交易。
封闭 JSON 契约只检查形状，不能把一个格式正确的哈希提升为证据或确认授权。

## 独立 Node 与费用接续

Python 内部准备层可同时返回未批准的候选元数据，供 Node 独立核验；普通预览仍只返回上述
摘要。Node 不接收或信任 Python 的预览结论，而是重新读取保留原件、准入审计和全部旧
检查点，独立重算状态、精确选源及知识沿用。候选只能沿用原窗口、捕获和非行动引用，
行动来源必须是经过完整证明的唯一接续；自洽重封的假状态或无关来源也不能通过。

候选只有五分钟的本地审阅窗口，并重新绑定当前控制、输入/检查点与费用。晚于候选的
控制、输入/检查点及已变化的当前费用不能沿用；最终确认仍须核对完整摘要的变化。
普通来源解析和历史比较是独立入口：比较专用字段不能替代当前投影，后者过期仍隐藏。
真实只读连接、原载荷 SQL 读取、精确旧审阅范围及范围内异常清理均已验证。

费用不会猜测。可以保留旧假设，或采用用户已另行明确登记的当前费用；原检查点仍按当时
原费用重放，旧输入和账目不重写。费用到期后回到未知，预览期限也受有效费用的期限截断。
这避免“来源已退役，费用更新不能先刷新旧输入”的循环，但没有批准正式迁移或新调整。

## 明确确认与不可变收据

`legacy_transition_workflow.py` 将“允许沿用原已处理行动的保守知识记录”单独登记为
兼容协议，不将确认等同于行情准入、恢复监测或交易。调用方必须提供当前工作区版本、
完整见证哈希及五项明确肯定回答；价格、时钟、强制启用及额外授权字段均不接受。
现阶段这些是领域函数，尚无普通页面或 API 会自动调用。

见证只有五分钟，并受原资料、检查点和当前有效费用期限约束；同 nonce 查询不会续期。
准备阶段只读，写入阶段再次从原件核验全部基础，最后检查新鲜时钟、停止、只读及恢复锁。
来源撤回、费用或控制/输入/检查点/版本变化不能提交旧准备结果。确认和审计/版本更新原子
提交，晚期失败整体回滚。响应丢失可取回同一历史收据，但它不重新批准当前来源。

迁移 57 只增加两张兼容审阅表及约束，不重建或修改任何旧输入、检查点、载荷、控制、任务
或已处理记录。见证仅保存有大小上限的来源引用元数据、精简证明及哈希，不复制行情原文、
检查点载荷或完整沿用明细。每个模型只登记一份此类兼容确认，不自动扩大保管期限。

收据只绑定原模型、原控制、原输入、原完整链末端和已处理知识集合。每次使用仍从原字节
重放原链，并核验当前唯一明确后继、完整行动经济事实、审计知识及使用许可；不能只验收据
形状或自洽哈希。原链核验可以严格止于收据批准的原序列，后续新检查点不会被误当原链，
也不能借此跳过原序列。新事件若落在已完成的入模后区间，仍要求独立历史重述。

独立 Node 也重新读取原件及重算原状态，不调用 Python 获取可信结论；只返回兼容收据，
不返回当前报价、净值或准入资格。收据的期限由原链/原输入/模型截断，不永久冻结确认时
的费用或监测开关。后续单独确认的新费用、到期后的未知费用及普通暂停/恢复分别核验，
不会改写原费用、自动复用过期费率或恢复原控制。

## 独立 v5 输入与原链继续消费

迁移 58 只扩充新的输入协议、准入记录和约束，保留历史行、rowid、载荷、FK 与旧迁移校验和。
旧协议及哈希不改写。v5 同时绑定原审计投影哈希、原来源保管期限、兼容确认与派生投影哈希；
派生使用明确的 v3 知识协议，不把沿用的保守知识伪装为纯实际审计 v2。投影和每条报价/汇率
期限只可被原兼容期限截短，不延长任何旧资料、报价或模型寿命。

原已处理行动逐项核验经济事实和当前审计知识后，才沿用原记录的知识时刻；新行动仍使用
实际审计来源。只持有兼容收据不够：必须有真实、原子提交、所有者/审计绑定的首次 v5 准入。
历史检查点比较只允许收据精确原前缀；普通当前来源读取仍拒绝退役旧输入。v5 后续输入
不得退化为旧协议或更换兼容绑定，数据库及独立消费者均重新检查。

首次准入可登记有明确行情/日历/汇率缺口的来源元数据，但不产生当前净值或交易许可。
即使投影在构建时已经过期，既有已启用模型仍可在原引用、身份、许可和审计全部有效时，
只使用核验后的证券元数据准备监听；实际日历和采集时窗仍须独立合格。比较投影不作为
当前估值，不因资料不足重新请求历史数据，也不自行改变监测开关。

初条端到端通过实际虚构回调验证：早于升级已完成且原准入被阻断的收盘采集，可在明确
兼容登记后由默认 core 重新核验原请求、控制、回执及保留原文，形成新 v5 输入和第二个
检查点。原采集/尝试/准入结果不重写，不新建提供方请求，原单位、起点和已处理哈希保留。
重复刷新不再次纳入同一采集。独立 Node、真正只读连接与普通工作台状态均重放原件。

另行明确确认的费用更新继续保留 v5；原检查点仍使用当时费用。到期后费用未知、行情陈旧
时隐藏当前净值，不按零费率补出建议。读模型优先标明费用已到期，即使新未知费用输入
尚因其他资料缺口未应用；`input_applied` 仍单独反映应用状态。自洽重封的伪报价/准入/审计
哈希不能取代原始资料重放。以上均是软件证据，不是实际市场准入或投资盈利证明。
