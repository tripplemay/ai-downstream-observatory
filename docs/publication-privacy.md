# 公开代码与本地个人资料

## 已确认的发布边界

公开仓库只保存代码、通用产品规格和明确标注的合成示例。个人投资方案、
资金规模、年度投入安排、实际券商及账户资料保留在本地，不作为公开默认值、
测试参数或构建输入。新建组合不自动生成资金计划，也不生成现金事实。

| 内容 | 保存与发布规则 |
|---|---|
| 源码、契约、迁移、通用文档 | 可提交；提交前复核实际 Git index |
| 合成测试、演示与 benchmark | 可提交；不复用完整个人方案，不暗示真实交易或投资收益 |
| 个人规划原件及本地发布审查备份 | `.private/`；Git 和 Docker 构建上下文均排除 |
| 实际数据库、账户原件及导入文件 | 受控数据目录；不随源码或镜像发布 |
| 环境配置、密码、令牌及恢复密钥 | 受控本地文件；不进入 Git、镜像、日志或公开 CI 工件 |
| 本地浏览器、测试与运行证据 | `artifacts/`；不进入 Git；分享前另行检查 |

`.gitignore` 不会自动取消已暂存或已跟踪的文件；`.dockerignore` 也不清除
已有镜像或远端记录。因此不能只检查工作树、只增加忽略规则，或直接执行
`git add -A` 后就认为已经脱敏。目录之外的原件和秘密仍需单独保护，不使用
`git add -f` 绕过这些边界。

## 每次公开提交前

1. 保留个人原件及必要的本地备份，不以覆盖原件的方式生成公开模板。
2. 检查工作树、未跟踪且未忽略文件，以及实际 index 的全部新增/修改内容；
   确认文档、默认值、fixture、衍生 benchmark、日志和附件没有带入个人信息。
3. 检查暂存路径、实际 blob 和忽略规则，执行 `git diff --cached --check`。
   `tests/deployment/release.test.mjs` 的路径边界回归不能替代内容审查。
4. 检查 Docker 构建上下文及 CI 上传范围。CI 只能上传该次隔离合成测试产生的
   验证工件，不能上传本地数据、个人规划或真实账户资料。
5. 绑定实际提交 SHA 和 CI 结果；不要把本地通过、代码公开和生产上线混为一谈。

当前 CI 的 push/PR 仅运行测试和隔离容器验证。生产发布使用独立的人工触发
工作流，另需通过发布门槛。公开代码不代表个人资料获准上传、实盘策略获准运行，
也不代表系统、生产或盈利目标已经验收。

若发现信息已经进入公开历史或工件，先记录受影响范围；删除当前文件不能撤回
历史副本。是否需要密钥轮换、工件删除或历史清理，应按实际泄露内容另行处理，
不擅自重写仓库历史。
