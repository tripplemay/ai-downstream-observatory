# 年度投入与默认持续观察

状态：2026-10-09，已实现默认 core 的计划版本绑定、释放边界复核、历史检查点重放和当前状态失效；虚构来源的限定冻结回归通过。尚未完成真实来源、完整界面/HTTP 或生产验收，不代表已上线。本文只使用通用规则，不包含个人计划。

## 投资者主路径

1. 保存简短研究偏好，待合格来源的参考方案生成、核验后保存为观察模型；不需要先建真实账户。
2. 可选填写[长期投入安排](18-private-planned-funding.md)。保存只登记计划版本，不确认到账、买入或策略批准，也不立即计算历史比较。
3. 默认 core 在后台读取当前计划。未到年度批次时展示下一批次的研究假设；到期后按未执行假设资金池评估新资金优先修复。行情、成本或其他证据不完整，仍显示证据不足，不生成看似可执行的买点。
4. 投资者查看当前结论及证据，自行采纳思路、暂缓或拒绝。三种决定都不下单、不更新现金/单位，也不消费假设资金池。实际交易和回录仍是独立路径。

没有计划时保留原监测引擎；保存计划后不再允许新任务遗漏该计划。旧请求和检查点仍按原版本重放，不能把新假设追溯到旧观察。已到期但实际已投入的资金不能仅凭审阅决定从假设池删除；明确重建观察起点、真实成交对照及相关产品流程仍需完善，当前不是自动实盘资金管理。

## 新版本，不改写旧历史

- `investor-evidence-monitor-request-v2.schema.json` 的引擎为 `investor-evidence-model-watcher-v4`。不可变请求除原模型/偏好/控制/市场输入/前序检查点外，固定七字段 `funding_binding` 和稳定 `funding_context_hash`。
- `investor-evidence-model-checkpoint-v3.schema.json` 固定生成该状态时的计划绑定。旧参考定义与低频定义都可使用；低频定义仍要求原政策状态。旧请求 v1、引擎 v1-v3 和检查点 v1/v2 合同不变，不将旧检查点补写为新版本。
- 每个历史检查点先读取其原绑定，再从相应计划、模型、历史偏好及精确保存审计独立重建日历假设。Python 和 Node 均重放整条市场状态链；历史计划可读不等于当前模型、行情、许可或祖先载荷仍有资格。
- 迁移 **45** 仅追加请求、检查点载荷和运行记录的 guard；旧 1-44 项 SQL 与清单条目不变，不重建表、不回填资金。SQL 拒绝错计划/模型/登记时间、非法摘要、额外请求字段，以及 v4 任务降级到未绑定的检查点载荷。摘要正确不单独证明来源或许可。

相关实现：`worker/investor/evidence_monitor_runtime.py`、`worker/investor/model_state.py`、`web/src/server/investor/evidence-monitor.ts`、`web/src/server/investor/evidence-model-state.ts`。原计划的日期和整数资金口径见[准备与归档规则](28-planned-funding-monitor-preparation.md)。

## 从发现到发布的失效边界

- 发现阶段以当前模型/输入和稳定释放上下文去重，同一释放区间不因每次轮询新建计划身份。
- 准备阶段核对冻结请求与当时计划；提交阶段在同一事务内再核对当前计划、释放上下文、控制、来源、前序检查点和有效租约。准备后改计划或跨越释放边界，旧结果跳过，不写检查点、运行或 outbox；后续 core 再处理新上下文。
- 下次复核不晚于下一批次或计划终点，还受原模型/行情/来源等期限约束。日期不能续期陈旧报价，也不能令失效来源重新合格。
- 当前 Node 读取会立即检测新计划或释放区间变化，隐藏旧 NAV/旧“继续观察”，标记需要重新核验；不能等旧任务完成后才失效。迟到任务与超期检查不能覆盖该状态。此处验证的是服务与严格客户端数据，不是完整浏览器呈现验收。
- 计划窗口到期停止输出投入意图并发布明确缺口；等待资金复核期间同一状态去重。后台评估保留原报价/来源缺口的优先检查，不用资金提示使失败证据变为可用。

## 不改变财富和数据权限

年度到期池是归一化研究假设，初始资金只作分母；观察模型初始名义值仍为 `10000`。现金、持仓单位、应收和公司行动只由原市场状态内核推进，不因计划、到期或审阅决定增加。稀疏检查点在旧版首次提升或计划绑定改变时留一次新版本；重复观察同一状态不无限创建检查点。低频政策可记录新的资金复核锚点，但不执行投入。

监测输入已有独立 `funding_intent`、同时又有保存计划时，按 `MONITOR_FUNDING_INTENTS_CONFLICT` 阻断，不猜测哪项优先或将预算相加。未知费用仍按 `CANNOT_COMPARE_CHANGE_COST` 阻断，不能因为新资金只买不卖就假设成本为零。

纯 `unadmitted_planned_funding_projection` 仍被行情/AI 输入合同拒绝。只有所有者、原始计划和审计经核验的新请求路径将其作为评估上下文；原行情投影哈希不改写。AI 授权仍仅限 `model_ratios`、`target_deviation`、`strategy_trigger_codes`，不新增年度金额、计划 ID、日期、风险答案、持仓、账户、原行情或密钥外发。行情用途、认证主体/生产绑定仍需独立验证，本次无真实外发。
