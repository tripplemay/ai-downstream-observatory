## 2. 架构决策

### ADR-01 保留模块化单体，先不拆微服务

已确认保留 Next.js + Python + SQLite，部署为一个 Web 实例和一个后台调度实例。同一宿主机使用本地持久卷；研究重计算不占据Web请求线程或长期数据库事务。

SQLite WAL仍只有一个同时写入者，且不适用于跨主机网络文件系统共享；因此不将这套方案水平扩容或放到NFS共享库上。[SQLite：WAL与并发](https://www.sqlite.org/wal.html)

若持续无法满足第8节性能/恢复目标，或必须多机写入，再单独提出数据库迁移决策，不在本轮无依据引入消息中间件和分布式系统。

### ADR-02 事实写入集中，研究结果隔离

```text
用户浏览器
  -> Next.js 鉴权层 / Server Actions / Route Handlers
    -> 账户与账本命令服务（真实事实、批准、预留）
    -> 只读查询服务（显式版本与质量）
                       |
            SQLite etf-workbench.db
                       |
Python调度 -> 数据采集 -> 不可变批次 -> 估值/研究/策略评估
                                  -> AI复核 -> 风控结果/建议草稿
                                  -> 通知发件箱

用户在券商交易 -> 成交文件/人工记录 -> 预览 -> 确认 -> 事实入账
```

同一数据库中采用表所有权和受检写入接口，不让 Web/Python 各自实现一套真实账本业务逻辑。SQLite没有细粒度服务账号权限；这是受信应用进程的工程边界，不声称可抵御具有宿主机或数据库文件写权限的进程。AI不持有数据库、shell或任意代码执行工具。

| 数据域 | 唯一业务写入者 | 其他模块权限 |
|---|---|---|
| 真实账户、导入确认、分录、持仓投影、账本版本 | Web账本命令服务 | Python只读，不直接补写真实成交 |
| 政策/策略批准、生效版本、用户确认、资金预留 | Web治理命令服务 | Python读取有效版本，不能自批 |
| 原始市场资料、数据批次、来源修订 | Python数据服务 | Web只读，不从页面修改来源事实 |
| 估值、绩效、回测、模拟事件、评估结果、风险快照 | Python计算服务 | Web只读，真实事实更新后标记旧结果失效 |
| AI证据与研究输出 | Python研究服务 | 仅作为待审证据，不直接应用投资动作 |
| 用户研究笔记 | Web笔记命令 | 与AI原始输出分版本保存 |
| 任务状态与通知尝试 | Python调度/通知服务 | Web只能发出授权命令或重试请求 |

市场发布、风险计算和批准都保留版本。批准时在同一短写事务内重新读取账本、当前市场发布指针、策略/政策和预留状态；输入摘要已变化则拒绝批准并重算。

### ADR-03 新库迁移，旧库不原地变真实账本

新路径拟为 `data/etf-workbench.db`，旧 `data/observatory.db` 保留只读归档。新真实账本从用户确认的期初状态开始；旧模拟盘不得提升为真实账户，旧净值不得直接拼接成新实绩。

schema由单一迁移清单管理，Web和worker启动只验证版本，不建表、不自动补列、不灌业务资金。空库可初始化参考枚举和无资金的工作区，但不能预置个人资金计划、种入现金或自动批准策略。

### ADR-04 金额用十进制，契约统一

Web拟采用经过测试的十进制库，Python用`decimal`；两端配置遵循ACC-04并共享金标准夹具。`decimal.js`可配置精度和舍入模式，作为候选实现，不在本轮安装或锁定版本。[decimal.js 官方文档](https://mikemcl.github.io/decimal.js/)

版本化JSON Schema作为跨运行时数据契约的单一来源；TypeScript校验器和Python校验器由它派生或对同一fixture验证，不能人工维护不同字段含义。统计浮点输出不能绕过金额转换检查。

### ADR-05 追加记录与可重建投影

事实、批准和研究结果追加保存；当前有效指针、任务状态、预留状态及展示缓存可变，但每次变更有事件和版本。先做到可重放和对账，不引入大型通用事件平台。

### 3.2 数据引用与附件

数据库保存受控附件ID、内容哈希、类型、大小和保留策略，不保存任意可供页面直接访问的文件路径。原始资料、券商文件和备份留在权限受控的数据目录，不纳入Git、镜像或公开静态目录。

市场大批次先在库外/暂存区解析校验，事务内仅提交标准化结果及发布指针；一个批次未完整校验前不能成为策略默认输入。历史研究引用固定manifest，不依赖会变化的“最新值”。

## 4. 服务命令与事务契约

### 4.1 公共约定

所有用户命令先验证身份和对象范围，再校验契约。变更命令携带`idempotency_key`及相应`expected_revision`；金额为字符串，时间为显式时区格式。统一错误包括：`UNAUTHENTICATED`、`FORBIDDEN`、`VALIDATION_FAILED`、`VERSION_CONFLICT`、`DATA_NOT_READY`、`POLICY_NOT_ACTIVE`、`INSUFFICIENT_FUNDS`、`DUPLICATE_CONFLICT`。

同键同内容返回同一业务结果；同键不同内容报冲突。幂等不是跳过身份验证。返回对象包含实际提交revision和审计ID，不仅是“成功”。

| 命令 | 主要输入 | 原子行为及输出 |
|---|---|---|
| `previewImport` | 文件ID、账户、解析/映射版本 | 只建暂存与预览，不修改账本 |
| `confirmImport` | batch、预览哈希、账本revision | 重新验重及对账前置检查；事件/分录/投影/head/审计一次提交 |
| `correctEvent` | 原event、更正内容、原因、revision | 反向+替代事件及投影更新原子提交 |
| `activatePolicy` | 候选版本、批准身份、生效时点、证据 | 检查完整性、重叠及准入，更新有效指针，不产生交易 |
| `requestEvaluation` | scope、周期、有效版本 | 入持久命令请求，不在HTTP请求中跑重回测 |
| `approveProposal` | proposal版本、expected heads、确认内容 | 核对当前依赖、有效期、策略状态、资金与证券预留；批准/预留/审计一次提交 |
| `prepareExecution` | approval、最新账户确认 | 再验输入与价格条件，返回短时有效执行清单；不下单 |
| `recordExecutionReport` | 券商下单/成交状态和证据 | 下单仅改变报告/预留；成交经账本命令入账，不猜测成交 |
| `cancelRemainder` | 未成交部分、原因、revision | 释放对应预留，不取消真实成交 |

模型调用和外部HTTP请求不得在上述数据库事务内执行。外部成交无法与本地批准构成分布式原子交易；用户在券商自行成交后以事实对账为准。执行前检查减少陈旧建议风险，但不承诺券商成交时市场条件不变。

### 4.2 SQLite运行约束

- 使用本地卷；每个连接启用外键，校验实际WAL模式，真实事实提交建议`synchronous=FULL`。
- 写事务尽量采用短的`BEGIN IMMEDIATE`，读取校验与CAS提交在同事务完成；禁止批量采集时持锁等待网络。
- `busy_timeout`不能替代并发正确性；遇锁按有限重试策略处理，同一命令幂等。
- 发布大行情批次和重算净值时分离暂存/发布，不删除当前可信结果再慢慢重建。
- 策略计算读取固定manifest和账本快照，计算可在事务外进行，保存结果时保留输入版本；批准发现版本变化即失效。
- 定期监测WAL体积、长读事务、锁等待、磁盘容量与备份结果。

## 5. 调度、失败恢复与通知

持久任务唯一键建议为`job_type + scope + period + input_version`。调度器领取任务时原子写lease和递增fencing token，保存heartbeat；lease过期可重领，但旧持有者不得继续提交发布结果。

```text
queued -> running -> succeeded / partial / failed / skipped
              -> lease_expired -> retry_queued
```

每次尝试独立记录，重试不覆盖前次错误。`skipped`需说明休市、无任务或依赖未就绪；依赖未就绪不算成功。外部网络操作最多建议3次尝试并指数退避；持续失败转人工待办，不无限重试。

任务依赖链：有效市场批次 -> 估值/必需数据 -> 策略评估 -> 必需AI复核 -> 风控/建议发布 -> 通知。部分成功只推进不受影响且证据充分的分支；影响范围不明则阻断总组合新建议。

跨日补跑必须按原周期及当时可用数据重放，标记迟到；不能用今日行情伪装成昨天及时产生的建议。错过执行时点的建议保持历史记录，不反向执行历史交易。

通知使用事务发件箱：投资结果提交时写outbox，发信失败只重试通知，不重新交易或记账。任务内副作用以幂等及唯一键保证；SMTP等外部发送可能出现“已发送但响应丢失”，只能尽量去重，不承诺外部恰好一次送达。

## 6. 安全、配置和可观测性

### 6.1 认证与授权

首版仍需单用户认证。建议采用成熟认证组件、服务端session和安全Cookie，不自行设计密码学协议；具体组件及安装版本列为实现前技术选型，不影响“全部入口必须鉴权”的确定要求。

Server Actions、Route Handlers和私有查询各自验证会话和授权，不只在首页或导航隐藏按钮；Next.js官方同样要求在服务端变更入口实施授权检查。[Next.js 15：Data Security](https://nextjs.org/docs/15/app/guides/data-security)

登录限速、session失效、退出撤销、Cookie安全属性、CSRF/Origin及代理头配置均纳入验收。健康接口只返回最小存活信息，不泄露余额、任务日志和配置。

### 6.2 文件与AI边界

- 上传限制类型、大小及解析资源，拒绝路径穿越和未支持格式；CSV导出防公式注入，HTML/Markdown呈现限制危险内容。
- 券商文件及完整账户信息不发送AI，日志和告警使用别名及最小字段。
- AI只接收预定义输入，只输出契约化研究结果；文本不得转换为任意SQL、shell或动态代码。
- 证据网页与模型输出均为不可信数据；检索限制目标协议/来源，防止用户或模型把内部地址当研究URL任意访问。
- 模型故障按03文档的已批准依赖规则降级，不用默认“乐观通过”结果替代复核。

### 6.3 配置与部署

统一配置名拟为`WORKBENCH_DB_PATH`、`WORKBENCH_DATA_DIR`、`WORKBENCH_ENV`和`WORKBENCH_MODE`；生产绝对路径显式配置，缺失时失败，不回退到另一个空库。路径对齐含日志、附件和备份，避免standalone工作目录变化导致读取错位。

增加`.dockerignore`并缩小COPY范围；排除`data/`、真实`config/`、`.git/`、`.venv/`、开发构建产物。容器非root运行，密钥通过受限挂载/环境注入，不进入镜像层、构建日志或客户端包。检查忽略规则不等于镜像验证，必须扫描实际构建结果。

CI执行测试和构建；部署需单独人工批准，使用明确release SHA/镜像标识。移除“任意main推送直接覆盖生产”的默认行为。首版始终无券商下单连接。

可观测性最少覆盖：任务各阶段成功率、数据有效时间和覆盖率、账本revision、未解决对账项、被阻断清单、锁等待、队列积压、AI失败、通知失败和备份恢复状态。运行日志不充当唯一审计账本。

## 7. 备份、恢复与迁移

### 7.1 备份设计

SQLite备份采用Online Backup API或经过验证的一致性快照，不在数据库活动写入时仅复制主`.db`文件忽略WAL。备份必须实际恢复校验，不能只检查文件存在。[SQLite：Backup API](https://www.sqlite.org/backup.html)

备份manifest至少包括：schema版本、应用release、数据库校验和、账本head、市场manifest引用、原始附件清单和备份时间。DB快照先确定引用集合，复制其中不可变附件并校验，最后原子发布完整manifest；不发布缺附件的成功备份。

已确认的初始工程目标：RPO不超过15分钟、RTO不超过2小时；具体基础设施和保留周期仍需确定，并通过恢复演练验证。RPO不是零数据损失承诺；恢复后仍需按券商事实核对未备份区间。

备份加密、至少一份异机副本，恢复密钥不与备份唯一副本放在同一故障域。备份访问不通过公开Web下载接口；保留/删除策略依据本地投资管理周期、审计需要和隐私要求制定，不预设个人投资年限，也不在本稿冒充法定保存期限。

### 7.2 迁移步骤

| 阶段 | 工作 | 放行证据 |
|---|---|---|
| M-00 基线冻结 | 记录代码、schema、数据规模和真实拓扑；保留旧系统 | 只读清单；生产操作另行批准 |
| M-01 副本演练 | 用SQLite备份得到隔离副本；构造旧schema多种样本 | 备份哈希、恢复通过、旧数据未变化 |
| M-02 新库初始化 | 独立迁移入口建新schema、空实际账本、参考枚举 | 迁移版本校验；Web/worker均不自动seed资金 |
| M-03 旧数据归档映射 | 转为带legacy来源的研究档案；新旧ID映射 | 行数/内容校验、孤儿检查、未映射项清单 |
| M-04 真实账户开账 | 用脱敏样例验解析；用户确认实际期初现金/持仓 | 各账户对账；历史未知明确标记 |
| M-05 影子运行 | 新系统只读/研究；新旧结果差异分析，禁止双写真实账本 | R-01至R-10回归及影子结果报告 |
| M-06 受控切换 | 停旧写任务、取最终备份、迁移尾差、复核、显式切换路径 | 双端版本一致、只读健康、账本及查询验收 |

### 7.4 回滚边界

- 首笔新真实事实写入前，可撤销流量切换并恢复已验证旧环境，但旧环境不得被宣称具备新账本能力。
- 新真实账本开始写入后，不允许直接用旧库覆盖；先停写和停止新建议，保存新库与全部尾部事实，回到新库兼容的只读版本或修复前滚。
- 若必须从备份恢复，隔离重放备份之后的可确认事件，重新对账；无法恢复的区间保持未就绪，不凭预算补余额。
- 外部券商已发生成交不可回滚，只能补录或真实执行新的交易；软件回滚不得制造反向成交。
- 未验证恢复路径之前，不得以“有备份”作为上线放行条件。

## 8. 工程目标与实施顺序

这些是已确认的初始工程预算，不是当前实测值，也不是投资阈值；若实现验证发现需要调整，应记录依据并重新评审。

| 指标 | 初始验收目标 |
|---|---|
| 基准测试环境 | 4 vCPU、8 GiB内存、本地SSD；记录具体版本和资源限制 |
| 数据集 | 10账户、1,000证券、200万行情记录、5万账本事件；含跨币种与错误样例 |
| 页面 | 缓存可追溯且数据已就绪时，核心查询服务端p95不超过2秒 |
| 原子命令 | 不含上传/外部调用的批准与小批记账，p95不超过1秒；结果正确优先 |
| 导入 | 1万行预览与确认可后台执行、可查询状态，60秒内完成为初始目标 |
| 运行恢复 | 进程中断后任务可恢复且副作用不重复；账本已提交事实不因重试丢失 |
| 备份恢复 | 第7节RPO/RTO必须演练证明；未达到则记录失败并调整设计 |

建议实施顺序：

1. **基础与隔离**：测试夹具、契约、迁移入口、认证、密钥与构建边界。
2. **真实账本**：开账、导入、分录、对账和审计；先验证F-01至F-07、F-12/F-13的事实与分录部分。
3. **可靠数据与估值**：市场日历、版本化批次、公司行动、汇率、收益质量标签。
4. **研究与模拟**：修复旧算法风险、基准、参数版本、样本外及前向模拟。
5. **建议闭环**：风控快照、批准CAS、预留、执行回录、AI复核与异常恢复。
6. **部署验收**：生产副本演练、恢复演练、人工验收和分级启用。

阶段2/3的输入互有依赖时先用固定可信fixture推进，不以临时联网成功替代确定性测试。阶段3补齐估值、绩效及质量样例，阶段5补齐并发预留；相应能力放行前必须完成F-01至F-16中全部适用样例，不把后续阶段尚未完成的检查标为通过。
