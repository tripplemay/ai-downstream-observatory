# Avoid reconstruction when there is no work to qualify

An idle worker can spend most of a pass validating retained research even when
it cannot enqueue or publish anything. A production loop observation identified
material CPU use, not its exact Python frame. The fictional full-role profiles
below independently identify two software costs; they do not prove a production
latency SLA or explain every busy period.

## One complete source reconstruction per initial-price context

`current_monitor_model` already verifies the complete source/result binding for
a fixed-policy reference. Initial-price context discovery no longer performs
that same complete check a second time. Legacy references still explicitly
request full result-binding verification: their ordinary header check alone is
not sufficient.

The final source resolution supplies reviewed reference headers and replays all
retained payloads, rather than rebuilding the dataset again when only capture
references and source expiry are needed. The complete binding is still checked
once, and owner, reviews, audits, currentness, hashes and original payload bytes
are still checked at their required resolutions. No successful permission,
database result or qualification is cached between calls. Existing preparation,
fresh transport-boundary and fenced final-commit checks remain unchanged.

## No recent receipt means no candidate, not a healthy source

First-input bootstrap checks model/workspace membership and searches the
existing bounded recent-receipt headers before rebuilding historical research.
An empty search returns the existing `PRICES_NOT_READY` gap. It does not produce
an input, certify a model, refresh a timestamp, reuse an old price or claim that
the historical sources are healthy. The search is repeated on each call.

If any receipt can be considered, the original complete current-model/source
validation and candidate replay still run. Full coverage, conflicting prices,
identity, calendar, rights, actions, FX, costs and final admission fences are
not replaced by the header search. Source withdrawal and later-arriving receipts
remain independently checked. A scoped membership lookup still rejects foreign
or missing models before receipt scanning.

## Fictional full-role comparison

A disposable fixture contains 1,826 invented source days, two fictional listings
and 118 retained transport projections. Its research contract uses the existing
six-month test window; this is **not** a five-year strategy study, real market
data or investment qualification. Initial-price slots were closed without I/O.
Measured passes used no new trial intents, SQL changes, credentials or providers.

Frozen preceding code and the changed code ran against the **same** temporary
database in before/after/after/before order, with no profiler in the timing runs:

| Full-role case | Before, seconds | After, seconds | Work per pass |
| --- | --- | --- | --- |
| Initial-price discovery with existing requests | 10.28 / 10.14 | 5.73 / 6.25 | Dataset builds 3 -> 1; retained payload replays 590 -> 354; audit bindings 3,592 -> 2,168 |
| Core with no recent receipt headers | 3.63 / 3.66 | 0.0019 / 0.0017 | Dataset builds 1 -> 0; no source qualification or publication on the empty path |

The second case advances only its private fixture clock while source retention
remains valid; it does not extend freshness, change a real clock or fetch a
missing session. New-receipt cases separately require complete qualification.
These observations are not summed, extrapolated to all states or presented as
shared-VPS capacity results. A faster pass can also run more often: per-pass CPU
reduction does not directly certify a proportional reduction in service CPU.

## Verification and remaining work

Focused regressions count complete builds and retained payload replays for both
model versions, reject withdrawal after reconstruction, and check empty search,
later arrival, withdrawal with recent headers, foreign scope and zero financial
facts. Existing concurrency, immutable request recovery, stops, read-only,
restoration, lease and transport-boundary regressions remain required.

The final focused combined regression passed 69 tests, additional source/monitor cases
82, full orchestration 183, and independent Node journeys 9. These sets overlap
and are not summed. Five fixed bundles, Next production build and the serialized
post-build TypeScript check passed. Negative cases first reproduced the repeated builds and
unnecessary empty-path model checks. An initial profile fixture incorrectly
assigned settlement metadata to closed days; only the invented fixture changed,
and the original failure remains in private evidence. No calendar rule was relaxed.

Full CI exposed seven existing FX bootstrap tests whose mocked model context
had no stored model header. Their fictional setup now persists the scoped
profile, reference, selection and model with normal database constraints; the
production membership check and FX assertions are unchanged. All seven cases
and the complete 198-case Python discovery shard passed locally. The original
CI failures remain failures, pending new exact-commit checks.

No migration, strategy, risk, fee/tax assumption, source authority, daily budget,
timeout or lease duration changes. Closed earlier price attempts are not retried.
Exact-commit CI, normal protected deployment and independent runtime acceptance
are separate. Partial candidates, qualified continuous-monitoring replay, other
discovery costs, capacity, running recovery and all remaining v2 P0/P1/P2 work
remain open. This increment does not turn an insufficient-data page into a
completed product.
