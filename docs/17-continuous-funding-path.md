# 连续长期资金路径：计算接口与验收边界

状态：2026-10-08，本地探索计算内核。纯入口没有数据库或发布副作用；独立[私有比较任务](20-private-funded-comparison.md) 已接入认证登记、后台和界面状态，完整经济结果未发布，尚未部署生产。只验证虚构数据上的算术和软件行为，不代表真实 ETF 策略有效，也不是个人十年预测。个人资金、券商与账户资料不进入本文。

## 目的

在一条连续组合轨迹中处理初始资本、明确到账的追加资本、待投入现金、分批释放、公司行动和交收。跨年不清空持仓、不重新设单位净值，也不拼接独立训练/验证/保留期回测。

比较使用完全相同的冻结配置、资金到账日期、费用、决策时点与市场资料，只改变资金可用于研究订单的日期：

- `immediate`：每笔资金在到账时全部可用。
- `staged`：每笔资金按输入中预先固定的当地自然日偏移等额分批；首批偏移必须为 0，最后一批不超过 60 日。初始资本与追加资本可以采用不同的显式偏移。

例如 `[0, 30, 60]` 只是三个预定批次的通用软件向量，不是已为用户选定的投入方式或最优买点。系统不读完价格再选择投入日期，也不根据这两条路径的胜负自动修改配置。

## 资金与收益口径

1. 全部资金在**到账时**进入 NAV、本金和外部现金流；尚未释放的人民币现金仍在组合内，不生息、不供订单使用。
2. 分批释放只减少等待现金、增加可用资金；它不是第二笔入金，不改研究单位，不产生收益，也不代表已经成交。
3. 本研究版本的战略部署基数为 `NAV - 未释放资本`。股票/类别目标与证券容差按此基数计算，原低频引擎的已冻结规则不变；完整组合 NAV 仍用于收益和外部资金流计算。两种资金路径使用相同定义。
4. 每批金额先按现金精度向下取整，最后一批承接余数，所有批次严格等于原到账金额。首版拒绝负数、零金额、不能满足现金精度或小于批次数量的资金，而不替调用者舍入本金。
5. 期末尚未释放的资本仍计入 NAV，未来批次保留并标记在窗口外；不删除这部分本金，也不强迫在最后一天投入无效产品。60 日限制的是资金释放日期，不保证实际研究成交在 60 日内完成；已释放余款仍可能等待后续低频触发。成交完成期限和阻断后的修复/重试还需在后续发布设计中明确。
6. `profit_cny = ending_nav_cny - initial_equity_cny - contributions_cny`。TWR/单位净值回撤不被后续追加本金掩盖；XIRR 使用到账日期，而不是资金释放日期。既有回撤字段为带负号的收益比例。

成本已经通过研究成交影响 NAV，摘要单列佣金、换汇、滑点和现金舍入，展示时不再重复扣除。税费仅覆盖调用者明确提供的成本及公司行动，不因字段存在就认证成本完整。

人民币分红支付后遵守新现金修复规则；外币分红保留原币。待交收股票、出售应收和分红应收跨年延续。新版本继续使用固定数量/预算、决策之后的允许收盘、明确交收和下月到期；分批期限不绕过无效价格、FX、最小交易单位或资金预留。

## 封闭接口

源码：`worker/investor/long_horizon.py`；共享引擎：`worker/research/rotation.py`。

- 输入：`contracts/v1/investor-long-horizon-input.schema.json` / `investor-long-horizon-input-v1`。
- 计划：`investor-long-horizon-plan-v1`，独立连续窗口，最多十个当地日历年；固定低频参数 v2、时区、资金流、决策时点、有限分批、成本和税务覆盖必须显式提供。
- 输出：`contracts/v1/investor-long-horizon-result.schema.json` / `investor-long-horizon-result-v1`。
- 引擎：`continuous-fixed-policy-funding-v1`。原月度、低频阶段接口及旧输出保持原经济口径，不静默变成连续账户。

决策时点须唯一、排序、位于窗口内，不能处于已收盘但尚不可观察的区间。全部计算时点最多到微秒，不能截断更细的时间而提前认定信息已知。参数冻结时间不得晚于窗口开始；这只是输入一致性，不证明参数真的在读历史结果之前登记。日偏移保留当地墙上时间；夏令时/日期跳变导致目标时间不存在或有两个可能时刻时明确拒绝，不猜选一个时刻。

CLI 无数据库、网络、券商、审批或实际订单操作：

```sh
umask 077
python -m worker.investor.long_horizon \
  < "$HOME/.config/etf-workbench/long-horizon-input.json" \
  > "$HOME/.config/etf-workbench/long-horizon-result.json"
```

这是研发接口，普通用户无需制作 JSON。合成输入默认拒绝，测试须显式 `--allow-synthetic`；即使允许测试，输出也不取得真实建议资格。输入最多 16 MiB、输出最多 1 MiB，重复 JSON 键、非有限数、越界输入或过大输出失败，而不静默截断；JSON 载荷和计算错误只返回有限错误码，不回显私人载荷。不要把资料或凭据放入命令行参数。

用户已有可选的[私有投入表单与版本](18-private-planned-funding.md)，可保存计划日期并查看本金/批次；它尚未生成本接口的来源绑定输入或结果，不能由计划表推定连续历史计算已运行。

新增[计划资本的显式历史连接](19-planned-capital-historical-binding.md) 使用独立连续 v2，允许现在登记的策略做过去窗口的回顾性探索，不把登记时间倒填至窗口前。它保留同日起点的两笔资本与各自精确批次，不扩展旧 v1 规则；目前是研发计算，不是来源准入、持久发布或 Web 功能。

输出含两条路径各自的本金、资产、损益、TWR/XIRR、回撤、成本、剩余等待现金、证券单位、执行缺口、固定分批表，以及月/年最后观测快照。快照不是经过认证的精确月末收盘价；没有观测的月份不会插值补造。`unreserved_released_cash_cny` 只表示扣除待投入资本与买入预留后的人民币现金，不包含外币现金或尚未交收出售款。

输入、数据、计划、参数、实现/时区和完整引擎轨迹分别封存哈希，便于按相同原件重算；哈希不是来源、许可、试验独立性或人工批准证明。全部输出固定：

```text
qualification=counterfactual_funding_path_comparison_only
source_independently_verified=false
parameters_independently_preregistered=false
actual_holdings_linked=false
execution_authorized=false
live_advice_eligible=false
```

该输入不是原 `investor-kernel-request` 的新动作；不能将结果直接写入既有参考方案或监测链。算完不代表已选风险、已优化策略、已准入发布或已交易。

## 验证与下一步

专项覆盖十年恒价的连续年度追加、新本金/人民币外汇损失分离、等待现金预算、末批跨窗口、精度余数、当地日及夏令时拒绝、跨年分红/拆分/交收、费用、失效 FX、缺项部署、哈希重算、封闭合同、输出上限和私人错误脱敏。

```sh
python -m unittest tests.investor.test_long_horizon -v
```

完整当前证据与失败记录见 [v2 追踪](v2-implementation-progress.md)。十年恒价向量是两只虚构人民币资产的算术测试，不是三地/多 ETF 十年的规模或性能验收。来源元数据仍不能自证完整日历、分红、无幸存者偏差、产品可买性或留存/使用许可；输入上限也不保证所有数量上限能够同时达到。
