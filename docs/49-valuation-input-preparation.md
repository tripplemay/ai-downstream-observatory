# 估值输入的自动准备

## 目标与使用

进一步减少账户页的重复录入，不将准备建议当作质量批准或交易授权。在“核对估值准备情况与任务”后：

- 从当前用户、当前账本的已审阅日历推导截至共同估值时点的最近完成交易日。包含明确的半日市/休市及当地时区，不推断周末或节假日；同市场多个交易所不一致时不合并猜测。
- 价格来源须完整覆盖该市场的保守历史标的要求、原币、预期交易日和可用时点；汇率须覆盖所有历史所需外币且不超过规则允许的最大范围。多候选不按名称、排序、价格或收益自动选择。
- 唯一完整候选才预填。准备说明引用元数据证据哈希，可自行补充；这不是新的原始材料、公司行动证明或供应商认证。
- 已推导交易日只读，纠错应更新已审阅日历。缺日历时保留明确缺口与原人工核查路径，不用今天日期或行情列表最大日期替代日历。
- 每次仍需选择汇率容忍时效、核查公司行动并明确确认；不从先前答案推断风险或扩大时效，不自动提交。来源为人工声明时继续显著标注其边界。

这是**已有输入的元数据准备**，不是新增自动采集。没有真实已发布行情和审阅日历时仍展示缺口；不为使页面可用而产生价格、分红或默认汇率。

## 证据与生命周期

- 投资者估值读取升级为封闭 `investor-valuation-v2`；会话、所有者、当前关联、工作区/账本版本及原有容量上限不变。准备额外限制读取字节和观察数量，不截断冒充完整覆盖。
- 预选仍经过原来源发布证明和 provider 回执验证。价格观察选择复用既有 Web 估值验证器的时点/并列版本逻辑；不新增 NAV 算法，不向外部 AI 发送行情或账户信息。
- 历史标的的币种也加入 FX 要求，不能因其成本为零或没有外币现金而漏掉持仓汇率。
- 准备结果加入上下文哈希，提交前任何证据变化须重新核对。推导出的日历版本/内容哈希/交易日以可选 `calendar_checks` 写入既有估值规则，随不可变 manifest 留存；旧不带此字段的规则兼容。
- Python 在准备与持久化前重新验证审阅源、审计、版本、当前头和交易日。日历在排队或计算期间变化时，fenced worker 以固定错误码 `VALUATION_CALENDAR_INPUTS_CHANGED` 跳过，不重试旧确认或写部分快照。
- Web 独立核对原知识时点证据；当前重述快照及绩效还复核当前日历头。更新后隐藏失效结果但保留历史；不改写历史收益。As-known 模式保留其原知识时点语义。
- 无迁移，不改资金、持仓、策略选择、执行权限或用户风险资料。

## 验证与边界

专项覆盖真实服务发布的审阅日历、唯一/多来源、半日市/休市、美国 DST、微秒收盘边界、来源与币种缺项、重建数据不作实际价格、超龄汇率、外币零成本持仓、草稿/队列/计算期间更新以及已生成快照失效。所有测试资料明确虚构，不是交易所日历或行情供应商认证。

原生回放在文档 48 的参数后增加 `--with-prepared-valuation`：通过认证 API 发布明确虚构的日历与市场批次，实际表单核验来源、交易日和说明已准备，而 FX 容忍与确认仍为空；真实 core 估值将日历版本/哈希写入结果，再独立复核 NAV。它继续覆盖丢失回执的原请求重试、新事实失效与桌面/390px。

真实数据自动采集、真实研究准入与连续监测、账户级待审/执行报告、完整 Linux/恢复/性能及生产发布仍未验收，不以此局部准备功能宣布完整 v2 已完成。
