# 公司行动交叉核验的只读进度

## 用户价值

工作台不能只告诉用户“证据不足”，却隐藏正在等待什么。本增量在总览和组合方案中，接在持续观察之后展示 EODHD 公司行动交叉核验的最近登记批次；不新增表单、JSON 操作、采集按钮或交易入口。现有按市场的价格任务进度保持独立，不用一个来源代替全部价格、汇率、发行人资料或市场状态。

## 状态和限制

- 区分尚未登记、声明未来生效、停用、到期、声明有效但尚无请求，以及最近一批四个固定请求。
- 每项区分排队、有效租约、租约过期、未知结果、窗口关闭、已保存草稿、传输失败、被关闭和保管期结束。已知失败只展示固定原因，不回传提供方错误原文、路径或凭据。
- 标明最近登记的纽约日期，而不是把历史批次称为“今日行情”。声明生效时间不是任务实际启动时间，有效租约也不是提供方已返回的证明。
- 合成采集有单独标识。正式传输资格也只是原生产者登记的任务元数据；界面不读取原始载荷，不独立证明响应或公司行动完整性。空数组不证明没有事件。
- 元数据快照最多有效 60 秒，并受已知声明和租约等期限进一步约束。到期、后台刷新暂停、网络失败或本机时钟前跳时，收起旧状态并要求重新读取，不在浏览器推测后台成功。

## 工程边界

沿用当前认证且绑定会话的投资者 GET、原有可见页轮询和单调展示时钟；不增加数据来源请求、后台任务、独立轮询、数据库迁移或备份副本。无工作区时不返回私有进度；读取受所有者与数据库一致快照约束。

只核对当前有效声明、必要的历史声明/完整控制审计链、最近登记日期最多四个请求，以及其任务、尝试和回执的封印/归属。活动声明歧义、超出原有千版控制上限或任何完整性异常均显示“暂未通过核对”，不影响独立核验的原研究结论。不会遍历十年原始载荷或全部捕获历史；控制审计使用批量连接，避免逐版本往返查询。

新返回值固定 `task_metadata_not_payload_verification`，提供方在线、公司行动完整性、研究准入及实时建议资格均为 `false`。客户端拒绝额外原文、假造条目、错误日期、超长快照期限、跨快照时间和资格提升；缺少可选新字段的历史客户端夹具仍可读取。工作区、约束、研究、资金、审批、订单和不可变每日槽均为零写入。

## 已打开页面的升级兼容

旧版页面严格拒绝未知响应字段；因此不能无条件向旧 GET 增加 `action_drafts`。新页面仅在原投资者 GET 中显式发送 `X-Workbench-Investor-View: action-drafts-v1`，服务端才读取并返回该进度，且必须有有效会话绑定。缺失或未知版本保持原封闭响应，服务端渲染保留新版进度。响应继续 `private, no-store`，并在 `Vary` 中区分 Cookie 和该版本头；不放宽客户端校验，不改变命令、回执或原有轮询次数。

兼容回归同时运行冻结哈希的真实旧版严格解析器和新版解析器，核对新旧响应共有资料相同、零 SQL 变更，以及认证、会话切换和查询边界。真实认证 HTTP 和实际工作台刷新测试分别验证服务端协商和新版手动/后台 GET；这不代表真实来源或生产界面已验收。

## 验收

使用真实应用生产者和完全虚构的传输构造未来授权、排队、有效/过期租约、未知尝试、部分/全部草稿、失败、历史声明与十年保管到期。独立 Web 读取、会话客户端、无原文查询、金融零写入、移动布局及离线到期分别核验。

这些软件证据不等于真实 API 可用、公司行动审阅、持续监测完成、策略盈利或生产发布。真实采集仍仅由已有明确授权和原单次租约调度执行，未知请求不因查看或刷新而重试。
