# 无新增公司行动的有界续接

当前状态：有界续接已发布，既定两组来源已按明确授权启用。实际原文的 Python 与独立 Web
重放、普通页面/旧客户端兼容及手机展示已验收；不因此宣称当前行情、完整持续监测或完整 v2 已完成。
新增事件的明确审阅接续另见[研发中的文档 81](81-reviewed-action-recovery.md)，不属于本规则的自动批准权限。

## 规则及边界

本规则需要独立、明确的所有者授权，不能由此前“只采集草稿”的许可推导。
它只接受选定两源的报告范围作为研究覆盖假设，不保证实际不存在其他行动。

- 绑定原有人工审阅、证券身份、三份锚定资料及其来源声明/控制。
- Vanguard 与人工审阅在重叠范围内的分配金额、支付日期，以及已审阅拆分比例必须精确一致。
- 可登记既有 EODHD 名义金额差异；其他日期、币种、缺失和歧义不作为可接受旧差异。
- 当前解析记录在重叠范围必须与锚定记录精确相同；不舍入、不应用接受容差。
- 两源均未报告人工审阅截止日之后的行动，且滚动窗口覆盖全部待续接区间，才可续接。
  发行人报告了另一源截止日之后的事件，也必须停止，不能用日期交集将其隐藏。
- 只改变覆盖截止日；原有事件、金额、税务假设、起始日及证据引用保持原样。
  不改变投资参数、资金、真实持仓、费用或交易权限，也不向 AI 发送原文。

规则有效期不得超过原人工审阅、身份、来源声明和原文保管期限。
既有研究或模型本身的期限不因此延长。当前实现仅支持既有固定请求映射，不能据此宣称覆盖其他证券或市场。

## 后台行为

登记默认停用。启用之后，只有 core 角色可派生；行情采集角色和 verifier 不发布续接。
纽约时间 01:00 后，每条规则、每个当地日期最多登记一个本地意图。
夏令时重复小时和暂停/恢复不重置当日意图，没有新增网络请求、凭据读取或未知结果重试。

后台只消费已有采集流程留下的资料。正常排队或执行中的资料先等待；
已知采集失败、意图窗口错过、新事件、更正、记录缺失或其他差异停止续接，并保留待复核状态。
普通暂停/恢复不能清除已登记的阻断；新事件需要新的明确审阅，不由本规则批准。

完整原文解析和比较在延迟读事务中准备，随后在短写事务中复核原审阅、来源控制、
原文字节及发布头。意图、发布、来源元数据和审计均不可变；失败回滚不留下半份发布。
替换别名单独防护，不能用 `INSERT OR REPLACE` 擦除旧控制、重置当日意图或覆盖前一日发布；
已有人工作出审阅的来源也不能被改作派生来源。
恢复锁、只读模式和停止边界继续生效。没有跨调用的许可缓存。

## 历史和当前来源

迁移 53 仅追加独立规则、控制、意图、发布表及读取视图，不重建原人工审阅表，
不改其行、rowid、人工审阅标记或旧迁移。

派生记录采用 `managed-actions-review:` 标识及 `investor-data-review-v2`，
明确标记 `owner_standing_no_new_actions_rule`，不冒充当天逐条人工审阅。
每次正式解析从原审阅和原文重新验证后，重建只改变截止日的虚拟事实。
日发布仅保存引用、哈希和覆盖日期，不重复保存整份历史金额与税务文本。

`investor_review_headers` 是兼容元数据视图；派生行的 `document_json` 故意为空。
消费者必须通过合格解析器重建，不能把视图、检查摘要或哈希相等直接当作研究准入。
元数据检查和正式原文重放分别实现，保管到期后仍能核验历史头部；
正常来源失效时隐藏派生结果，但不由新规则的停用去改写原人工历史方案。

当前监测只允许最新、有效且明确关联的发布替代其绑定的原审阅或同规则旧发布。
无关的重叠资料继续保持歧义，不以“时间最新”自动选中。
规则阻断不得回退到其较早人工覆盖，冒充当前资料；其他证券的规则不污染本证券的选择。

规则暂停后恢复时，旧控制版本的输入仍然失效。只有同一规则在当前控制版本下产生了
新的、经过完整原文重放的合格发布，且原有经济事实精确一致，才可把旧输入的已审计引用
作为重建意图。旧输入不返回当前价格或估值；全部替换窗口必须重新通过价格、汇率、
身份、用途、成本和模型准入，随后登记新输入，保留旧记录及其失效状态。
这个恢复分支仅供 core 的来源刷新使用，不能用于监听请求、直接估值或清除阻断；
缺少新发布、不同规则、来源撤回、期限已到或模型停用仍停止，不增加提供方请求。

## 高级运营入口

普通投资者不需要填写内部标识。运营入口沿用仓库外私有文件和目录权限检查：

```sh
python -m worker.investor.data_pipeline \
  --db /private/data/workbench.db --workspace WORKSPACE --actor OWNER \
  preview-action-maintenance \
  --base-review ORIGINAL_ACTION_REVIEW --listing-review LISTING_REVIEW \
  --issuer-capture ISSUER_CAPTURE --dividend-capture DIVIDEND_CAPTURE \
  --split-capture SPLIT_CAPTURE
```

`preview-action-maintenance` 和 `inspect-action-maintenance --authority AUTHORITY` 使用真正只读连接，
不登记意图、不发布、不调用来源。预览只返回绑定、计数和最大期限，不输出金额、税务或原文。

`register-action-maintenance --file /private/policy.json` 核验封闭声明后默认停用；
`control-action-maintenance --authority AUTHORITY --enable` 或 `--disable` 只变更该规则控制。
这些命令没有任意端点、测试资料、调用方时钟或强制清除阻断参数，亦不直接发布。
检查输出只证明审计元数据，不证明整套当前行情、策略或交易资格。

## 普通工作台状态

工作台以每只 ETF 一条状态展示“已登记覆盖续接”“等待资料”“需要复核”，
采集任务收进可展开详情。异常、停用和过期时仍可看到明确标注的历史覆盖日期，
但不把它当作当前行情、研究准入或整个组合资料齐备。只列出本工作区已登记的固定 VT/BND 规则。

该视图只读取所有者、规则/控制/意图/发布审计及绑定来源的许可、保管和清理元数据，
不读取原人工事实或来源载荷，不解析原文、写入数据库、调用提供方或重置任务。
研究消费仍由独立原文重放决定，不能将元数据状态提升为通过资格认证。
新事件、更正及错过意图期限均显示待复核；暂停/恢复不能清除已经登记的阻断。

状态快照最多 60 秒，并受已知规则/来源期限截断。即使编辑锁阻止后台刷新，
本地单调显示时钟也会隐藏过期状态；系统时钟回拨和失败刷新不能复活旧结论。

普通页 SSR 显式读取该可选视图，后续 GET 使用 `X-Workbench-Investor-View: action-drafts-v2`。
旧 `action-drafts-v1` 仅返回原草稿字段；缺失或未知版本仍保留原封闭响应。
新可选字段不进入命令回执，协商请求仍须有效会话绑定，响应继续为私有、不缓存并声明 `Vary`。
冻结的两代旧严格客户端均保留哈希断言，不通过放宽旧解析器来迁就新字段。
