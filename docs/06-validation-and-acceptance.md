# ETF 投资工作台：策略验证与产品验收标准

版本：v1.1 | 日期：2026-09-12 | 状态：公开验证与验收规格

依据：[01 投资约束模板](01-investment-mandate.md)、[02 产品需求](02-product-requirements.md)、[03 决策治理](03-decision-policy.md)；计算真值见[04 数据与核算](04-data-and-accounting.md)，架构、迁移及性能预算见[05 架构与迁移](05-architecture-and-migration.md)。

本文是通用验证与验收规范，不是通过报告或个人批准记录。样例使用明确的合成输入，不代表个人资金安排；产品测试、压力测试、恢复和策略验证须分别保留执行证据。采用本规范不补齐投资未决项，也不替代策略准入或部署签核。

## 1. 两条验收线和四级放行

**工程正确性不等于投资有效性；投资历史表现良好也不能豁免工程错误。**

| 等级 | 允许的使用方式 | 必须通过的条件 | 不代表什么 |
|---|---|---|---|
| L-0 文档基线 | 作为开发和研究依据 | 需求、核算、治理及未决项一致，用户确认相应文档 | 不代表功能已开发 |
| L-1 账本与观察 | 导入实际事实、对账、展示合格范围内的资产与历史 | 账本/数据/安全/恢复工程测试、对应账户对账和用户操作验收 | 不允许有效实盘投资建议 |
| L-2 研究与模拟 | 使用经过验证的数据管线开展研究及前向模拟 | L-1共用基础合格，模拟隔离、执行时序、数据来源和实验可重放 | 不代表策略值得分配真实资金 |
| L-3 实盘建议 | 在预算内产生分账户待确认清单 | 全部适用工程测试通过，03文档G-01至G-04通过，策略证据与政策批准，用户明确启用 | 不自动向券商下单，不保证盈利 |

可以按L-1/L-2先提供受限能力，但必须显示模式，不能暗藏可绕过的L-3入口。L-1允许授权导入和更正事实，不是数据库只读模式；故障恢复时的只读模式另行禁止所有写入。用户确认文档或代码通过CI均不自动升级使用等级。

当前状态：第一轮与第二轮共六份文档均为v1.0已确认设计基线，完成L-0文档确认；尚不能据此宣布任何新增L-1/L-2/L-3能力通过。

## 2. 测试环境、证据和状态

### 2.1 环境隔离

- 单元测试使用内存数据库或临时目录、固定时钟、固定汇率/行情和合成账户。
- 集成测试使用独立`test`数据库，禁用真实邮件与AI收费调用；外部故障通过可控mock注入。
- 端到端与性能测试在专用staging执行，不连接真实券商或写生产库。
- 迁移先使用旧schema合成样本及隔离副本；生产切换前再经批准使用实际生产备份演练。
- 验证文件、原件和结果按来源/版本分离；真实账户资料不得入Git或外部AI。
- 每次验收绑定release SHA、schema、依赖锁、环境配置、fixture哈希、固定种子和测试时钟。

### 2.2 证据包

建议目录形态为`artifacts/acceptance/<run-id>/`，属于将来生成的工件，本轮未创建或运行测试程序。

证据至少包括：manifest、用例清单及状态、命令/入口、退出码、脱敏日志、预期与实际差异、数据库校验、截图、性能统计、恢复报告、缺陷及签核记录。没有证据的口头“正常”不计为通过。

状态只能为：`NOT_RUN`、`PASS`、`FAIL`、`BLOCKED`、`NOT_APPLICABLE`。`NOT_APPLICABLE`需写出理由与批准范围；数据不足或服务不可达属于阻塞，不能算跳过后全通过。

### 2.3 误差标准

- 事实分录、数量、幂等计数和金标准已给定的十进制金额：在规定确认量子上精确一致；不接受累计浮点漂移。
- 金额展示与来源核对：只允许已解释且按ACC-04规则产生的舍入，不能容许每行任意一分钱误差累积。
- 合成TWR/Dietz/回撤/FX收益率：绝对误差不超过`1e-10`，比较的是比例值而非百分数文本。
- F-09单根XIRR：利率绝对误差不超过`1e-8`且净现值残差不超过0.01人民币元；同时满足，不只判断收敛标志。
- F-10多根必须返回歧义及可复核的根信息；NaN、Infinity或失败时0%一律失败。
- 大规模统计与性能另设容差，不得用统计容差放宽真实账本一致性。

### 3.1 属性与随机序列测试

在固定种子下生成入金、买卖、结算、转账、更正和公司行动序列，至少验证：

- 每事件每币种分录平衡，数量变动能追溯；没有授权卖空时不能发布导致负可卖数量的清单。
- 重放投影等于增量投影；打乱获取顺序但保留事实顺序，重述结果一致。
- 幂等重试不增加分录；更正后原记录可查。
- 净资产与净投入、损益关系成立；无费用同价买卖/结算不制造盈利。
- 每个账户的现金与预留约束成立；跨账户内部转账对总组合净投入为零。

跨语言计算对同一fixture运行十进制参考实现，比较逐步结果；不能只用最终四舍五入后的展示值判断一致。

### 4.1 端到端人工场景

按真实使用次序走通：开户资料 -> 初始事实 -> 追加到账 -> 估值 -> 目标建议 -> 复核 -> 批准 -> 用户报告下单 -> 部分成交 -> 导入/对账 -> 剩余建议 -> 月度归因。

在合成多券商、多市场账户上演练，不绑定个人交易渠道，不要求也不使用真实下单。桌面与移动端至少覆盖1440×900和390×844：金额不截断、币种/日期/质量可见、确认按钮状态正确、键盘可操作、错误原因可读。技术接口通过不能替代这些人工检查。

## 5. 性能、可靠性与恢复验证

目标值以05文档第8节为准，结果报告必须同时写环境与实际数据量，不把本机快速返回泛化为生产性能。

### 5.1 测量方案

- 准备10账户、1,000证券、200万行情记录、5万账本事件的确定性数据集。
- 同时运行后台市场批次发布、估值、前台查询及批准/小批记账，检验SQLite竞争。
- 核心查询和原子命令分别至少记录1,000次样本；区分冷启动与稳定运行，报告p50/p95/p99、错误率、锁等待及资源占用。
- 页面查询服务端p95目标2秒以内，原子命令p95目标1秒以内；1万行导入预览及确认后台完成目标60秒以内。
- 正确性错误数必须为0；失败重试不能因最后成功而从错误统计中消失。
- 重回测走后台，浏览器可查询状态；测试取消、超时和重启后结果是否残留为假成功。

### 5.2 故障注入

依次在事务提交前、提交后响应前、任务发布前、通知发送后等位置中断进程；固定相同幂等键重试。预期只有完整提交或完全不提交，不出现半组分录、重复批准或超额预留。

注入数据库锁、磁盘满、损坏的输入文件、数据源延迟、AI超时及备份目的地不可达；验证分级失败和显式阻断，不能无声回落到新空数据库。

### 5.3 恢复演练

1. 记录基准账本head和持续生成的合成事实，完成带附件manifest的备份。
2. 在隔离环境模拟主机丢失，从异机副本恢复到全新环境，密钥按实际恢复方案取得。
3. 验证schema、DB一致性、附件哈希、金额/数量、批准和未完成执行状态。
4. 根据券商合成事实重放备份之后的流水并对账，无法确认的区间维持阻断。
5. 测量实际恢复点与故障时点之差、恢复到可用只读状态的时长及完成对账的时长。
6. 目标RPO不超过15分钟、RTO不超过2小时；超过目标为失败或设计待调整，不以手工找回部分文件代替成功。

至少在每次重大schema迁移前进行一次完整演练。策略重启不能自动恢复未经复核的实盘建议模式。

## 6. 策略研究与有效性验证

本节规定研究证据结构；具体ETF、风险预算、收益目标、基准和准入阈值仍待D-01/D-02/D-03/D-06批准。不能把工程目标数字当成投资风险授权。

### 6.1 预注册实验计划

在观察最终测试结果前保存：

- 经济假设、预期收益来源、适用市场、反证与可能失效环境。
- 候选标的范围和历史可买规则，价格/公司行动口径。
- 参数搜索空间、搜索预算、选择方法和所有尝试的保存方式。
- 训练/验证/最终测试区间、滚动验证安排及最终测试解封规则。
- 决策和成交时点、市场日历、缺价/停牌处理、整手、费用和资金约束。
- 对照基准、现金收益假设、资金流、换汇与成本情景。
- 主要评价指标、风险约束、证据量要求与接受/拒绝条件。
- 前向模拟起点、冻结版本、最短观察期、有效评估/调仓次数及复审规则。

所有必填项必须有明确值和批准记录才进入正式准入评估；未填时可探索研究，但报告标为探索性，不得事后补一套刚好让结果通过的阈值。

### 6.2 验证门槛

| 编号 | 门槛 | 最低证据要求 | 不满足时 |
|---|---|---|---|
| S-01 | 数据可信 | 来源、许可/使用范围、历史可获得时间、退市/上市及修订处理明确 | 限探索，不能形成正式绩效证据 |
| S-02 | 实现正确 | E-10/E-11/E-12/E-18/E-22/E-28等适用测试通过；收益与执行可复放 | 结果无效，先修实现 |
| S-03 | 实验纪律 | 预注册计划、搜索记录、未提前查看的测试集及解封记录 | 结果只能标为样本内/已污染 |
| S-04 | 样本外与稳健性 | 多时段或滚动窗口；参数邻域、费用、延迟、缺失数据敏感性 | 保持研究或拒绝，不能只报最优参数 |
| S-05 | 公平基准 | 同币种、同资金流、可执行成本；被动配置及简单策略对照 | 不宣称超额价值 |
| S-06 | 收益风险约束 | 达到预先批准的收益/风险/证据量条件，同时报告回撤和修复 | 不分配实盘预算 |
| S-07 | 前向模拟 | 冻结规则、实时形成决策、真实摩擦、失败与漏执行记录；达到批准观察量 | 不用回填历史冒充前向模拟 |
| S-08 | 实施能力 | 账户可买、数据稳定、资金路径/币种/结算与实际费用可支持 | 不能产生对应账户实盘建议 |
| S-09 | AI增益 | 如依赖AI，完成有/无AI同条件对照与事实质量检查 | 不把AI作为必要放行环节或收益来源声明 |
| S-10 | 人工准入 | 策略版本、证据包、有限资金预算、启停条件和批准人明确 | 保持待批准，不自动升级 |

样本长度、交易数量和模拟时长不能由一个全局常数替所有策略决定。按策略频率及所需市场情景在预注册计划中明确；几次月度调仓即使盈利也不能自动声称统计充分。若样本量不足以支持结论，记录“不足”，而不是降门槛。

### 6.3 必须比较的情景

- 一次投入、分批投入和受约束择时：统一真实到账时点，包含等待现金，不能给分批方案偷偷延后资金起点。
- 原始成本、较高成本和较差成交延迟，禁止只报告零摩擦结果。
- 资产上涨、下跌、震荡及不同相关性阶段；定义选择规则，避免事后挑有利区间。
- 不同参数邻域和候选范围，报告策略是否只在单一参数上有效。
- 不同市场休市、时区和交易日，基金新上市/退出、暂停交易、数据中断。
- 基准固定配置、简单趋势/轮动对照和不加AI版本；对照也须通过收益正确性检查。

跨市场研究必须保证：在A股决策时点不能使用尚未发生的美股收盘价；同一自然日不是数据同时可得的证明。

### 6.4 报告必须公开的结果

累计/年化净收益及实际区间、TWR或估算方法、同资金流XIRR、最大回撤、修复时间、现金占比、换手、费用、超额收益、滚动窗口分布、失败窗口、所有被搜索版本和参数敏感性。

同时记录覆盖不足、幸存者偏差、收益修订及未计税费。若采用置信区间或显著性检验，写清方法、时间序列相关性处理和多重搜索影响，不能仅显示“胜率高”或AI评分。

相对基准的超额表现只是其中一项，不自动证明风险可接受；单次高收益或低回撤不构成持续盈利保证。

## 7. AI质量与权限验收

AI只生成研究意见，不具备交易授权。采用固定案例集和预留案例集，包括正常行情、证据冲突、缺数据、陈旧资料、不可达来源、提示注入及真实账本脱敏样例。

| 维度 | 验收要求 |
|---|---|
| 权限 | 对抗用例中越权账本写入、政策激活、批准和秘密访问次数为0 |
| 结构 | 无效输出可识别并进入失败/降级路径，不能经宽松解析误当通过 |
| 来源 | 每条用于决策的事实能找到支持它的来源和日期；虚构来源不能发布为已证实 |
| 时效 | 陈旧或未知日期被标注，不能冒充当前基金/市场状态 |
| 推理边界 | 事实、推断、建议、反证和缺口区分；模型置信度不显示为统计概率 |
| 一致性 | 同一模型/提示词/数据版本可定位；生成差异被记录，系统安全不依赖文本完全复现 |
| 增益 | 和仅策略版本比较，说明AI是减少错误、提高可解释性还是改变建议；没有证据不宣称增厚收益 |
| 人工复核 | 对固定及预留案例逐项审阅来源支持度和遗漏，保留分歧与修正记录 |

模型或提示词升级重新执行回归，不能仅因供应商说性能更好就替换生效依赖。模型不可用时遵守已批准降级策略；依赖它的强制复核不能被默认通过。

## 9. 缺陷等级、发布与签核

### 9.1 缺陷等级

- **B0 阻断**：账本损坏/漏记/重复、资产或收益严重失真、前视偏差、越权、秘密泄露、丢失新成交的回滚、可能错误执行的资金/状态问题。
- **B1 高**：关键数据质量不可见、任务假成功、策略/页面口径不一致、核心对账或恢复路径不可用。
- **B2 中**：不改变决策含义的非核心流程缺陷或明显性能问题。
- **B3 低**：纯视觉/文案问题，不遮蔽金额、币种、风险及状态。

任何影响拟放行等级的B0/B1未解决，不予放行。B2/B3须明确影响、期限和接受人；不能把缺失的正确性测试降级为文案问题。

### 9.2 工程发布门槛

1. 对应等级全部适用用例已执行且通过；关键BLOCKED/NOT_RUN不能以总通过率掩盖。
2. 核算金标准、并发幂等、权限、迁移、恢复、前视回归不允许例外豁免。
3. 在目标版本完成TypeScript/Python检查、构建、依赖安全与镜像秘密检查。
4. 实际生产备份副本迁移演练及必要人工界面验收通过。
5. 明确备份点、回滚边界、待办和运行模式，用户单独批准部署。
6. 上线后检查schema/服务/任务/数据质量/账本对账；健康接口200不等于业务验收完成。

### 9.3 策略放行门槛

对应工程等级已满足，S-01至S-10逐项有证据；所有适用未决项获批，01/03政策版本生效。准入单写明预算、版本、启用范围、复审和退出条件，用户签核后才启用L-3。回测盈利、AI认可或测试通过不自动替代这一步。

### 9.4 验收报告模板

```text
验收ID / 日期 / release SHA / schema / 运行模式
环境及数据manifest / 测试时钟 / 工具与依赖版本
目标放行等级 / 适用需求和用例范围
PASS / FAIL / BLOCKED / NOT_RUN / NOT_APPLICABLE 各清单
核算差异 / 对账结果 / 风险与数据质量 / 工程性能
策略证据与基准 / AI质检 / 未决项及限制
缺陷等级与处理 / 备份恢复及回滚证据
结论：拒绝 / 仅允许受限模式 / 允许指定范围
工程复核人 / 投资批准人 / 部署批准人及时间
```

一人可以承担多个角色，但确认记录和责任范围仍应分开。

## 10. 规格与执行状态的区分
