# 投资者策略与模型计算内核

这不是交易服务，也不是行情来源认证器。纯计算内核不打开账户数据库、不读取凭据、不连接券商、不生成订单。它读取执行代码与时区文件以固定重现标识；金融输入从内存或标准输入传入。`runtime.py`、`model_runtime.py`、`trials.py` 是独立的工作区任务与审计层，只写研究状态和任务租约，不写真实金融事实。独立的 `data_pipeline.py` 是私有运维入口，明确审阅后可读官方行情并保留受限 SDK 投影，不继承纯计算内核的无网络/无凭据边界。

## 两条计算路径

- `strategy.research_reference`：有限、预先冻结的固定配置候选；简单基准必须同时是可选择候选。复用原研究引擎的日历、原始价格、公司行动、交收、TWR 与佣金/换汇/滑点计算。训练期按扣费后单位净值年化回报、回撤、换手、哈希稳定排序；声明的试验预算不能被突破。
- 风险未知只输出训练期比较与假设性角色冲击，不选定权重，不打开验证或保留期。风险确认后只验证训练期冻结的同一候选；候选或基准计算失败、风险不满足时阻断，不改选另一个更好看的样本外结果。
- `monitor.assess_model`：模型单位与现金、有效收盘、FX、目标和计划投入分开。每个市场核对自己的预期已完成收盘，不要求三地相同交易日期；过期、未来未知、缺口不能得出“无需调整”。
- 新投入仍是假设。先按低配缺口分配新资金与模型现金，预留估算费用，不卖出高配资产；资金不足时明确保留剩余偏离。无新投入时只研究超阈值变化。费用占比阈值的分母是加入计划资金后的假设模型 NAV，不是实际账户资产。
- 成本包含声明的佣金、最低费用、滑点与外币换汇假设。单位、可交易性、真实资金、交收、税务、账户权限尚未核验，所有输出均非可执行篮子。`model_state.advance_model` 可推进独立观察单位与企业行动，当前只有合成快照适配器，不是已验证的真实收益生产者。

## 合同与边界

`contracts/v1/investor-*.schema.json` 固定输入和输出形状。结果包含输入哈希、执行实现/时区标识、结果哈希及明确的 `live_advice_eligible: false`。这些哈希是重现标识，不是来源、数据许可、未看过保留期或投资适用性的证明。保留期独立未曝光状态仍为 `not_independently_verified`。

服务端消费合同在 `web/src/server/investor/kernel-contracts.ts`。它检查请求绑定、时间、模型 NAV、资金修复及缺口，转换为现有观察合同和变化卡；本身不发布结果或启用调度。无法精确转换为应用毫秒时点时拒绝，不四舍五入未来证据。输入超过微秒精度时也拒绝，不让 Python 时间解析静默截断。

`before_plan_hash` / `after_plan_hash` 应绑定独立、不可变的目标定义版本，不能绑定包含本次 `input_version` 的最终展示快照，否则会形成哈希循环。发布生产者还须独立核验目标版本、模型检查点、当前 profile、来源收据、产品身份、日历、行动覆盖、留存许可和任务租约。

## CLI

`python -m worker.investor` 仅从标准输入读取 `investor-kernel-request-v1` 形状的 JSON，标准输出返回结果；重复 JSON 键、非有限值、递归异常、超过 16 MiB 输入或 1 MiB 输出均拒绝。错误只返回代码，不回显私人输入。

研究输入默认拒绝合成数据。`--allow-synthetic` 仅用于明确的测试/探索，不能将结果升级为实时参考、实际持仓或投资建议。模型计算接口同样只提供算术，不能靠填入哈希或来源文字获得来源认证。

`python -m worker.investor.funded_history` 提供计划资本到明确过去窗口的连续计算；整年平移日期、逐笔保留本金/批次，以独立连续 v2 保留当前参数记录与比较登记声明，不把它倒填为历史预注册。直接 v2 计算须显式 `python -m worker.investor.long_horizon --retrospective`；旧 v1 不放宽。同日起点两笔资本按各自批次释放，期外批次保留。这些入口均无 DB/网络/凭据/发布。原 Node 绑定函数仍不认证经济结果；新增独立纯经济重放核对全部派生字段，但不认证原不透明轨迹摘要、来源或策略资格。详见 [历史连接边界](../../docs/19-planned-capital-historical-binding.md)。

## 私有数据证据链

迁移 29 的来源、审阅、采集收据与可逻辑删除的独立投影载荷由 `data_evidence.py` 处理；`data_snapshot.py` 从全部保留引用只读重建历史。官方历史下载仍为 `reconstructed`，不会伪造 provider `published_at`；日历和 FX 的假设可用时点单独参与研究决策可见性。模拟采集默认拒绝，内部显式测试只得到 synthetic，不能与官方块混合。

`python -m worker.investor.data_pipeline` 提供 store/review/collect/check/admit/purge 的后台高级操作，使用仓库外私有文件并只输出摘要。迁移 30 的 `source_inputs.py` 准入只保存引用和有限设计，不复制价格；相同来源/设计复用，自动为当前偏好入队。它不是用户必做的初始化流程。许可记录仍是所有者审阅而非数据商认证；默认 core 已有下述有界载荷维护，WAL/备份/全部下游和生产留存治理仍缺。具体参数和验证边界见 [私有研究数据链路](../../docs/14-private-research-data-pipeline.md)。

历史/监测快照在单次重建内复用相同事实的纯校验，最多 128 个摘要，离开作用域即释放；不缓存来源、审计、最新审阅或价格载荷，每次读取仍核对完整绑定。五年虚构资料的全输出对照和复跑入口见[文档 50](../../docs/50-research-source-validation-reuse.md)；局部提速不是 VPS 性能或研究资格验收，也未降低 900 秒核心租约。

`source_retention.py` 在 core 发现新任务前，以一个共享 1–1000 条预算清理到期/rights 失效的行情 BLOB，以及到期/来源失效的监测检查点与运行 BLOB。来源判断包含原研究及全部检查点祖先；未到期清理核对审计/哈希/范围，不读取凭据或重放价格。每项收据/审计/删除原子提交，可跨连接重复调用；停止/后续失败保留先前成功项，恢复锁和 read-only 阻止清理。它不更新工作区 revision、不新增观察/outbox/jobs、不动真实金融事实，不影响独立资金比较/AI 清理器。仅删除活动 SQLite 行，不保证 SQL 扫描硬上限、停机时及时删除、WAL/备份/介质擦除或已完成生产验收。

## 后台研究队列

`investor_funded_study` 是独立的私有计划资金比较任务：认证动作冻结当前偏好、投入版本、来源引用和真实登记时间；默认 core 处理全部低频 v2 候选，两条资金路径共享输入条件。迁移 36 的运行继续只保存计算哈希/失败元数据及 false 资格；迁移 37 在同一受控提交中限期留存派生结果 BLOB。Web 专用认证只读请求重建当前输入，再由固定 Node 子进程独立重放后显示历史汇总，不选择个人权重、不取得参考方案或交易资格。恢复锁、来源/资金/偏好/实现变化、租约和 provider 角色隔离均保留。

`funded_result_retention.py` 由 core 发现循环按批处理到期或来源失效结果，只删除派生 BLOB 并保留所有者审计/摘要。GET 不做清理或续租，来源失效先隐藏结果；没有承诺停止 core 后及时清理或擦除 WAL/备份/介质。详见 [私有长期比较](../../docs/20-private-funded-comparison.md)。

迁移 26 新增不可变研究输入、请求与结果；保存偏好或检查条件时，服务器冻结 profile、输入和引擎版本。相同输入去重，读取状态不会入队。请求使用独立工作区作用域，复用已有 `job_runs` 租约/attempt/fencing，不创建占位真实 portfolio 或账户，也不允许普通 `command_requests` 冒充研究任务。

核心 worker 自动发现并执行 `investor_research`。计算在写事务外，提交在租约栅栏内；发布前重查最新 profile、输入和执行源码版本。已变更任务跳过，不覆盖新约束；恢复锁和失效租约阻止结果、观察和 revision 的整个提交。发布完成推进研究工作区 revision，旧客户端必须读取最新状态再保存。公开日志只用固定错误码，不回显验证失败的私人输入。

`register_synthetic_input` 只允许 `synthetic`，生产 core 默认不计算它。`admit_evidence_input` 只解引用已审阅来源和官方采集收据，接受 `reconstructed` 研究设计，默认 core 可计算；模拟采集不能由设计 JSON 改标进入。无合格输入时完成明确缺口。风险明确且冻结候选通过全部阶段时，可生成可保存的探索历史参考方案；没有有效监测输入时观察仍为证据不足。未知风险和合成分支不自动生成该方案。当前全部验证是虚构资料与模拟官方传输，不证明真实数据已准入。

网页展示任务排队/计算/重试/阻断/失败/过时状态，在可见页等待任务时只读轮询；合成候选标为软件测试，重建候选另列来源边界、历史区间与有效期。Node 从保留收据独立重放历史并核对哈希，不采集或计算策略。正常来源失效隐藏旧权重，不影响保存偏好；证据损坏仍固定报错。历史研究候选不是实际持仓，不是风险授权或已通过真实研究资格的方案。

后台研究已接入下述阶段进度和合作式心跳；这不证明真实全规模研究性能。真实适用来源、多年覆盖、真实来源上的方案发布验收、真实监测结论及独立保留期资格仍待完成。原临时浏览器 fixture 的 `computed-observe`、`computed-decision`、`computed-stale` 也仍仅允许空临时库，不可运行于生产目录。

## 探索历史参考方案

迁移 31 的不可变证据链接将方案与工作区、请求/运行、准入输入及结果哈希绑定。`reference_plan.py` 只渲染已冻结结果，不重选权重或代填风险；方案、链接、运行、观察及 revision 在同一租约栅栏事务提交。阶段试验审计独立保留，最终失败不删除曝光。共享 `investor-reference-plan.schema.json` 要求 reconstructed 方案携带封闭证据，不允许实时建议或独立样本外资格声明。

Node 的 `reference-evidence.ts` 独立核对当前来源、已成功默认研究作业与试验，再完整重建权重及解释并比较哈希。读取不重新计算策略；来源失效隐藏旧权重、拒绝保存/恢复，不删除历史证据。保存只登记独立观察模型，不建账户、不批准策略、不成交。reconstructed 模型不能使用合成快照；收据投影监测已接入下述默认 core，真实来源验收与自动采集仍未完成，缺输入时继续阻断。

## 试验登记与阶段续租

迁移 28 追加不可变实验、阶段意图、阶段结果与训练期候选冻结。实验固定请求/profile、数据、计划、策略、实现、窗口、候选、基准和有效预算；本版有效预算为每个训练候选各一次、验证一次、保留期一次，不扩大上游声明的预算。阶段意图在读取评估窗口前以短事务提交；其存在即保守地记录曝光，崩溃或最终结果发布失败不能删除它。

未知风险只登记训练期试验，不冻结、不读取验证或保留期。已确认风险时，冻结证据包含全部训练结果哈希；登记器独立重算训练期排序，只允许同一候选进入后期。重试沿用同一实验和阶段意图，复用已封存的阶段结果，不增加调参次数；未完成阶段才重新计算。新实现需要新实验，不会重写旧冻结。

曝光按本地试验窗口重叠保守检查，而非仅按数据/计划哈希；改标签、产品列表或快照值不能清除已登记的重叠窗口。发布收据固定曝光查询水位，后续试验不改写历史收据。该覆盖仅为 `local_investor_trials_only`，不包括旧研究登记器、人工查看、工具外试验或独立保管证明。内核的 `holdout_unseen_status` 仍为 `not_independently_verified`；本地发现重叠时额外展示 `previously_exposed`，没有“独立验证通过”的升级路径。

阶段边界与回测执行时点循环进行合作式续租、停止和当前来源检查；陈旧租约或失效来源不能写阶段结果。测试推进时钟使计算超过原租约，证明续租后可提交；跳过续租或中途撤回仅保留意图、拒绝结果。不可中断的输入校验/指标计算、真实数据规模的响应时间和停止延迟仍需性能验收，不能由短 fixture 推定。登记器支持 synthetic 和 owner-reviewed reconstructed；迁移 30 保留旧实验及 trial rowid，包括水位空洞，不重写历史曝光。生产默认缺口检查不登记合成实验。

Node 从保留输入、实验、意图、阶段结果和冻结证据重新核对发布收据与候选排序；只有自洽的输出哈希不足以绕过已封存结果。GET 可显示进行中的阶段计数，但不执行试验、不续租。试验审计与最后的观察/研究 revision 原子发布分开，故未发布的失败尝试仍保留研究曝光，不成为成功结论或资金事实。

## 连续观察模型

迁移 27 追加模型定义、控制版本、快照、检查点、监测请求与运行记录。保存参考方案登记独立模型，不建真实账户；相同方案复用模型，不重复初始化。暂停/恢复只增加控制版本，不改写历史模型，也不下单。GET 不入队；网页的只读刷新不等于重新研究。

模型归一化起点固定为 10,000 CNY，按观察开始时价格建立分数单位，不使用个人预算，也不模拟开仓、交易单位和交收。它跟踪观察中的单位，不自动执行计划资金、再平衡建议或采纳意见。因此展示的是估值，不是个人资产、策略成交净值或扣费后收益率。

未复权价格与企业行动分离：拆分改变单位；除息建立净额应收，支付时从应收转为相应币种现金。外币现金和未到账应收参与估值，但不充当可直接分配的人民币现金。权益保留已支付标记，重复事件不重复入账；历史修订、覆盖断档、行情/FX 陈旧和未知权益阻断，不悄悄改写既有检查点。

core 发现独立 `investor_monitor` 任务，按 15 分钟窗口或新快照/控制版本去重。检查点推进本身不触发同一窗口的无限重算。无输入时检查一次并等待输入变化；暂停、切换方案或修改偏好使旧任务失效。计算在事务外；检查点、运行、观察和工作区 revision 在租约栅栏内原子提交，恢复锁不能留下部分结果。价格更新不能续期旧策略，原方案过期后需重新研究。

输入适配器 `register_synthetic_snapshot` 仅用于合成数据，生产 core 默认不计算它。测试开关不在生产 worker CLI 暴露；隔离计算的估值可以展示为软件测试，但应用观察仍为 `insufficient_evidence`、`monitoring=not_enabled`。Node 同时核对保留快照、目标定义、模型单位、现金、应收估值和计算结果，而非仅接受一组自洽哈希。真实来源、许可和日历资格仍须另行验收，不能由这些哈希自证。

## 监测数据投影与元数据准入

`monitor_data.py` 从已审阅收据和三地各自的窗口构造只读监测投影。价格使用真实 SDK 接收时点，FX 和企业行动使用实际审阅时点；历史 assumed_available_at/published_at 不成为监测取得时间。明确日历范围和下一收盘约束有效期，缺新行情、FX 或日历就输出具体缺口，不补价格或假定节假日。计划资金仍仅是假设，不写模型现金。

`investor-monitor-data-input.schema.json` 固定引用、设置及投影哈希，不留存价格副本；`resolve_monitor_data` 重建并核对当前来源和全部冻结哈希。`check_reference_listing_identity` 另核对当前目录与原方案代码/市场/币种，不能仅靠相同内部 ID 继续观察另一产品。后台 `check-monitor-snapshot` 检查当前已选模型，只输出摘要，零数据库写、零凭据读取、零 provider 调用。

独立 `investor-monitor-data-input-v2` 支持监测专用 `investor-monitor-price-snapshot-v1`，显式区分历史与 Confirmed 回调引用；窗口可增加非空 `confirmed_capture_ids`。`build_monitor_dataset` 逐目标核对完整覆盖，仍按审阅日历重建时点，不伪造 provider 发布时间；原研究 `build_dataset` 与历史接口不接受回调。迁移 42 原子重建监测元数据表的 schema CHECK，保留旧 rowid、列、子引用和审计。默认 core、Node 独立重放、下游来源清理与 AI 全目标用途检查已接通，自动三地收盘监听和真实资格仍未验收。具体升级与边界见[监测专用回调快照](../../docs/14-private-research-data-pipeline.md#监测专用回调快照与版本化准入)。

`confirmed_feed.py` 已增加日历驱动监听切片：从当前启用的已选模型及已准入 seed 分市场登记 `investor_confirmed_watch`，由 longport 角色执行；core 只消费完整回执并接入原监测链。监听不持写锁，回执与任务在租约保护下原子提交；共享 SDK mutex 和窗口预留，单次尝试，漏窗不补历史。模拟 CN 的两版模型闭环、三地窗口规划及失败边界已验证；真实三地持续采集、长期重启治理和生产运行尚未验收。详细说明和复跑入口见[自动监听](../../docs/14-private-research-data-pipeline.md#日历驱动的自动监听与后台准入)。

`monitor_bootstrap.py` 在默认 core 维护中为当前启用、已选且从未登记监测输入的模型建立首个输入。只发现已有且保留中的完整官方收据，重放当前审阅和各市场最新已完成交易日；整个多目标回执采用或拒绝，不截取目标伪造完整覆盖。价格冲突、挂牌/日历歧义、行动或 FX 多重来源均阻断。容差来自完整核验的冻结研究参数，行情质量上限为七天，FX 使用研究与监测中更严格的时效；费用与投入意图保持未知，不猜测风险答案。未知费用且触发变化仍不发布检查点，既有输入不覆盖、不因到期自动重启。模型/来源/控制再次核对后，输入、revision 和额外 bootstrap 审计同事务提交。此模块不读取凭据、不调用 SDK，也不能获得缺失行情或批准许可。详见[首次自动输入](../../docs/14-private-research-data-pipeline.md#首个监测输入的自动建立)。

`initial_prices.py` 为从未登记输入的已选模型补充缺失的过去交易日价格，仅复用原研究当前有效的审阅来源。默认 longport 单次调用原固定历史传输；已有完整正式收据不重采，当地当日收盘后仍等待。`prepare_prices` 冻结请求/原始字节、I/O 不持写锁，同连接最终复核；价格收据/载荷、迁移 44 的 run/audit 与 job 状态原子提交。30 秒历史 I/O 不提供监听器的中途 heartbeat/停止，调用预算及提交租约/停止检查仍严格。core 只有完整价格/行动/FX 才建立输入，不猜测许可、成本、风险或投入；它不是首次研究资料取得或真实三地生产验收。详见[初始价格采集](../../docs/14-private-research-data-pipeline.md#缺失首份监测价格的受控自动采集)。

Web 的 `acquisition.ts` 只读当前模型/控制版本的任务元数据，首页以最多三个市场卡显示首份价格及后续收盘窗口。不执行 SDK/Python、不写库、不验证价格或证明 worker 在线；异常任务记录单独显示不可用，不绕开或关闭原研究核验。没有登记便不预测后续日历，漏窗/部分回调不声称自动追回。浏览器计时独立于刷新、编辑和网络，可使旧窗口、租约、策略及复核结论按时失效。详见[进度边界](../../docs/14-private-research-data-pipeline.md#首页采集进度与时间失效)。

迁移 32 追加 `investor_monitor_evidence_inputs`；`monitor_admission.py` 和 `admit-monitor-snapshot` 只保存合格输入的引用、设置与哈希，不复制报价、FX 或企业行动投影。准入要求当前已选模型、最新偏好及仍有效的参考证据；写锁内完整重放载荷，再检查当前来源和投影期限。相同来源与设置重复操作复用记录，不增加任务、控制版本或金融事实。恢复锁、read-only、失效来源和途中变更使整个准入回滚。

Node 的 `monitor-source.ts` 不调用 Python、SDK 或研究引擎，独立重放各市场窗口、精确价格/FX/企业行动及投影期限；存储读取还检查所有者审计、当前偏好/方案与完整参考证据。伪造并重新封存投影哈希仍不能替代保留收据。该读取器已接入首页的独立模型和成本重放。

**元数据准入不等于真实来源验收。** 新投影不能交给合成快照注册器。迁移 33 的 `investor_evidence_monitor` 已接入默认 core：冻结请求、租约内再次核对、原子发布及来源绑定的连续检查点；新增输入使旧缺口任务失效，不让其覆盖合格运行。真实资格仍需真实资料与纵切验收，当前验证只用虚构事实/模拟 SDK。

检查点与运行的不可变头不含报价或估值，派生载荷可在到期后通过所有者审计删除；观察行保存运行引用。Node 从当前仍有效的来源独立重放全部链和决策算术，重新封存错误单位、成本、结果或期限不能通过。原方案或祖先来源到期阻断连续链，不自动延长许可或重设观察起点。逻辑删除不证明 WAL/备份清理；企业行动修订重述、明确重新起点、长期链规模、当日收盘采集、自动更新/留存联动及生产验收尚缺。

默认收据请求采用 `investor-evidence-model-watcher-v2`：有效收盘或单位/现金/应收/行动状态变化才追加检查点；价格、FX、费用、计划投入或纯时钟变化仍独立评估，但复用已核验的状态哈希、原始来源与原期限。旧 v1 请求保持逐次追加语义，独立读取器同时核验两种版本；引擎版本参与请求去重。1000 个状态的重放安全上限仍保留，无变化复核可继续，实际状态需要推进时明确阻断为 `MONITOR_CHECKPOINT_LIMIT_REQUIRES_RESTART`，不静默丢弃祖先、不自动拼接新旧收益。稀疏状态不等于十年运行或完整重新起点流程已验收。
